Docs / Providers & models
The model behind the panel

Choose the setup that matches your patience, privacy, and budget.

WebBrain includes 114 provider cards spanning its built-in cloud option, direct cloud APIs, model routers, and local OpenAI-compatible servers. You only need one active provider.

WebBrain Companion

Use our separate desktop app for a local model or supported account subscriptions. Download WebBrain Companion for Windows, macOS, or Linux. In Providers, choose the WebBrain Companion card, keep the default http://127.0.0.1:8327/v1 address unless the app shows a different port, then load a model, save, and test the connection. The extension on this computer needs no API key. Account-backed requests still reach the upstream provider; the optional Bonsai model runs locally.

The quick choice

Fewest steps

WebBrain Compass

Built in, active by default, and includes a free daily allowance. No model server or API key setup.

Private & offline-capable

Local model

Use llama.cpp, Ollama, ODS, LM Studio, Jan, vLLM, SGLang, or LocalAI. Your model requests stay with the server you run.

Direct relationship

Cloud API

Bring a key for OpenAI, Anthropic, Gemini, Mistral, DeepSeek, xAI, Groq, and other supported providers.

Broad catalog

Router

Use one account to choose among many models. OpenRouter and Hugging Face are useful when you experiment often.

114 built-in provider cards

The Providers page includes 79 additional direct APIs and routers, including Azure AI Foundry, Vertex AI, Vertex Anthropic, Cerebras, Cohere, DeepInfra, Perplexity, Vercel AI Gateway, Venice, and many regional coding plans. Search by provider or model name instead of scrolling the whole list.

Most cards use an API key and OpenAI-compatible endpoint. Vertex cards use a Google Cloud project, location, and authorization key; the global location uses Google’s global endpoint, while Vertex Anthropic also supports the us and eu multi-region hosts. Cloudflare accepts an optional AI Gateway ID and automatically uses the default gateway for @cf/ models when the field is blank. Interactive Ask turns stream when the selected provider supports it and automatically retry once without streaming if the connection ends early. Provider-reported token usage is recorded directly; otherwise WebBrain records a conservative estimate so streaming cannot bypass cost limits.

GitHub provider entries are intentionally absent

GitHub itself is not going away, but GitHub Models retires July 30, 2026. GitHub Copilot requires a separate subscription/OAuth integration. GitLab Duo and SAP AI Core also require custom authentication and discovery not supported by the browser extension.

Configure a provider

  1. Open the Providers page. Choose More… in the side panel’s model menu, or use the Providers link at the top of Settings. The LLM tab lists the chat providers.
  2. Find the provider. Use Local, Cloud, Router, or the search field.
  3. Open its card. Non-active cards are collapsed to keep the list readable.
  4. Enter the values. Local servers usually need a URL and model name. Cloud providers also need an API key.
  5. Save. This stores the card’s current fields in the browser.
  6. Test Connection. Fix any reported URL, key, model, or server problem before continuing.
  7. Set Active. Only after the test succeeds. A saved provider is not necessarily the provider the side panel is using.

What the fields mean

FieldMeaningNew-user advice
Server / Base URLThe OpenAI-compatible root endpoint or provider API root.Use the exact value shown by your local app or provider. Do not paste a chat webpage URL.
API keyA credential sent to that provider.Local servers normally do not need one unless you enabled authentication.
ModelThe model identifier the server expects.Spelling and prefixes matter. “Model not found” usually means this field does not match the provider catalog.
Context windowHow much prompt, history, page content, and tool schema fits in one request.16k tokens is the usable target for reliable local runs. 8k can work with Compact; 4k is too small.
Supports visionWhether the selected local or open catalog model accepts images.Enable only when the exact served model can process image input.
Prompt tierHow large a prompt and normal browser-tool set WebBrain exposes.Start with Mid for local models. Use Compact for small contexts and Full for capable models.
Input / output costOptional price estimates per million tokens.Fill these when you want WebBrain’s cost allowances to estimate providers that do not report usage cost.

Load models asks supported local servers which models are currently available. For llama.cpp, ODS, Ollama, and LM Studio, Test Connection or Load models can also detect the live context window when the backend reports it.

Browser extensions still need permission to reach local servers

If the server works in a terminal but not in WebBrain, check the server’s CORS/origin setting. Ollama commonly needs OLLAMA_ORIGINS="chrome-extension://*,moz-extension://*" before ollama serve.

Prompt tiers in plain language

CompactSmallest prompt and action-tool surface. Designed for constrained local models and roughly 8k contexts.
MidCommon browser tasks, iframes, downloads, scheduling, and form verification. The best local-model starting point.
FullAdds advanced UI and DOM fallbacks such as hover, drag/drop, frames, and shadow DOM tools.

Cloud providers are forced to Full. Local providers default to Mid unless you choose another tier. OpenRouter exposes the tier because its catalog includes models with very different capabilities. Dev mode is blocked for Compact-tier providers.

When Test Connection fails

  1. Connection refused: start the local server and confirm the port.
  2. CORS or origin error: allow the WebBrain extension origin in the local server.
  3. Unauthorized: paste a current key for the same provider as the base URL.
  4. Model not found: copy the exact model ID from the provider or use Load models.
  5. Requests time out: raise the LLM request timeout in Settings → Budgets for large local models on CPU.
  6. Runs fail after a few turns: confirm the real context window; lower the prompt tier or load the model with a larger context.
Test before you switch

Keep the working provider active while you configure a new one. Save and test the new card first; only then click Set Active.

Optional assistive models

The active provider handles the main conversation, planning and final replies. The other tabs of the Providers page hold a separate Vision model, a Speech (speech-to-text) endpoint, Generative media, Decision models and SafeSocial. These settings are independent of provider filtering and selection.

Vision and Decision models default to Auto: in Chrome they use Compass VLD v6 2B once it is downloaded (or the previous Compass VLD Tiny v5 where it is the only one downloaded), and nothing before that. Without either, a downloaded Ternary Bonsai 2 2B Vision reads screenshots and a downloaded D1 answers decisions; while WebBrain Cloud is active, Compass’s managed decision model answers decisions until one of these is downloaded. A decision model only answers yes-or-no and multiple-choice questions such as “Is this task finished?”; turn it On to use OpenRouter, TypeSafe, a local server, D1 or the in-browser model for every decision, or Off to never use one. Existing permissions and completion checks still apply. See Vision, speech and decision models for setup and data-sharing details.
