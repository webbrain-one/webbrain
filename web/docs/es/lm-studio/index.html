Modelo local, web en vivo

Ofrece a un modelo de LM Studio dos formas de acceder a la web.

WebBrain Web Tools añade la lectura de URL públicas a cualquier chat de LM Studio compatible con herramientas. Al conectar la extensión WebBrain, el mismo complemento también puede delegar un objetivo al perfil de Chromium donde ya tienes sesión iniciada.

Este es un complemento, no la configuración de MCP

Instala webbrain/web-tools desde el Hub de LM Studio. No registres @webbrain/mcp-server ni uses el puerto de MCP 17374 para esta ruta; la delegación al navegador desde el complemento de LM Studio usa el puerto 17375.

Empieza por el Hub

Instalar y activar WebBrain Web Tools

  1. Mantén LM Studio abierto.Abre la ficha del Hub de webbrain/web-tools y elige Run in LM Studio. También puedes abrir el enlace profundo de abajo en la misma máquina.
  2. Activa el complemento en el chat.Abre el control de integraciones o herramientas junto al campo de chat y activa webbrain/web-tools.
  3. Selecciona un modelo compatible con herramientas.El complemento pone sus herramientas a disposición de ese chat; el modelo decide cuándo llamarlas según tu solicitud.
  4. Prueba primero la ruta de la web pública.Pide: "Lee https://news.ycombinator.com y resume los temas principales de los titulares actuales." El modelo debería usar research_url.
lmstudio://plugin?owner=webbrain&name=web-tools

Instalación por CLI

lms clone copia un artefacto del Hub al directorio actual; no instala esa copia por sí solo. Entra en el directorio clonado y ejecuta la forma de instalación de lms dev:

lms clone webbrain/web-tools
cd web-tools
lms dev --install

Consulta la referencia de lms clone y la referencia de lms dev --install de LM Studio para el comportamiento de la CLI.

Seis herramientas, dos superficies de confianza

Lo que el complemento da al modelo

HerramientaPara qué usarla¿Requiere extensión del navegador?
fetch_urlObtiene una URL HTTP(S) conocida. Maneja JSON, HTML, texto sin formato, encabezados y cuerpos de solicitud, y resume las respuestas binarias en lugar de incluirlas en línea.No
research_urlExtrae el texto legible de artículos o documentación, eliminando los elementos de navegación habituales.No
browser_taskDelega un objetivo Ask o Act en lenguaje natural a WebBrain en el navegador con sesión iniciada.Sí
browser_statusComprueba la conexión de la extensión o consulta una ejecución existente mediante runId.Sí
browser_respondReenvía la respuesta del usuario a una ejecución en pausa en el estado needs_user_input.Sí
browser_abortDetiene una ejecución en curso. Las acciones ya completadas no se deshacen.Sí
Las páginas largas se comprimen, no simplemente se recortan

Cuando un resultado excede su presupuesto de devolución, las herramientas HTTP conservan el inicio, pasajes centrales seleccionados de alto valor y el final. Un resultado comprimido informa compacted: true e incluye metadatos de compresión. Pide una página más acotada o aumenta maxChars cuando el contenido omitido importe.

Usar las herramientas HTTP públicas sin navegador

Leer un artículo conocido

Usa research_url para leer https://example.com/article y dame la tesis principal del autor, la evidencia que la respalda y las limitaciones que declara.

Inspeccionar una respuesta de API

Usa fetch_url para leer https://api.example.com/status. Devuelve el estado HTTP y los campos que indican la salud del servicio.

research_url suele ser la mejor opción para prosa. Usa fetch_url cuando importen el tipo de respuesta, la estructura JSON, los encabezados, el método o el cuerpo de la solicitud.

Obtener una URL no es una pestaña del navegador

Estas solicitudes son anónimas y no ejecutan el JavaScript de la página. Si un resultado informa spaSuspected: true o la página exige inicio de sesión, deja de reintentar la ruta HTTP y usa browser_task tras conectar la extensión.

Ruta con sesión iniciada opcional

Conecta el navegador que ya usas

  1. Instala WebBrain en un navegador Chromium.El puente funciona en Chrome, Edge, Brave, Opera y Vivaldi. Firefox no puede alojar esta conexión.
  2. Activa webbrain/web-tools en LM Studio.El complemento abre su listener de loopback local al inicializarse.
  3. Abre los ajustes de WebBrain.Ve a Configuración → Bridge.
  4. Establece la URL del complemento y la clave de emparejamiento.Introduce ws://127.0.0.1:17375/extension, pega la clave de ~/.webbrain/bridge-key (creada al iniciar el complemento y compartida con el servidor MCP) en el campo Clave de emparejamiento y activa el puente en la nube.
  5. Verifica la ruta completa.Pide al modelo de LM Studio que llame a browser_status. Un resultado conectado demuestra que el listener del complemento y el handshake de la extensión están listos.
Un solo destino de puente a la vez

La extensión tiene un único socket de puente de salida. El puerto 17375 la conecta a este complemento, el puerto 17374 al servidor MCP y el puerto 17373 a WebBrain Cloud. Cambiar la URL cambia el destino; no los combina.

Pueden intervenir dos modelos

El modelo de chat de LM Studio decide llamar a browser_task y recibe el resultado. La extensión de WebBrain ejecuta la tarea delegada del navegador con el proveedor activo configurado en WebBrain. Si el contenido de la página debe permanecer en el dispositivo, configura también ese proveedor de WebBrain para usar un modelo local.

Leer sin cambiar la página

Usa browser_task en modo Ask para leer el panel de cuenta que ya tengo abierto en el navegador y lista las cinco alertas más recientes. No cambies nada.

Interactuar con filtros de permiso

Usa browser_task en modo Act para abrir el borrador que ya aparece en mi navegador y actualiza el nombre de la empresa a Acme Europe. Detente antes de cualquier envío o confirmación final.

Deja que las ejecuciones del navegador en curso continúen

browser_task espera un resultado, pero su tiempo de espera no cancela el trabajo que ya se está ejecutando en la extensión. Conserva el runId devuelto y usa la herramienta de recuperación que corresponda al estado.

runningConsultar con browser_status
needs_user_inputPreguntar y luego usar browser_respond
completedResultado listo
failedRevisa el error y las evidencias
abortedDetenido; las acciones anteriores siguen vigentes
  • No inicies un browser_task duplicado tras un agotamiento de tiempo; consulta la ejecución existente.
  • Nunca inventes una respuesta a las preguntas de aclaración de WebBrain. Pregunta al usuario y reenvía su respuesta textualmente.
  • browser_abort detiene los pasos posteriores. No puede deshacer un formulario enviado, un mensaje enviado u otra acción completada.

Mantén claras las dos superficies de confianza

  • El HTTP público se ejecuta en el proceso local del complemento.fetch_url puede enviar métodos, encabezados y cuerpos de solicitud; solicita una mutación solo cuando la pretendas.
  • Los destinos de red privada se bloquean de forma predeterminada.Se rechazan loopback, RFC1918, link-local, metadatos de nube y nombres de host de intranet habituales. Para acceder a localhost o tu LAN, activa Allow private network access en los ajustes del complemento en LM Studio, solo en el chat que lo necesite. El modelo no puede activarlo por sí solo, y aunque esté activo, los endpoints de metadatos de nube siguen bloqueados.
  • Las redirecciones se vuelven a comprobar.El complemento valida cada destino y elimina los encabezados similares a credenciales cuando una redirección cruza orígenes.
  • El listener del navegador permanece en loopback.Nunca reenvíes ni hagas proxy del puerto 17375. El handshake de la extensión identifica al cliente pero no es autenticación por secreto compartido; considera el software local como confiable.
  • El modo Ask es la opción predeterminada.Usa Act solo cuando el resultado solicitado requiera interacción visible en el navegador, y mantén el navegador en un estado en el que puedas detener comportamientos inesperados.
  • El modelo de LM Studio puede ver los resultados de las herramientas.Una ejecución del navegador también envía el contexto de la tarea a través del proveedor activo configurado en WebBrain. Elige con cuidado los límites entre ambos modelos.

Para los detalles a nivel de implementación, incluida la forma en que cada conexión se fija a la dirección verificada, lee las notas de seguridad del complemento.

Solución de problemas por síntoma

SíntomaQué suele significarSolución
Las herramientas no aparecenEl complemento no está activado en este chat, o el modelo elegido no puede llamar herramientas.Activa webbrain/web-tools junto al campo de chat y selecciona un modelo compatible con herramientas.
browser_status informa desconectadoEl complemento está disponible, pero la extensión de WebBrain aún no se ha conectado.Usa Chromium, activa el puente en la nube e introduce exactamente ws://127.0.0.1:17375/extension.
El listener no puede iniciarse o informa un conflicto de direcciónOtra instancia del complemento u otro proceso ya ocupa el puerto 17375.Cierra la instancia duplicada y recarga el complemento. Comprueba primero con lsof -nP -iTCP:17375 -sTCP:LISTEN.
Una página pública está vacíaLa página se renderiza con JavaScript o oculta el contenido tras un inicio de sesión.Si spaSuspected es true, conecta la extensión y usa browser_task.
La tarea agotó el tiempo pero el navegador sigue actuandoSe agotó el presupuesto de espera, pero la ejecución de WebBrain no se canceló.Llama a browser_status con el runId devuelto, o a browser_abort si quieres detenerla.
Firefox nunca se conectaFirefox no tiene tiempo de ejecución de puente de documento fuera de pantalla.Usa un navegador Chromium para las herramientas de navegador. Las dos herramientas HTTP públicas funcionan sin extensión.
MCP o WebBrain Cloud están desconectadosLa URL de LM Studio reemplazó el único destino de puente de la extensión.Cuando termines, cambia los ajustes de vuelta al puerto 17374 (MCP) o 17373 (WebBrain Cloud).

Configuración del entorno del puente

VariableValor predeterminadoSignificado
WEBBRAIN_BRIDGE_PORT17375Puerto de loopback al que se conecta la extensión.
WEBBRAIN_BRIDGE_PATH/extensionRuta de WebSocket; debe coincidir con la URL de los ajustes de WebBrain.
WEBBRAIN_COMMAND_TIMEOUT_MS30000Presupuesto de tiempo de espera para un comando y una respuesta del puente.

Si cambias el puerto o la ruta para un complemento desarrollado localmente, actualiza la URL del puente en la nube en los ajustes de WebBrain para que coincida. La mayoría de los usuarios debe mantener los valores predeterminados.
