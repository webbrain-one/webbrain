Docs / Omarchy

Browser tasks from your Omarchy desktop.

Open the WebBrain panel, describe a task, and hand it to your selected coding agent. WebBrain works in the Chromium browser you already use, with its existing website logins and your choice of model.

The native panel launches Claude Code, Codex, or OpenCode with the WebBrain MCP connection configured. The agent owns the browser task; the panel shows setup readiness and provides shortcuts to the extension, documentation, and Cloud.

Before you install

  • Omarchy Quattro, targeting the 4.5.0 plugin API.
  • Node.js 20 or later, npm, and Git.
  • A Chromium-based browser and the current WebBrain extension.
  • One installed, authenticated agent: Claude Code, Codex, or OpenCode.

Installation is for your user and needs no sudo. It preserves your default browser and agent. Configure the extension's model provider separately; local and hosted providers work. Firefox's MCP bridge has not been verified on a real installation, so use Chromium for this integration.

1. Install the integration

Use the integration and MCP source from the same WebBrain checkout:

git clone --filter=blob:none --sparse --depth 1 https://github.com/esokullu/webbrain.git
cd webbrain
git sparse-checkout set integrations/omarchy mcp-server
node integrations/omarchy/bin/webbrain-omarchy.mjs install --agent claude

Replace claude with codex or opencode. Add --dry-run to preview setup without installing.

The installer enables the widget when the Omarchy shell is running. Add --no-enable to skip activation; it does not disable an already-enabled copy during an update. If setup reports that the shell was unavailable, enable it later from the desktop:

omarchy-shell shell rescanPlugins
omarchy plugin enable webbrain.browser

The helper builds the paired MCP server from your source checkout, copies the native plugin, and creates an MCP registration named webbrain-omarchy. If another enabled WebBrain registration is detected, setup stops without changing it. Disable or remove that old registration in the selected agent before continuing. Unrelated registrations are preserved.

Setup uses this checkout's paired server rather than an unversioned npm release. It needs network access for the server's locked dependencies.

LocationInstalled content
~/.local/bin/webbrain-omarchyCommand-line launcher
~/.local/share/webbrain-omarchy/Helper, MCP server, and integration state
~/.config/omarchy/plugins/webbrain.browser/Plugin manifest and QML

The installed copy is self-contained. Keep the checkout for future updates. Do not run omarchy plugin add against the monorepo root: this plugin's manifest is in a subdirectory, so use the helper above.

2. Pair your browser

Open the extension's store page and install it in the browser profile you want WebBrain to use:

webbrain-omarchy open extension

In a private terminal, print the pairing key:

webbrain-omarchy pairing-key

In WebBrain → Settings → Bridge, use ws://127.0.0.1:17374/extension, paste the key into Pairing key, and enable the bridge. Leave the separate Cloud Bridge token empty for this MCP connection.

Launch the selected agent and ask it to call webbrain_connection on the webbrain-omarchy server. A successful result confirms that the paired browser is connected. The agent starts the MCP server itself, so a WebSocket error before it starts is expected.

The key lives in ~/.webbrain/bridge-key. Enter it directly in the extension, never in an agent chat. The desktop panel and status command do not reveal it.

3. Launch browser work

Click the WebBrain bar widget, enter a task, and launch it with your selected agent. Or use:

webbrain-omarchy launch --task "Summarize the page already open in my browser and include its URL."

This opens the selected agent in an Omarchy terminal. Add --inline to use the current terminal instead.

If a WebBrain bridge is already running, the launcher directs you back to the existing agent window. Continue there, or close that agent before opening another. The panel does not inject tasks into an existing session.

The agent receives your task and instructions to verify the connection and use WebBrain's task-level tools. Follow results and clarification questions in the agent and WebBrain. The panel does not stream run progress or execute browser actions itself.

Ask mode and webbrain_extract read the already-open page. Navigation and interaction require Act mode. Browser actions retain WebBrain's permission checks. See the MCP guide for status, clarification, and abort tools.

webbrain-omarchy status --json

This reports installation readiness, not a live browser connection. Use webbrain_connection inside the agent to check the paired extension.

Optional Cloud browsers

webbrain-omarchy open cloud

The panel's Cloud action opens the dashboard. Cloud browsers use separate profiles and logins; they do not inherit your local browser's cookies. This integration does not manage Cloud sessions.

For agent-driven Cloud work, install the separate WebBrain Cloud skill and provide WEBBRAIN_API_KEY through the agent's environment or secret manager. See the Cloud API guide for workflows, live viewing, billing, and session cleanup.

Update or remove

Close agent sessions using WebBrain, update the source checkout, and rerun the installer with the same agent:

git pull --ff-only
node integrations/omarchy/bin/webbrain-omarchy.mjs install --agent claude

To switch agents, uninstall first and then install with the new --agent value:

webbrain-omarchy uninstall

Uninstall removes this integration's files and its unchanged managed MCP registration, preserving unrelated or user-modified configuration. It keeps the browser extension, logins, model settings, and pairing key.

It also disables the widget and rescans plugins when the Omarchy shell is available. If removal reports that shell cleanup could not be confirmed, run:

omarchy plugin disable webbrain.browser
omarchy-shell shell rescanPlugins

Configuration backups remain in a private directory under ~/.local/share/webbrain-omarchy-backups-*. Keep them private: they may contain other agent settings and credentials.

Troubleshooting

ProblemNext step
Command not foundPut ~/.local/bin on your PATH and reopen the terminal.
No widgetCheck omarchy plugin list and enable webbrain.browser.
Setup or build failureCheck Node 20+, npm, the complete MCP source, and dependency download access. Run webbrain-omarchy status --json.
Stored Node runtime missingUninstall and rerun the source installer with your current Node runtime. The registration uses the Node path selected during installation.
Existing WebBrain registrationDisable or remove the old enabled WebBrain server in the selected agent, then rerun setup.
No MCP tools in the agentRestart its MCP connection. Check that the active account/configuration has the webbrain-omarchy registration.
WebSocket errorStart the selected agent, keep Chromium open, and check ws://127.0.0.1:17374/extension.
Pairing mismatchPrint the key in a private terminal and replace it in WebBrain's Bridge settings.
Bridge port already occupiedContinue in the already-open agent, or close it before launching another task. One process must own port 17374.

The extension holds one outbound bridge socket. Local MCP uses 17374, Cloud uses 17373, and LM Studio uses 17375. Switching the URL switches the destination; launching more server processes does not share the browser.

Omarchy can keep separate accounts for the same coding agent. Install for the intended account. The helper remembers its configuration paths and selected Omarchy account for status, launch, update, and removal, including launches from the desktop panel. Changing Omarchy's active account later does not switch this integration. It stores paths and the account name, not credentials. Uninstall and reinstall to select another agent or account.

What this version includes

A native task panel, selected-agent setup, paired browser access, and installation diagnostics. A shared multi-agent broker, live run monitoring, and automatic Cloud lifecycle controls are outside this version. Browser automation does not add an operating-system control API.

For implementation details, see the technical guide, integration source, and Omarchy shell plugin manual.
