Dokumentation / LM Studio-Plugin
Lokales Modell, lebendiges Web

Geben Sie einem LM Studio-Modell zwei Wege zum Web.

WebBrain Web Tools ergänzt jede toolfähige LM Studio-Unterhaltung um das Lesen öffentlicher URLs. Mit angehängter WebBrain-Erweiterung kann dasselbe Plugin ein Ziel auch an das Chromium-Profil delegieren, bei dem Sie bereits angemeldet sind.

Dies ist ein Plugin, nicht die MCP-Einrichtung

Installieren Sie webbrain/web-tools über den LM Studio Hub. Registrieren Sie für diesen Pfad nicht @webbrain/mcp-server und verwenden Sie nicht den MCP-Port 17374; die Browser-Delegation des LM Studio-Plugins nutzt Port 17375.

Ein Plugin, zwei Routen

Was das Modell erreichen kann

LM Studio-Chatmodellwählt ein Werkzeug aus Ihrer Eingabeaufforderung
→
webbrain/web-toolslokales Node-Plugin · sechs Werkzeuge
→
Öffentliche URL oder angemeldeter Browseranonymes HTTP · optionale Erweiterungsbrücke
RouteGeeignet fürWas es nicht kann
fetch_url / research_urlÖffentliche Artikel, Dokumentationen, APIs, JSON, Text und statisches HTML.Keine Browser-Cookies, kein JavaScript-Rendering, keine Klicks, Eingaben oder authentifizierte Sitzung.
browser_taskAngemeldete Dashboards, Webmail, clientseitig gerenderte Apps und Aufgaben, die sichtbare Browser-Interaktion erfordern.Erfordert WebBrain in Chromium und die Plugin-Brückenverbindung.

Vor der Installation

AnforderungWas zu prüfen ist
LM StudioÖffnen Sie die aktuelle Desktop-App. Ihre mitgelieferte Laufzeitumgebung kann installierte Plugins ausführen; für die normale Nutzung ist keine separate Node.js-Installation erforderlich.
Toolfähiges ModellVerwenden Sie ein Modell und eine Chat-Konfiguration, die Werkzeuge aufrufen kann. Ein reines Textmodell ohne Tool-Nutzung ruft das Plugin nicht auf.
NetzwerkzugriffDie beiden HTTP-Werkzeuge kontaktieren die von Ihnen angeforderte URL aus dem lokalen Plugin-Prozess.
Optionale BrowserverbindungFür browser_task installieren Sie WebBrain in Chrome, Edge, Brave, Opera oder Vivaldi und halten Port 17375 frei.
Aktiver WebBrain-AnbieterBrowser-Aufgaben laufen weiterhin über den in der WebBrain-Erweiterung konfigurierten Anbieter.
Beginnen Sie im Hub

WebBrain Web Tools installieren und aktivieren

  1. Halten Sie LM Studio geöffnet. Öffnen Sie den Hub-Eintrag von webbrain/web-tools und wählen Sie Run in LM Studio. Sie können den untenstehenden Deep Link auch auf demselben Rechner öffnen.
  2. Aktivieren Sie das Plugin im Chat.Öffnen Sie die Steuerung für Integrationen oder Werkzeuge neben dem Chat-Eingabefeld und schalten Sie webbrain/web-tools ein.
  3. Wählen Sie ein toolfähiges Modell.Das Plugin stellt dem Chat seine Werkzeuge bereit; das Modell entscheidet anhand Ihrer Anfrage, wann es sie aufruft.
  4. Probieren Sie zuerst die Route über das öffentliche Web.Fragen Sie: "Lesen Sie https://news.ycombinator.com und fassen Sie die Hauptthemen der aktuellen Schlagzeilen zusammen." Das Modell sollte research_url verwenden.
lmstudio://plugin?owner=webbrain&name=web-tools

Installation über CLI

lms clone kopiert ein Hub-Artefakt in das aktuelle Verzeichnis; es installiert diese Kopie nicht automatisch. Wechseln Sie in das geklonte Verzeichnis und führen Sie die Installationsform von lms dev aus:

lms clone webbrain/web-tools
cd web-tools
lms dev --install

Siehe die lms clone-Referenz und die lms dev --install-Referenz von LM Studio für das CLI-Verhalten.

Sechs Werkzeuge, zwei Vertrauensbereiche

Was das Plugin dem Modell bietet

WerkzeugWofür verwendenBrowser-Erweiterung erforderlich?
fetch_urlRuft eine bekannte HTTP(S)-URL ab. Verarbeitet JSON, HTML, Klartext, Request-Header und -Bodies und fasst binäre Antworten zusammen, statt sie inline einzubetten.Nein
research_urlExtrahiert lesbaren Artikel- oder Dokumenttext und entfernt übliche Navigationselemente.Nein
browser_taskDelegiert ein Ask- oder Act-Ziel in natürlicher Sprache an WebBrain im angemeldeten Browser.Ja
browser_statusPrüft die Verbindung der Erweiterung oder fragt einen bestehenden Durchlauf per runId ab.Ja
browser_respondLeitet die Antwort des Nutzers an einen bei needs_user_input pausierten Durchlauf weiter.Ja
browser_abortStoppt einen laufenden Durchlauf. Bereits abgeschlossene Aktionen werden nicht rückgängig gemacht.Ja
Lange Seiten werden verdichtet, nicht einfach abgeschnitten

Wenn ein Ergebnis das Rückgabebudget überschreitet, behalten die HTTP-Werkzeuge den Anfang, ausgewählte signalstarke mittlere Passagen und das Ende. Ein verdichtetes Ergebnis meldet compacted: true und enthält Verdichtungsmetadaten. Fordern Sie eine schmalere Seite an oder erhöhen Sie maxChars, wenn der ausgelassene Inhalt wichtig ist.

Öffentliche HTTP-Werkzeuge ohne Browser nutzen

Einen bekannten Artikel lesen

Lesen Sie mit research_url https://example.com/article und nennen Sie die Hauptthese des Autors, die Belege dafür und die genannten Einschränkungen.

Eine API-Antwort prüfen

Rufen Sie mit fetch_url https://api.example.com/status ab. Geben Sie den HTTP-Status und die Felder zurück, die die Dienstgesundheit anzeigen.

research_url eignet sich meist besser für Artikelinhalt. Verwenden Sie fetch_url, wenn Antworttyp, JSON-Struktur, Header, Methode oder Request-Body wichtig sind.

Ein URL-Abruf ist kein Browser-Tab

Diese Anfragen sind anonym und führen das JavaScript der Seite nicht aus. Wenn ein Ergebnis spaSuspected: true meldet oder die Seite eine Anmeldung verlangt, wiederholen Sie die HTTP-Route nicht, sondern nutzen Sie browser_task, nachdem die Erweiterung verbunden ist.

Optionale angemeldete Route

Verbinden Sie den Browser, den Sie bereits nutzen

  1. Installieren Sie WebBrain in einem Chromium-Browser.Die Brücke funktioniert in Chrome, Edge, Brave, Opera und Vivaldi. Firefox kann diese Verbindung nicht bereitstellen.
  2. Aktivieren Sie webbrain/web-tools in LM Studio.Das Plugin öffnet beim Initialisieren seinen lokalen Loopback-Listener.
  3. Öffnen Sie die WebBrain-Einstellungen.Gehen Sie zu Einstellungen → Bridge.
  4. Legen Sie Plugin-URL und Kopplungsschlüssel fest.Geben Sie ws://127.0.0.1:17375/extension ein, fügen Sie den Schlüssel aus ~/.webbrain/bridge-key (beim Plugin-Start erstellt, mit dem MCP-Server geteilt) in das Feld Kopplungsschlüssel ein und aktivieren Sie die Cloud-Brücke.
  5. Überprüfen Sie den vollständigen Pfad.Bitten Sie das LM Studio-Modell, browser_status aufzurufen. Ein verbundenes Ergebnis belegt, dass Plugin-Listener und Erweiterungs-Handshake bereit sind.
Immer nur ein Brückenziel

Die Erweiterung hat genau einen ausgehenden Bridge-Socket. Port 17375 verbindet sie mit diesem Plugin, Port 17374 mit dem MCP-Server und Port 17373 mit WebBrain Cloud. Das Ändern der URL wechselt das Ziel; sie werden nicht zusammengeführt.

Möglicherweise sind zwei Modelle beteiligt

Das LM Studio-Chatmodell entscheidet, browser_task aufzurufen, und empfängt das Ergebnis. Die WebBrain-Erweiterung führt den delegierten Browser-Durchlauf mit dem in WebBrain konfigurierten aktiven Anbieter aus. Wenn der Seiteninhalt auf dem Gerät bleiben muss, konfigurieren Sie auch diesen WebBrain-Anbieter für ein lokales Modell.

Lesen, ohne die Seite zu ändern

Lesen Sie mit browser_task im Ask-Modus das bereits in meinem Browser geöffnete Konto-Dashboard und listen Sie die fünf neuesten Alarme auf. Ändern Sie nichts.

Interagieren über Berechtigungstore

Öffnen Sie mit browser_task im Act-Modus den Entwurf, der bereits in meinem Browser angezeigt wird, und aktualisieren Sie den Firmennamen auf Acme Europe. Halten Sie vor jeder endgültigen Übermittlung oder Bestätigung an.

Laufende Browser-Durchläufe fortsetzen lassen

browser_task wartet auf ein Ergebnis, aber sein Timeout bricht die in der Erweiterung laufende Arbeit nicht ab. Bewahren Sie die zurückgegebene runId auf und verwenden Sie das zum Status passende Wiederherstellungswerkzeug.

runningMit browser_status abfragen
needs_user_inputNachfragen, dann browser_respond nutzen
completedErgebnis liegt vor
failedFehler und Nachweise ansehen
abortedGestoppt; frühere Aktionen bleiben wirksam
  • Starten Sie nach einem Timeout keinen doppelten browser_task; fragen Sie den bestehenden Durchlauf ab.
  • Erfinden Sie niemals eine Antwort auf eine Rückfrage von WebBrain. Fragen Sie den Nutzer und leiten Sie seine Antwort wortwörtlich weiter.
  • browser_abort stoppt künftige Schritte. Ein übermitteltes Formular, eine gesendete Nachricht oder eine andere abgeschlossene Aktion kann es nicht rückgängig machen.

Die beiden Vertrauensbereiche klar trennen

  • Öffentliches HTTP läuft im lokalen Plugin-Prozess.fetch_url kann Methoden, Header und Bodies senden, fordern Sie eine Änderung also nur beabsichtigt an.
  • Private Netzwerkziele sind standardmäßig blockiert.Loopback, RFC1918, Link-Local, Cloud-Metadaten und übliche Intranet-Hostnamen werden abgelehnt. Für localhost oder Ihr LAN aktivieren Sie Allow private network access in den Plugin-Einstellungen in LM Studio, nur in einem Chat, der es braucht. Das Modell kann es nicht selbst aktivieren, und selbst wenn aktiv, bleiben Cloud-Metadaten-Endpunkte blockiert.
  • Weiterleitungen werden erneut geprüft.Das Plugin validiert jedes Ziel und entfernt glaubwürdigungsähnliche Header, wenn eine Weiterleitung die Origin wechselt.
  • Der Browser-Listener bleibt auf Loopback.Leiten Sie Port 17375 niemals weiter und proxyen Sie ihn nicht. Der Handshake der Erweiterung identifiziert den Client, ist aber keine Authentifizierung mit geteiltem Geheimnis; betrachten Sie lokale Software als vertrauenswürdig.
  • Der Ask-Modus ist die Standardwahl.Nutzen Sie Act nur, wenn das gewünschte Ergebnis eine sichtbare Browser-Interaktion erfordert, und behalten Sie die Kontrolle, um unerwartetes Verhalten zu stoppen.
  • Das LM Studio-Modell sieht Werkzeug-Ergebnisse.Ein Browser-Durchlauf sendet zudem den Aufgabenkontext über den in WebBrain konfigurierten aktiven Anbieter. Wählen Sie die Grenzen beider Modelle mit Bedacht.

Für Details auf Implementierungsebene, einschließlich der Frage, wie jede Verbindung an die geprüfte Adresse geheftet wird, lesen Sie die Sicherheitshinweise des Plugins.

Fehlersuche nach Symptom

SymptomÜbliche BedeutungLösung
Die Werkzeuge erscheinen nichtDas Plugin ist für diesen Chat nicht aktiviert, oder das gewählte Modell kann keine Werkzeuge aufrufen.Aktivieren Sie webbrain/web-tools neben dem Chat-Eingabefeld und wählen Sie ein toolfähiges Modell.
browser_status meldet getrenntDas Plugin ist verfügbar, aber die WebBrain-Erweiterung hat sich noch nicht verbunden.Verwenden Sie Chromium, aktivieren Sie die Cloud-Brücke und geben Sie exakt ws://127.0.0.1:17375/extension ein.
Der Listener kann nicht starten oder meldet einen AdresskonfliktEine andere Plugin-Instanz oder ein anderer Prozess belegt bereits Port 17375.Schließen Sie die doppelte Instanz und laden Sie das Plugin neu. Prüfen Sie zuerst mit lsof -nP -iTCP:17375 -sTCP:LISTEN.
Eine öffentliche Seite ist leerDie Seite rendert mit JavaScript oder verbirgt den Inhalt hinter einer Anmeldung.Wenn spaSuspected true ist, verbinden Sie die Erweiterung und nutzen Sie browser_task.
Die Aufgabe läuft in den Timeout, aber der Browser macht weiterDas Zeitbudget ist aufgebraucht, der WebBrain-Durchlauf wurde aber nicht abgebrochen.Rufen Sie browser_status mit der zurückgegebenen runId auf, oder browser_abort, wenn Sie stoppen möchten.
Firefox verbindet sich nieFirefox hat keine Laufzeitumgebung für Offscreen-Dokument-Brücken.Verwenden Sie für Browser-Werkzeuge einen Chromium-Browser. Die beiden öffentlichen HTTP-Werkzeuge sind ohne Erweiterung nutzbar.
MCP oder WebBrain Cloud sind getrenntDie LM Studio-URL hat das einzige Brückenziel der Erweiterung ersetzt.Wechseln Sie die Einstellungen nach Abschluss zurück auf Port 17374 (MCP) oder 17373 (WebBrain Cloud).

Umgebungskonfiguration der Brücke

VariableStandardwertBedeutung
WEBBRAIN_BRIDGE_PORT17375Loopback-Port, mit dem sich die Erweiterung verbindet.
WEBBRAIN_BRIDGE_PATH/extensionWebSocket-Pfad; er muss mit der URL in den WebBrain-Einstellungen übereinstimmen.
WEBBRAIN_COMMAND_TIMEOUT_MS30000Zeitbudget für einen Brückenbefehl und die Antwort.

Wenn Sie Port oder Pfad für ein lokal entwickeltes Plugin ändern, aktualisieren Sie die Cloud-Brücken-URL in den WebBrain-Einstellungen entsprechend. Die meisten Nutzer sollten die Standardwerte beibehalten.
