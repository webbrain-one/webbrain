Echte Sitzung, Steuerung auf Aufgaben-Ebene

Lass deinen Coding-Agenten den Browser verwenden, in dem du bereits angemeldet bist.

WebBrain MCP verbindet Codex, Claude Code, Cursor, OpenClaw, OpenCode und andere Stdio-MCP-Clients mit deinem echten Chromium-Profil. Nach einer einmaligen Einrichtung beschreibst du die Browser-Aufgabe einfach in natürlicher Sprache. Dein Coding-Agent wählt die passenden WebBrain-Werkzeuge und ruft sie auf; WebBrain führt das Ziel im Browser aus – mit denselben Modi, Ursprungs-Berechtigungen und sichtbaren Stopp-Reglern wie in der Seitenleiste.

Du musst keine MCP-Funktionsaufrufe von Hand eingeben

Sage „Verwende WebBrain, um das in meinem Browser geöffnete Dashboard zusammenzufassen“ oder „Verwende WebBrains Act-Modus, um dieses Formular zu aktualisieren“. Dein MCP-Client übersetzt diese Anfrage in Werkzeugaufrufe und gibt das Ergebnis in derselben Konversation zurück. Die später im Funktionsformat gezeigten Beispiele sind vor allem für Debugging oder für Client-Entwickler gedacht.

Nur Chromium

Die Brücke benötigt das Offscreen-Dokument der Erweiterung; verwende daher Chrome, Edge, Brave, Opera oder Vivaldi. Die Firefox-Erweiterung ist weiterhin eigenständig nutzbar, kann sich aber nicht mit diesem MCP-Server verbinden.

Der komplette Pfad

Was wo startet

Dein MCP-Client startet das npm-Paket über stdio als lokalen Kindprozess. Dieser Prozess lauscht nur auf 127.0.0.1:17374. Die Erweiterung verbindet sich damit und führt jede Aufgabe über die Agent-Schleife von WebBrain im ausgewählten Browser-Tab aus.

Codex、Claude Code、Cursor、OpenClaw、OpenCodeMCP-Client · besitzt den Kindprozess
→
@webbrain/mcp-serverstdio · 127.0.0.1:17374
→
WebBrain in deinem BrowserAngemeldete Tabs · Berechtigungsschranke

Der Server ist kein zweiter Browser und kopiert keine Cookies. Er ist eine lokale Übergabestelle zwischen MCP-Client und Erweiterung. Das Browser-Profil – und damit die authentifizierte Sitzung – bleibt immer an Ort und Stelle.

Schritt 1 · nur einmal

Server bei deinem MCP-Client registrieren

Verwende einmal eine der clientspezifischen Konfigurationen unten. Das sind Installationsbefehle, nicht die Art, wie du Browser-Aufgaben anforderst. Nach der Registrierung startet der Client den Server für dich, und du chattest wie gewohnt weiter; betreibe nicht parallel eine manuelle Instanz auf demselben Port.

Codex-App, CLI oder IDE-Erweiterung

codex mcp add webbrain -- npx -y @webbrain/mcp-server

Codex speichert MCP-Server in ~/.codex/config.toml; App, CLI und IDE-Erweiterung teilen sich diese Konfiguration auf demselben Codex-Host. Öffne für lange Browser-Aufgaben diese Datei und gib dem Werkzeug mehr Zeit als das Standard-Budget von Codex pro Aufruf:

[mcp_servers.webbrain]
command = "npx"
args = ["-y", "@webbrain/mcp-server"]
tool_timeout_sec = 360

Starte die App oder IDE-Erweiterung nach der Änderung der Datei neu. Führe im CLI codex mcp list aus, um den Eintrag zu bestätigen, und prüfe in einer Codex-Sitzung mit /mcp den verbundenen Server. Siehe den offiziellen Codex-MCP-Leitfaden für die geteilte Host-Konfiguration und alle unterstützten Optionen.

Claude Code

claude mcp add --transport stdio webbrain -- npx -y @webbrain/mcp-server

Der explizite Transport entspricht der aktuellen Claude-Code-MCP-Konfiguration. Führe nach dem Hinzufügen claude mcp list aus, um den Serverzustand zu prüfen.

Cursor

Füge in den MCP-Einstellungen von Cursor einen lokalen Stdio-Server hinzu oder setze diesen Inhalt in die MCP-JSON-Datei, die Cursor verwendet. Das Format folgt dem Cursor-Format für lokale MCP-Server:

{
  "mcpServers": {
    "webbrain": {
      "command": "npx",
      "args": ["-y", "@webbrain/mcp-server"]
    }
  }
}

OpenCode

Füge diesen Eintrag der Datei ~/.config/opencode/opencode.json hinzu, im Format für lokale MCP-Server von OpenCode:

{
  "mcp": {
    "webbrain": {
      "type": "local",
      "command": ["npx", "-y", "@webbrain/mcp-server"]
    }
  }
}

OpenClaw

Registriere WebBrain in OpenClaw als ausgehenden MCP-Server. Verwende für diese Integration nicht openclaw mcp serve: Dieser Befehl lässt OpenClaw selbst als Server dienen – die Gegenrichtung.

openclaw mcp add webbrain \
  --command npx \
  --arg -y \
  --arg @webbrain/mcp-server \
  --timeout 360

mcp add prüft den Stdio-Server vor dem Speichern. Führe openclaw mcp status --verbose aus, um die gespeicherte Definition zu prüfen. Die normalen Werkzeugprofile coding und messaging enthalten eingerichtete MCP-Server; das Profil minimal, eine explizite bundle-mcp-Ablehnung oder eine Sandbox-Werkzeugrichtlinie kann sie verbergen. Siehe den OpenClaw-MCP-Leitfaden für aktuelle Registry- und Richtlinien-Details.

Manueller Start

Ein manueller Start ist nützlich, um den Listener zu diagnostizieren, aber bei normalem MCP-Gebrauch nicht nötig:

npx -y @webbrain/mcp-server

Lass dieses Terminal offen. Wenn du es schließt, endet der Bridge-Listener. Führe in einem Quellcode-Checkout npm install, npm run build und dann npm start in mcp-server/ aus.

Schritt 2

WebBrain auf den lokalen Listener zeigen lassen

  1. Starte oder starte deinen MCP-Client neu. Sein WebBrain-Server muss laufen, bevor sich die Erweiterung verbinden kann.
  2. Öffne die WebBrain-Einstellungen. Gehe zu Einstellungen → Bridge.
  3. Lege die exakte URL fest. Gib ws://127.0.0.1:17374/extension ein.
  4. Füge den Kopplungsschlüssel ein. Führe npx -y @webbrain/mcp-server pairing-key in einem Terminal aus (oder öffne ~/.webbrain/bridge-key) und füge den Schlüssel in das Feld Kopplungsschlüssel ein. Der Server vertraut nur einem Browser, der nachweist, diesen Schlüssel zu besitzen. Falls das Feld fehlt, aktualisiere zuerst WebBrain.
  5. Aktiviere die Cloud-Brücke. Der Status sollte von „Verbindung wird hergestellt“ auf „Verbunden“ wechseln. Die Bezeichnung ist historisch bedingt: Dieses Ziel ist lokal.
  6. Überprüfe die Verbindung Ende-zu-Ende. Bitte deinen MCP-Client, webbrain_connection aufzurufen. „Connected“ belegt, dass Client, lokaler Server, WebSocket-Listener und Erweiterungs-Handshake bereit sind.
Immer nur ein Bridge-Ziel

Die Erweiterung hält genau einen ausgehenden Bridge-Socket: WebBrain Cloud auf 17373, dieser MCP-Server auf 17374 oder das LM-Studio-Plugin auf 17375. Das Ändern der URL wechselt das Ziel; es wird nicht multiplexed.

Schritt 3 · einfach fragen

Beschreibe die Browser-Aufgabe in natürlicher Sprache

Formuliere die Anfrage in Codex, Claude Code, Cursor, OpenClaw oder OpenCode so, als gibst du sie einem Kollegen weiter. WebBrain zu nennen macht deine Absicht eindeutig; gib die Seite, das erwartete Ergebnis, den Umfang an und ob Änderungen erlaubt sind.

Lesen ohne Seitenänderung

Lies mit WebBrain das bereits in meinem Browser geöffnete Stripe-Dashboard. Liste die fehlgeschlagenen Zahlungen der letzten sieben Tage mit Kunde, Betrag, Währung, Datum und Fehlergrund auf. Ändere nichts.

Vorhersagbares JSON zurückgeben

Extrahiere mit WebBrain alle überfälligen Rechnungen aus dem in meinem Browser geöffneten Dashboard. Gib JSON mit Kunde, Betrag, Währung, Fälligkeitsdatum und Rechnungs-URL zurück. Ändere nichts.

Mit der Seite interagieren

Öffne im Act-Modus von WebBrain den bereits in meinem Browser sichtbaren Kundendatensatz und aktualisiere den Firmennamen auf Acme Europe. Stoppe vor dem endgültigen Absenden oder Bestätigen.

Der Coding-Agent wählt webbrain_run für allgemeines Lesen oder Interagieren und webbrain_extract, wenn strukturierte Daten angefragt werden. Er liefert die Argumente, überwacht den Lauf und präsentiert WebBrains Ergebnis zurück in der Konversation. Der Ask-Modus kann lesen und extrahieren; er kann nicht klicken, tippen, navigieren oder absenden. Der Act-Modus kann interagieren, innerhalb der üblichen WebBrain-Berechtigungen im Browser.

Interne Details – die musst du nicht eingeben

Für die erste Eingabe oben würde der Client einen ungefähr so aufgebauten Aufruf tätigen. Diese Darstellung ist nützlich beim Bauen oder Debuggen von MCP-Clients; normale Nutzer können sie ignorieren.

webbrain_run(
  task: "read the open Stripe dashboard and list failed payments from the last 7 days with customer, amount, currency, date, and failure reason",
  mode: "ask"
)

Sage für eine Aufgabe, die interagieren muss, ausdrücklich „Verwende den Act-Modus von WebBrain“ und lass den Browser sichtbar. WebBrain wendet seine üblichen Genehmigungsabfragen je Fähigkeit und Herkunft an.

Sechs Werkzeuge, eine Vertrauensgrenze

Die Werkzeuge, die dein MCP-Client für dich nutzt

Üblicherweise wählst du ein Ergebnis, nicht ein Werkzeug. Dein MCP-Client liest diese Beschreibungen, wählt das passende Werkzeug, füllt dessen Eingaben aus deiner Anfrage und behandelt nachfolgende Aufrufe. Diese Referenz hilft dir, dieses Verhalten zu verstehen oder zu debuggen.

WerkzeugWofürWichtige Eingaben
webbrain_runJedes Browser-Ziel, schreibgeschützt oder interaktiv.task, mode, optional tab_id, wait, timeout_seconds sowie das Act-exklusive allow_api_mutations.
webbrain_extractVorhersagbares JSON aus authentifizierten Seitendaten. Immer im Ask-Modus.task, output_schema, optional tab_id, wait und timeout_seconds.
webbrain_statusEinen Hintergrundlauf abfragen oder alle bekannten Läufe auflisten.Optional run_id. Weglassen, um Läufe aufzulisten.
webbrain_respondDie Antwort des Nutzers an einen pausierten Lauf übergeben.run_id, clarify_id, answer, optional timeout_seconds.
webbrain_abortEinen falschen oder nicht mehr benötigten Lauf stoppen.run_id. Bereits ausgeführte Aktionen werden nicht rückgängig gemacht.
webbrain_connectionDen Handshake der Erweiterung prüfen und bei Trennung eine gezielte Lösung erhalten.Keine Eingaben.
Warum es kein MCP-Klick- oder -Tipper-Werkzeug gibt

Die Berechtigungsprüfungen von WebBrain sitzen in der Agent-Schleife der Erweiterung. Würde man die Primitive der unteren Ebene direkt über MCP exponieren, umginge man diese Grenze. Wenn du deterministische Browser-Automatisierung auf niedriger Ebene brauchst (wie Playwright), ziehe andere MCP-Server in Betracht. WebBrain schützt deine angemeldete Sitzung, indem es Aktionen innerhalb des Berechtigungsmodells der Erweiterung hält.

Strukturiertes JSON anfordern

Im normalen Gebrauch sagst du, was extrahiert werden soll, und nennst die gewünschten Felder: „Extrahiere mit WebBrain alle überfälligen Rechnungen aus dem geöffneten Dashboard und gib JSON mit Kunde, Betrag, Währung, Fälligkeitsdatum und Rechnungs-URL zurück.“ Ein fähiger MCP-Client kann diese Felder in das benötigte Schema übersetzen und webbrain_extract für dich aufrufen.

Das Funktionsbeispiel unten zeigt den gleichwertigen Werkzeugaufruf für Client-Entwickler und Debugging. Beschreibe die Auswahllogik in task; beschreibe die Ausgabeform nur in output_schema.

webbrain_extract(
  task: "extract every overdue invoice visible in this account; preserve the displayed currency and use ISO dates where the page provides a full date",
  output_schema: {
    type: "object",
    properties: {
      invoices: {
        type: "array",
        items: {
          type: "object",
          properties: {
            customer: { type: "string" },
            amount: { type: "number" },
            currency: { type: "string" },
            due_date: { type: "string" },
            invoice_url: { type: "string" }
          },
          required: ["customer", "amount", "currency", "due_date"]
        }
      }
    },
    required: ["invoices"]
  }
)
  • Verwende einen Objekt-Stamm mit expliziten properties- und required-Feldern.
  • Fordere nur die engsten Daten an, die du brauchst. Ein Schema gewährt keinen Zugriff auf Daten, die die Browser-Sitzung nicht sieht.
  • Das Werkzeug ist schreibgeschützt, aber Seitentext und Ergebnis gehen dennoch an den in WebBrain konfigurierten LLM-Anbieter.
  • Ist das Ergebnis für den gespeicherten Schnappschuss des Laufs zu groß, meldet der Status möglicherweise, dass das gespeicherte Ergebnis gekürzt wurde. Verkleinere die Anfrage und versuche es erneut.

Den Lebenszyklus eines Laufs verstehen

Die meisten MCP-Clients verwalten diesen Lebenszyklus für dich: Sie warten auf das Ergebnis, zeigen WebBrains Klärungsfrage an, wenn menschliche Eingabe nötig ist, und fahren mit deiner Antwort fort. Die expliziten Aufrufe unten sind nützlich für Client-Entwickler, zur Fehlerbehebung oder wenn du den Client bewusst eine lange Aufgabe im Hintergrund starten lässt.

Aufrufe im Vordergrund warten standardmäßig. Bei langer Arbeit kann der Client wait: false setzen und mit webbrain_status abfragen.

runningDie Arbeit läuft im Browser weiter
needs_user_inputDie Frage an den Nutzer weiterleiten
completedErgebnis bereit
failedFehler und Nachweise ansehen
abortedGestoppt; frühere Aktionen bleiben wirksam
# Referenz auf Werkzeug-Ebene
# Start ohne Warten
webbrain_run(task: "compare the invoices across all visible pages", mode: "ask", wait: false)

# Zurückgegebene ID abfragen
webbrain_status(run_id: "mcp_…")

Ein Timeout eines WebBrain-Laufs gibt die Kontrolle an den MCP-Client zurück, bricht die Browser-Aufgabe aber bewusst nicht ab. Frage den zurückgegebenen run_id ab. So verhindert man, dass ein Timeout eine Aufgabe still beendet, die möglicherweise bereits eine wesentliche Aktion ausgeführt hat.

Wenn WebBrain eine Frage stellt

Der pausierte Schnappschuss enthält eine für Menschen lesbare Frage und eine clarify_id. Zeige dem Nutzer diese Frage. Sende seine Antwort wörtlich; rate nicht.

webbrain_respond(
  run_id: "mcp_…",
  clarify_id: "clarify_…",
  answer: "Use the Acme EU account."
)

Wähle die kleinste Berechtigung

WahlErlaubte AktionenWann nutzen
mode: "ask"Lesen, zusammenfassen, vergleichen und extrahieren. Keine Seiteninteraktion.Du brauchst nur Informationen. Das ist die Standardoption.
mode: "act"Navigation, Klicks, Eingaben, Downloads und Formularinteraktion durch WebBrains Berechtigungsschranke.Das Ergebnis erfordert sichtbare Browser-Aktionen.
allow_api_mutations: trueErlaubt einem Act-Lauf, mutierende HTTP-Anfragen zu verwenden, wenn der UI-Pfad ungeeignet ist.Seltene, ausdrückliche Ausnahme. Im Ask-Modus abgelehnt; sollte standardmäßig aus bleiben.

Die Genehmigung des MCP-Clients und die von WebBrain sind getrennte Ebenen. Dein Client fragt möglicherweise vor dem Aufruf von webbrain_run; WebBrain fragt möglicherweise vor einer wesentlichen Aktion auf einem Ursprung. Die eine Genehmigung ersetzt nicht die andere.

Sicherheitsgrenzen, die du einhalten solltest

  • Halte den Listener lokal. Er ist an 127.0.0.1 gebunden. Leite Port 17374 nicht weiter, veröffentliche ihn nicht über eine Container-Brücke und proxy ihn nicht ins Netzwerk.
  • Bewahre den Kopplungsschlüssel sicher auf. Loopback allein ist keine Authentifizierung; der Server vertraut einem Socket erst, nachdem dieser eine Einmal-Herausforderung mit einem HMAC beantwortet hat, der mit dem Kopplungsschlüssel signiert ist; der Schlüssel selbst geht nie über den Socket. Wer ~/.webbrain/bridge-key lesen kann, darf koppeln – füge den Schlüssel also nicht in einen Chat ein. Die Erweiterung authentifiziert den Server nicht; behandle lokalen Code und MCP-Pakete weiterhin als vertrauenswürdige Software.
  • Nutze zuerst Ask. Schreibgeschützte Arbeit ist leichter zu prüfen und hat eine geringere Schadensreichweite.
  • Halte den Browser im Act-Modus sichtbar. Du kannst den Lauf im Seitenpanel stoppen, und unerwartete Navigation oder Eingaben sind ein Grund zum Stoppen.
  • Denke an die Anbietergrenze. Die MCP-Brücke bleibt lokal, aber Seiteninhalte werden an den in WebBrain konfigurierten Modellanbieter gesandt. Verwende ein lokales Modell, wenn Inhalte auf dem Gerät bleiben müssen.
  • Verwechsle einen Timeout nicht mit einem Rollback. Ein Abbruch stoppt künftige Schritte; er kann eine gesendete E-Mail, ein abgesandtes Formular, einen Kauf oder eine andere abgeschlossene Aktion nicht rückgängig machen.

Das vollständige Design findest du im Sicherheitsmodell, im Dokument zu Datenschutz und Datenfluss sowie im Leitfaden zu Modi, Sicherheit und Datenschutz.

Verwandte Integration

Du nutzt LM Studio?

LM Studio verwendet das separate WebBrain Web Tools Plugin, nicht dieses MCP-Paket. Dessen Werkzeuge fetch_url und research_url können öffentliche Seiten ohne die Browser-Erweiterung lesen; seine Browser-Werkzeuge können ein Ziel über Port 17375 an deine angemeldete Chromium-Sitzung delegieren.

Wähle ein Bridge-Ziel

Registriere @webbrain/mcp-server nicht in LM Studio, nur um das veröffentlichte Plugin zu nutzen. Siehe den Leitfaden zum LM-Studio-Plugin und wechsle dann die Cloud-Brücken-URL der Erweiterung vom MCP-Port 17374 auf den Plugin-Port 17375, wenn du diese Integration brauchst.

Was dieser Server bewusst nicht tut

  • Er startet keinen Headless-Browser und erstellt kein neues Browser-Profil.
  • Er funktioniert nicht über den Firefox-Build.
  • Er exportiert keine Cookies, Zugangsdaten oder Session-Speicher.
  • Er exponiert die etwa fünfzig Klick-, Eingabe-, Frame-, Screenshot-, Netzwerk- und DOM-Primitive von WebBrain nicht direkt an den MCP-Client.
  • Er macht die Brücke nicht sicher für eine Fernnutzung.
  • Er beseitigt nicht die Notwendigkeit eines konfigurierten Modells in WebBrain.

Wenn du deterministische Browser-Automatisierung auf niedriger Ebene in einem isolierten Profil brauchst, passt ein MCP-Server im Playwright-Stil vielleicht besser. Verwende WebBrain MCP, wenn die entscheidende Anforderung deine vorhandene angemeldete Browser-Sitzung plus WebBrains Sicherheitsmodell im Browser ist.
