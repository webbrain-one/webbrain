Das Modell hinter dem Panel

Wählen Sie die Einrichtung, die zu Ihrer Geduld, Ihren Privatsphäre-Bedürfnissen und Ihrem Budget passt.

WebBrain enthält 114 Anbieterkarten, von gehosteten Cloud-Diensten über direkte Cloud-APIs und Modell-Router bis zu lokalen OpenAI-kompatiblen Servern. Sie benötigen nur einen aktiven Anbieter.

Schnellauswahl

Wenigste Schritte

WebBrain Compass

Integriert, standardmäßig aktiv und mit täglichem Gratis-Kontingent – ohne Modellserver oder API-Schlüssel.

Privatsphäre und Offline-Fähigkeit

Lokales Modell

Nutzen Sie llama.cpp, Ollama, ODS, LM Studio, Jan, vLLM, SGLang oder LocalAI.

Direkt beim Hersteller

Cloud-API

Geben Sie Ihren eigenen Schlüssel für OpenAI, Anthropic, Gemini, Mistral, DeepSeek, xAI, Groq und weitere unterstützte Anbieter ein.

Breites Modellverzeichnis

Modell-Router

Wechseln Sie mit einem Konto zwischen vielen Modellen; ideal für häufiges Experimentieren.

114 integrierte Anbieterkarten

Die Anbieterseite ergänzt 79 direkte APIs und Router, darunter Azure AI Foundry, Vertex AI, Vertex Anthropic, Cerebras, Cohere, DeepInfra, Perplexity, Vercel AI Gateway, Venice und viele regionale Coding-Pakete. Suchen Sie nach Anbieter oder Modellname.

Die meisten Karten nutzen API-Schlüssel und OpenAI-kompatible Endpunkte. Vertex-Karten verwenden ein Google-Cloud-Projekt, eine Region und einen Autorisierungsschlüssel; die globale Region nutzt Googles globalen Endpunkt, und Vertex Anthropic unterstützt zusätzlich die Multi-Region-Hosts us und eu. Cloudflare akzeptiert eine optionale AI-Gateway-ID; bei @cf/-Modellen wird bei leerem Feld automatisch das Gateway default verwendet. Anbieter mit Streaming zeigen Antworten im interaktiven Ask in Echtzeit und versuchen es bei vorzeitigem Verbindungsabbruch automatisch einmal ohne Streaming. Meldet der Dienst den Token-Verbrauch, wird er direkt erfasst; sonst notiert WebBrain eine konservative Schätzung, damit Streaming die Kostenlimits nicht umgeht.

GitHub-Einträge bewusst nicht enthalten

GitHub selbst verschwindet nicht, aber GitHub Models wird am 30. Juli 2026 eingestellt. GitHub Copilot erfordert ein separates Abonnement bzw. eine eigene OAuth-Integration. GitLab Duo und SAP AI Core erfordern zudem spezielle Authentifizierung und Deployment-Erkennung, die die Browser-Erweiterung nicht unterstützt.

Schritte der Einrichtung

  1. Öffnen Sie die Anbieterseite. Wählen Sie im Modellmenü der Seitenleiste Mehr… oder den Link „Anbieter“ oben auf der Einstellungsseite. Der Tab LLM listet die Chat-Anbieter.
  2. Finden Sie den Anbieter. Nutzen Sie „Lokal“, „Cloud“, „Router“ oder das Suchfeld.
  3. Karte aufklappen und Werte ausfüllen. Lokale Server benötigen meist Adresse und Modellname; Cloud-Anbieter zusätzlich einen API-Schlüssel.
  4. Speichern. Schreibt die aktuellen Felder in den Browser.
  5. Verbindung testen. Beheben Sie zuerst Adress-, Schlüssel-, Modell- oder Serverfehler.
  6. Aktiv setzen. Erst nach erfolgreichem Test. Speichern heißt noch nicht aktivieren.

Funktion im Terminal heißt nicht Zugriff für die Erweiterung

Eine abgelehnte Verbindung bedeutet meist, dass der Server nicht gestartet ist oder der Port falsch ist; bei CORS/Origin-Fehlern muss die Herkunft der Browser-Erweiterung erlaubt werden. Für Ollama üblich: OLLAMA_ORIGINS="chrome-extension://*,moz-extension://*" ollama serve.

Prompt-Stufen

CompactKürzester Prompt und kleinste Werkzeugfläche, für kleine lokale Modelle mit rund 8k Kontext.
MidÜbliche Browser-Aufgaben, iframes, Downloads, geplante Aufgaben und Formularprüfung. Empfohlener lokaler Einstieg.
FullErgänzt erweiterte Fallback-Tools wie Hover, Drag & Drop, Frames und Shadow DOM.

Cloud-Anbieter nutzen fest Full; lokale Anbieter standardmäßig Mid; Compact-Anbieter können den Dev-Modus nicht nutzen.

Wenn der Verbindungstest fehlschlägt

  1. Connection refused:Starten Sie den lokalen Server und prüfen Sie den Port.
  2. CORS/Origin:Erlauben Sie die Herkunft der WebBrain-Erweiterung im Server.
  3. Unauthorized:Prüfen Sie, ob Schlüssel und Base URL zum selben Anbieter gehören.
  4. Model not found:Kopieren Sie die exakte Modell-ID oder nutzen Sie Load models.
  5. Zeitüberschreitung:Erhöhen Sie das LLM-Anfrage-Timeout unter „Einstellungen → Budgets“ für große lokale CPU-Modelle.
  6. Scheitert nach wenigen Runden:Prüfen Sie das echte Kontextfenster; senken Sie die Prompt-Stufe oder vergrößern Sie den Modellkontext.

Optionale unterstützende Modelle

Der aktive Anbieter übernimmt die Hauptunterhaltung, die Planung und die endgültigen Antworten. Die weiteren Tabs der Anbieterseite konfigurieren unabhängig ein Vision-Modell, einen Speech-Endpunkt (Sprache-zu-Text), Generative Medien, Entscheidungsmodelle und SafeSocial. Diese Einstellungen hängen nicht vom Anbieterfilter oder -wechsel ab.

Vision- und Entscheidungsmodelle stehen standardmäßig auf Auto: In Chrome wird Compass VLD v6 2B nach Abschluss des Downloads genutzt (Compass VLD Tiny v5, falls nur dieses geladen wurde; fehlen beide und ist nur Ternary Bonsai 2 2B Vision oder D1 geladen, liest Ersteres Screenshots und Letzteres trifft Entscheidungen; ist WebBrain Cloud aktiv, bearbeitet das verwaltete Entscheidungsmodell von Compass die Entscheidungen), vor dem Download keines. Ein Entscheidungsmodell beantwortet nur Ja/Nein- und Multiple-Choice-Fragen wie „Ist diese Aufgabe erledigt?“; wählen Sie Ein, damit OpenRouter, TypeSafe, ein lokaler Server, D1 oder das Browsermodell alle Entscheidungen beantworten, oder Aus, um nie eines zu nutzen. Bestehende Berechtigungen und Abschlussprüfungen gelten weiterhin. Einrichtung und Datenteilung siehe Vision-, Sprach- und Entscheidungsmodelle.
