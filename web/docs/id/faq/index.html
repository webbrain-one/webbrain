Pertanyaan yang Sering Diajukan

Jawaban singkat tentang penyiapan, model, penagihan, keamanan, dan cara kerja WebBrain di browser Anda.

Tidak ada jawaban yang cocok dengan pencarian tersebut.

Tentang WebBrain

7
Apakah WebBrain alternatif gratis untuk plugin peramban Claude?

Ya. WebBrain menyediakan kapabilitas agen peramban AI yang serupa — membaca halaman, mengekstrak data, mengklik tombol, mengisi formulir, dan mengotomatiskan alur kerja multi-langkah. Tidak seperti plugin peramban Claude berpemilik yang membutuhkan langganan Claude Pro dan hanya bekerja dengan model Anthropic, WebBrain sepenuhnya gratis, open-source (lisensi GPL-3.0-or-later), dan mendukung beberapa penyedia LLM termasuk model lokal yang sepenuhnya berjalan di mesin Anda.

Bagaimana WebBrain dibandingkan dengan OpenClaw, Browser-Use, dan kerangka agen AI lainnya?

Mereka kategori alat yang berbeda. WebBrain adalah ekstensi peramban — Anda memasangnya di Chrome atau Firefox dan mengobrol di panel samping, tanpa coding. Kerangka seperti OpenClaw dan Browser-Use adalah SDK pengembang untuk membangun pipeline peramban otomatis dengan Python, biasanya menggunakan peramban headless dan CDP. Bayangkan begini: WebBrain untuk menjelajah sehari-hari bersama asisten AI; kerangka agen untuk membangun bot scraping dan otomasi pengujian. Anda bisa menggunakan keduanya — mereka saling melengkapi.

Bisakah saya mengedit alur kerja WebBrain?

Ya. Gunakan Editor Alur Kerja WebBrain untuk meninjau, mengedit, memvalidasi, dan mengekspor berkas JSON alur kerja di browser Anda.

Apakah WebBrain bekerja di Firefox?

Ya. WebBrain dirilis dengan versi Chrome (Manifest V3, menggunakan sidePanel API) dan versi Firefox (Manifest V2, menggunakan sidebar_action). Kedua versi memiliki fitur yang identik. Versi Firefox dapat dimuat sebagai add-on sementara untuk pengembangan, atau dipublikasikan ke addons.mozilla.org untuk pemasangan permanen.

Bagaimana cara menggunakan WebBrain untuk scraping web dan ekstraksi data?

Cukup buka halaman web mana pun, buka panel samping WebBrain, dan minta dengan bahasa natural: "Ekstrak semua nama produk dan harga dari halaman ini", "Ambil semua alamat email pada halaman ini", atau "Ringkas artikel ini dalam poin". Agen AI membaca isi halaman, memahami strukturnya, dan mengembalikan data yang diekstraksi. Untuk scraping yang lebih kompleks, beralih ke mode Aksi — agen dapat berpindah antar halaman, mengeklik tombol pagination, dan mengagregasi data lintas banyak halaman.

Apakah WebBrain mendukung mode dry-run?

Per 7.0.0, belum. Mode dry-run direncanakan dan sudah ada di roadmap.

Bisakah saya berkontribusi ke WebBrain?

Tentu saja! WebBrain berlisensi GPL-3.0-or-later dan menyambut kontribusi. Lihat repositori GitHub untuk issue, permintaan fitur, dan panduan kontribusi.

Cloud dan penagihan

5
Berapa biaya langganan WebBrain Compass?

WebBrain Compass saat ini US$5/bulan per profil perangkat, jauh lebih murah daripada Claude Pro untuk sementara waktu. Penggunaan saat ini tidak dibatasi dalam kebijakan penggunaan wajar: penggunaan pribadi normal tidak masalah, tetapi penyalahgunaan, otomatisasi berlebihan, penjualan ulang, atau volume yang tidak wajar tidak diperbolehkan.

Langganan ditautkan ke pengenal perangkat yang dibuat ekstensi untuk GUID browser + OS tersebut, bukan ke akun pengguna. Jika pengenal itu hilang karena Anda mereset penyimpanan ekstensi, menghapus profil browser, menginstal ulang browser, mengganti browser/OS, atau kehilangan perangkat, kami tidak dapat mengambil atau memindahkannya dan tidak memberikan pengembalian dana atas kehilangan tersebut.

Bagaimana cara mengelola atau membatalkan langganan saya?

Kelola penagihan di api.webbrain.one/account dan masuk menggunakan email Anda.

Saya sudah membayar WebBrain Compass, tetapi ekstensi meminta saya membayar lagi. Apakah saya harus membayar dua kali?

Tidak — jangan membayar lagi. Langganan Compass Anda tertaut ke pengenal browser/perangkat yang dibuat ekstensi, jadi jika pengenal itu berubah (browser atau perangkat baru, browser diinstal ulang, profil browser dihapus, atau penyimpanan ekstensi disetel ulang), ekstensi tidak lagi mengenali langganan Anda dan meminta pembayaran.

Tautkan kembali langganan Anda ke browser saat ini melalui portal mandiri di api.webbrain.one/portal dan ikuti petunjuk di sana untuk memulihkan akses.

Untuk kwitansi dan perubahan penagihan lainnya, kelola penagihan di api.webbrain.one/account dengan email Anda.

Bagaimana cara kerja Cloud Sync terenkripsi?

Cloud Sync adalah fitur opsional untuk pelanggan aktif WebBrain Compass. Fitur ini menyinkronkan memori WebBrain, teks isi otomatis Profil, dan konfigurasi penyedia yang didukung, termasuk kunci API. Fitur ini tidak menyinkronkan riwayat obrolan, riwayat peramban, tangkapan layar halaman, atau token akses dan refresh OAuth lama.

Peramban Anda mengenkripsi vault sinkronisasi sebelum diunggah dengan kata sandi yang Anda pilih. WebBrain Compass hanya menyimpan vault terenkripsi; tidak dapat membaca memori, teks profil, pengaturan penyedia, atau kunci API Anda, dan tidak dapat memulihkan kata sandi sinkronisasi untuk Anda.

Kolom email untuk autentikasi penagihan/langganan magic-link WebBrain Compass. Bukan kata sandi akun. Jika UI meminta mengubah kata sandi di Cloud Sync, yang dimaksud adalah kata sandi enkripsi sinkronisasi, bukan kata sandi akun WebBrain.

Jika Anda lupa kata sandi sinkronisasi, vault cloud terenkripsi lama tidak dapat didekripsi. Anda dapat mereset vault cloud dan mengunggah salinan terenkripsi baru dari perangkat yang masih menyimpan data secara lokal.

Bagaimana WebBrain menjaga tagihan LLM cloud tetap terkendali?

Tiga lapisan independen:

Tangkapan layar hemat token. Sebelum gambar meninggalkan mesin Anda, WebBrain mengubah ukurannya (sisi pendek dibatasi, rasio aspek dipertahankan) dan mengompresi JPEG secara iteratif hingga muat dengan anggaran token gambar per giliran. Tangkapan layar 2000×1200 yang akan menghabiskan ~1.500 token input di GPT-4o akan dikompresi menjadi ~300–500 token tanpa kerugian praktis untuk tugas membaca halaman. Diimplementasikan di _fitImageDimensions dengan unit test untuk perhitungan anggarannya.

Pemangkasan konteks cerdas. Riwayat percakapan, keluaran alat, dan dump DOM inline dibatasi per giliran dan dipangkas yang terlama lebih dulu saat jendela konteks model aktif mendekati penuh. Anda tidak akan melihat eksekusi diam-diam membengkak dari 10k token menjadi 100k karena read_page mengembalikan artikel sepanjang novel.

Model visi khusus. Pasangkan model teks murah (mis. GPT-4o-mini) untuk perencanaan dan pemanggilan alat dengan model visi terpisah (mis. GPT-4o) hanya untuk tangkapan layar, sehingga Anda tidak membayar harga model multimodal di setiap giliran. Konfigurasikan di Penyedia → Visi.

Hasil akhirnya: sesi panjang dengan penyedia cloud tetap terprediksi. Untuk kendali penuh, gunakan llama.cpp secara lokal — biaya per token nol.

Model dan penyiapan lokal

8
Bisakah saya menggunakan WebBrain sepenuhnya offline?

Ya. Penyedia bawaan WebBrain adalah llama.cpp, yang menjalankan model AI lokal di komputer Anda. Tidak perlu kunci API, AI tidak butuh internet, dan data tidak pernah meninggalkan mesin Anda. Cukup unduh model GGUF, jalankan llama-server, dan Anda punya agen peramban AI yang sepenuhnya privat. Anda juga dapat menggunakan Ollama dengan endpoint kompatibel-OpenAI miliknya.

Apa itu Kotak Darurat, dan bagaimana cara kerja RAG offline?

Kotak Darurat adalah koleksi kurasi berisi ~570 dokumen referensi lapangan domain publik (medis, kelangsungan hidup, pendidikan, komunikasi) yang dapat diunduh dan diindeks secara lokal oleh WebBrain. Setelah terinstal, Anda dapat mengajukan pertanyaan faktual secara offline dan mendapatkan jawaban dari dokumen-dokumen tersebut — tanpa koneksi internet.

Di balik layar, WebBrain menggunakan SQLite FTS5 untuk pencarian kata kunci cepat di Kotak Darurat maupun arsip Wikipedia yang terinstal, plus lapisan pencarian semantik opsional memakai model E5 multibahasa yang diunduh secara lokal (~140 MB). Hasil kedua metode digabungkan dan didiversifikasi, dan setiap jawaban mengutip bagian sumber yang tepat. Kutipan dibuka di pembaca lokal yang memverifikasi integritas dokumen sebelum ditampilkan — tidak pernah membuka halaman web langsung.

Anda juga dapat memasang arsip Wikipedia melalui Mode Apocalypse untuk basis pengetahuan offline yang lebih luas. Filter sumber dan bahasa memungkinkan Anda mengontrol koleksi yang dicari.

Model AI apa saja yang didukung WebBrain?

WebBrain mendukung empat jenis penyedia: llama.cpp (model GGUF lokal apa pun), OpenAI (GPT-4o, GPT-4, dsb.), Claude (Claude Opus, Sonnet, Haiku melalui API asli), dan OpenRouter (akses ke 100+ model dari berbagai penyedia). Endpoint API apa pun yang kompatibel-OpenAI dapat digunakan, jadi Anda juga bisa memakai layanan seperti Together AI, Groq, Mistral, atau server lokal apa pun dengan antarmuka kompatibel-OpenAI.

Model apa yang paling direkomendasikan?

Per 21 April 2026, rekomendasi teratas adalah Qwen 3.6 35B. Alasannya: pada tolok ukur visi kami (vision-model-shootout), ia mengungguli Gemma 4 pada pemahaman tangkapan layar sembari tetap praktis untuk inferensi lokal.

Untuk GPU konsumen, RTX 5090 ideal, dan RTX 4090 sering kali bisa dijalankan dengan kuantisasi INT4 AutoRound via Intel/Qwen3.6-35B-A3B-int4-AutoRound.

Untuk kecepatan maksimal, kami merekomendasikan menyajikan melalui vLLM. Contoh perintah:

python -u -m vllm.entrypoints.openai.api_server --model Intel/Qwen3.6-35B-A3B-int4-AutoRound --served-model-name qwen3.6-35b --quantization auto --dtype bfloat16 --max-model-len 65536 --max-num-batched-tokens 32768 --max-num-seqs 4 --host 0.0.0.0 --port 8000 --gpu-memory-utilization 0.92 --enable-prefix-caching --enable-chunked-prefill --limit-mm-per-prompt '{"image": 4, "video": 1}' --mm-processor-cache-type shm --reasoning-parser qwen3 --enable-auto-tool-choice --tool-call-parser qwen3_coder --trust-remote-code --allowed-origins '["*"]' --speculative-config '{"method": "dflash", "model": "z-lab/Qwen3.6-35B-A3B-DFlash", "num_speculative_tokens": 15}' --attention-backend flash_attn

DFlash speculative decoding bersifat opsional.

Mengapa WebGPU hanya tersedia di Mode Apocalypse?

Karena kami belum menilai inferensi teks WebGPU di browser cukup baik untuk sebagian besar pengguna, dan kami tidak ingin Anda mengalami pengalaman yang buruk. Jika ingin menggunakan model LFM2.5 2.6B yang sama secara lokal, jalankan inferensi di komputer Anda dengan llama.cpp atau Ollama lalu arahkan WebBrain ke endpoint lokal tersebut alih-alih mengandalkan WebGPU.

Fallback visi WebGPU tetap tersedia karena modelnya jauh lebih kecil dan fallback ini hanya digunakan sesekali.

Saya mendapat "Failed to fetch" saat menghubungkan ke server LLM lokal (vLLM, Ollama, llama.cpp) di jaringan saya

Jika server LLM Anda berada di mesin lain dalam jaringan lokal (mis. http://192.168.1.x:8000), Chrome memblokir permintaan kecuali server mengirim header CORS. Solusinya bergantung pada server Anda:

vLLM: Mulai dengan --allowed-origins '["*"]' (nilainya harus berupa list JSON).
Ollama: Atur variabel lingkungan OLLAMA_ORIGINS=* sebelum memulai.
llama.cpp: CORS aktif secara bawaan — tidak perlu perubahan.

Jika server berjalan di localhost (mesin yang sama dengan peramban), CORS biasanya tidak diperlukan. Masalah ini hanya menyangkut koneksi antar mesin di jaringan lokal. Pastikan base URL pada pengaturan WebBrain diakhiri dengan /v1 (mis. http://192.168.1.47:8000/v1). Pengecualian: Ollama yang dipakai dari ekstensi browser mungkin tetap membutuhkan OLLAMA_ORIGINS; lihat FAQ Ollama di bawah.

Mengapa Ollama di localhost mengembalikan 403 dari ekstensi WebBrain?

Versi Ollama terbaru dapat menolak permintaan dari origin ekstensi browser meskipun Ollama berjalan di mesin yang sama. Ekstensi mengirim Origin seperti chrome-extension://... atau moz-extension://..., dan Ollama dapat menjawab 403 kecuali origin tersebut diizinkan.

Tutup aplikasi desktop Ollama apa pun yang sudah memakai port 11434, lalu jalankan Ollama dengan salah satu perintah ini:

OLLAMA_ORIGINS="*" ollama serve
OLLAMA_ORIGINS="chrome-extension://*,moz-extension://*" ollama serve

Biarkan URL dasar Ollama di WebBrain tetap http://localhost:11434/v1. Pemeriksaan curl di terminal masih bisa berhasil tanpa pengaturan ini karena tidak mengirim origin ekstensi browser.

Bisakah saya menggunakannya juga di LM Studio?

Ya. Alat jaringan hanya-baca WebBrain — fetch_url dan research_url — juga hadir sebagai plugin LM Studio mandiri di webbrain/web-tools. Pasang dengan lms clone webbrain/web-tools dan aktifkan di obrolan LM Studio mana pun — model apa pun yang mendukung tool calling kemudian dapat memanggil kedua alat itu tanpa Anda memasang ekstensi peramban. Murni Node, tanpa peramban headless. Sumber: lmstudio-plugin/.

Browser dan penggunaan sehari-hari

5
Bisakah saya memindahkan sidebar Firefox dari kiri ke kanan, seperti panel samping Chrome?

Bisa — sidebar Firefox bawaannya di kiri, tetapi Anda dapat memindahkannya. Klik kanan di mana saja pada header sidebar dan pilih Move Sidebar to Right (atau gunakan View → Sidebar → Move Sidebar to Right dari bilah menu). Posisinya tersimpan antar restart. sidePanel Chrome bawaannya di kanan dan tidak bisa dipindahkan pengguna dari panel itu sendiri.

Apakah ada batasan saat menggunakan WebBrain di Web Panel Vivaldi?

Ya. Web Panel Vivaldi memblokir dialog JavaScript bawaan seperti confirm(), alert(), dan prompt(). Peralihan mode Tanya, Aksi, dan Dev di WebBrain tidak lagi bergantung pada dialog tersebut, tetapi beberapa tindakan sekunder masih bergantung padanya.

Perekaman: Untuk saat ini, jangan gunakan /record di Vivaldi. Jika perekaman gagal, Vivaldi dapat menyembunyikan peringatan galat sehingga tidak ada penjelasan yang terlihat.

Pengaturan, Riwayat, Jejak, dan serah-terima Ollama: Halaman-halaman ini juga memiliki dialog bawaan, tetapi WebBrain biasanya membukanya sebagai tab biasa sehingga berfungsi. Jika Anda memasukkan salah satunya secara manual ke Web Panel, buka di tab biasa sebelum menggunakan tindakan yang bergantung pada dialog.

Bisakah saya menggulir ke atas atau ke bawah saat WebBrain bekerja di tab saya?

Biasanya bisa — terutama dalam mode Ask untuk permintaan hanya-baca seperti “Ringkas halaman ini.” Anda dapat terus menggulir saat WebBrain bekerja.

Kapan sebaiknya dihindari? Tangkapan layar otomatis mencerminkan viewport tab saat ini. Saat WebBrain sedang aktif memeriksa atau berinteraksi dengan konten yang terlihat dalam mode Act atau Dev, menggulir dapat menggeser target atau mengubah apa yang dilihat model. Tunggu hingga langkah tersebut selesai sebelum menggulir; di luar momen itu, Anda dapat terus menggunakan halaman.

Bisakah saya beralih ke tab lain saat WebBrain sedang bekerja pada sebuah halaman?

Ya. Sejak versi 27.0.0, WebBrain tidak mengambil alih fokus di peramban berbasis Chromium maupun Firefox kecuali akses latar depan benar-benar diperlukan. Proses tetap terikat pada tab tempat proses dimulai, sehingga Anda dapat bekerja dengan aman di tab lain.

Jika suatu langkah yang jarang terjadi membutuhkan tab asli berada di latar depan, WebBrain mungkin memfokuskan tab tersebut sebentar. Hindari mengeklik atau mengetik di tab yang sama saat WebBrain sedang aktif bertindak di sana.

Apa yang dilakukan WebBrain dengan spanduk cookie dan paywall?

Spanduk cookie: WebBrain mengenali spanduk persetujuan dari kerangka umum (OneTrust, Cookiebot, Didomi, Quantcast, Google Funding Choices, TrustArc) dan menutupnya sebelum menalar halaman. Prioritasnya adalah "Tolak semua" / "Tolak non-esensial" / "Hanya yang perlu" jika terlihat jelas; jika tidak, ia jatuh ke "Terima semua" alih-alih hilang dalam labirin "Kelola preferensi".

Paywall: WebBrain melaporkan paywall dengan jujur dan memberi tahu Anda apa yang sebenarnya dapat dilihatnya (judul, dek, paragraf pertama). Ia tidak mencoba menembus paywall — tidak ada archive.today, 12ft.io, pembersihan cookie, penonaktifan JS, atau trik mode pembaca. Jika ingin artikel penuh, masuk dengan langganan atau minta WebBrain mencari liputan gratis untuk cerita yang sama.

Keamanan dan privasi

8
Apakah WebBrain aman digunakan? Bisakah ia memodifikasi halaman web?

WebBrain memiliki tiga mode. Mode Tanya (bawaan) hanya-baca dan tidak dapat mengubah apa pun pada halaman. Mode Aksi memungkinkan tindakan peramban seperti mengeklik, mengetik, dan menavigasi, sedangkan mode Dev menambahkan alat debug halaman. Tindakan yang berdampak memerlukan persetujuan secara bawaan; jika gerbang izin tersebut dimatikan, WebBrain menampilkan spanduk peringatan yang terlihat. Anda dapat menghentikan agen kapan saja dengan tombol Berhenti. Kode sumber ekstensi sepenuhnya terbuka untuk audit di GitHub.

Apa itu spanduk «WebBrain started debugging this browser»? Mengapa WebBrain memakai CDP?

Agar dapat bertindak pada halaman dengan andal, WebBrain memakai Chrome DevTools Protocol (CDP) melalui API ekstensi standar chrome.debugger — itulah yang memicu spanduk Chrome «WebBrain started debugging this browser». CDP memungkinkan agen mengeklik dan mengetik dengan peristiwa input tepercaya yang benar-benar diterima situs modern; peristiwa sintetis yang dipicu dari content script ditolak oleh banyak situs, Web Components, dan bidang yang dikontrol framework. Lewat ini pula WebBrain mengambil tangkapan layar berpresisi piksel untuk cadangan visi dan menjangkau iframe lintas-asal dan shadow DOM yang tak terlihat oleh content script.

Mode Tanya yang hanya-baca tidak memerlukan CDP — pembacaan halaman dan pohon aksesibilitas berjalan lewat content script biasa. Yang membutuhkannya adalah keandalan Mode Aksi dan pekerjaan lintas-asal, dan pada ekstensi Manifest V3 tidak ada API tanpa debugger untuk input tepercaya. WebBrain melampirkan debugger hanya saat sebuah tindakan membutuhkannya, per tab, dan seluruh ekstensi bersifat sumber terbuka sehingga Anda dapat mengaudit persis apa yang dilakukan sesi. CDP itu kuat, jadi kami memperlakukan jejaknya sebagai sesuatu yang harus dibatasi (lampirkan sesuai kebutuhan, jauhkan pembacaan darinya), dan memperketatnya lebih lanjut ada dalam peta jalan keamanan kami.

Pertanyaannya terlalu banyak. Bisakah saya menonaktifkannya?

Prompt persetujuan itu ada demi keselamatan Anda. Bahkan di situs yang Anda percayai, pelaku jahat dapat meniru instruksi LLM atau menyisipkan konten yang mencoba membuat agen melakukan hal-hal atas nama Anda yang tidak akan Anda setujui. Karena itu WebBrain meminta persetujuan sebelum tindakan yang berdampak. Jika Anda tetap tidak ingin melalui prompt tersebut, ketik /dangerously-skip-permissions di panel samping atau nonaktifkan: buka plugin samping, klik ikon roda gigi di header, buka tab Permissions di settings.html, lalu matikan opsi Ask before consequential actions.

Apakah WebBrain memanggil API langsung, atau selalu mengeklik melalui UI?

Secara bawaan, WebBrain selalu melalui UI yang terlihat untuk setiap tindakan yang membuat, memodifikasi, menghapus, mengirim, mengeposkan, atau membeli sesuatu. Ia akan menavigasi ke halaman, mengisi formulir, dan mengeklik tombol — persis seperti yang akan Anda lakukan. Ia menolak memanggil endpoint REST/GraphQL secara langsung melalui fetch() latar belakang untuk mutasi. Ini disengaja: tindakan API tidak terlihat (Anda tidak melihat apa yang dikirim), sering memerlukan token autentikasi terpisah yang mungkin belum Anda konfigurasi, dan memiliki radius dampak yang jauh lebih besar daripada satu salah klik yang terlihat. UI-first berarti semuanya tampil di layar, di dalam sesi peramban normal Anda, dan dapat dihentikan.

Untuk membaca data — mengambil README, melihat issue, membandingkan harga antar situs, memeriksa halaman status — WebBrain dengan bebas menggunakan permintaan HTTP latar belakang melalui alat fetch_url dan research_url. Membaca bukanlah tindakan; tidak mengubah apa pun pada layanan jarak jauh, sehingga kekhawatiran keamanan yang sama tidak berlaku.

Jika Anda secara khusus ingin mengizinkan mutasi API untuk sebuah tugas tertentu, ketikkan /allow-api di awal pesan Anda (opsional diikuti dengan deskripsi tugas singkat). Override per-percakapan ini memungkinkan WebBrain jatuh ke endpoint API saat UI benar-benar gagal atau tak bisa digunakan, sembari tetap memprioritaskan UI saat UI bisa. Sebuah lencana tetap muncul di atas area input selama override aktif, dan akan hilang saat Anda mereset percakapan.

Bagaimana isi-otomatis Profil bekerja, dan apakah aman?

Isi-otomatis profil adalah fitur opsional di Pengaturan → Memori. Anda memasukkan bio singkat — nama, email kerja, perusahaan, dan kata sandi sekali pakai untuk pendaftaran berisiko rendah — lalu mengaktifkannya. Saat aktif, WebBrain menambahkan teks itu ke prompt sistem agen sehingga ia dapat mengisi formulir pendaftaran tanpa bertanya setiap kali.

Teks tersebut disimpan dalam bentuk teks biasa di penyimpanan lokal peramban Anda. Teks itu tidak dikirim ke proyek WebBrain, tetapi dikirim ke penyedia LLM yang Anda konfigurasi pada setiap giliran, sebagai bagian dari prompt sistem. Mati secara bawaan.

Jangan menaruh kata sandi akun penting (Google, Apple, iCloud, perbankan, SSO kantor, email utama) di sini. Akun-akun itu seharusnya menggunakan 2FA dan tidak perlu Anda serahkan kepada agen. Kasus penggunaan yang dimaksud adalah kata sandi sekali pakai yang Anda pakai ulang untuk pendaftaran newsletter dan uji coba gratis.

Apakah pengaturan Penyamaran tangkapan layar menjamin data pribadi saya tidak pernah sampai ke model visi cloud?

Tidak — pengaturan ini mengurangi risiko paparan, bukan jaminan. Saat diaktifkan (Pengaturan → Lanjutan → Penyamaran tangkapan layar, nonaktif secara default), WebBrain mem-pixel-kan kolom formulir dan teks yang terlihat seperti alamat email atau nomor telepon pada setiap tangkapan layar sebelum dikirim ke model visi. Pendeteksian berjalan sepenuhnya di perangkat Anda menggunakan heuristik DOM; tidak ada yang dikirim ekstra.

Ini bersifat best-effort dan fail-open. Jika detektor tidak bisa berjalan di suatu halaman — misalnya tepat setelah navigasi, di penampil PDF, atau di halaman browser yang dibatasi — tangkapan layar tetap dikirim tanpa disamarkan daripada membatalkan tugas Anda. Konten yang tidak bisa dilihat heuristik DOM (teks yang digambar di canvas, informasi pribadi di dalam gambar, widget yang tidak umum) juga bisa lolos. Dan pengaturan ini hanya mencakup tangkapan layar: teks halaman yang dikirim ke model tidak disamarkan olehnya.

Untuk privasi visi yang penuh, gunakan model lokal. Dengan penyedia offline seperti llama.cpp atau Ollama, tangkapan layar dan teks halaman tidak pernah meninggalkan perangkat Anda, jadi sejak awal tidak ada yang perlu disamarkan — ini satu-satunya konfigurasi di mana privasi benar-benar terjamin. Lihat "Bisakah saya menggunakan WebBrain sepenuhnya offline?" di atas.

Tidak punya perangkat yang mampu menjalankan model lokal dengan visi? Jalan tengah yang baik adalah menggunakan model lokal kecil untuk perencanaan dan pemanggilan alat (cukup ringan untuk CPU/GPU yang sederhana), dipadukan dengan penyedia cloud untuk sub-panggilan visi, dengan Penyamaran tangkapan layar diaktifkan. Percakapan dan teks halaman Anda tetap berada di perangkat, dan setiap tangkapan layar yang dikirim ke visi cloud sudah memiliki kolom formulir serta email/telepon yang terdeteksi dalam keadaan buram — paparan cloud berkurang tanpa perlu perangkat keras untuk model visi lokal penuh. Atur pembagian ini di Penyedia → Visi (lihat "Bagaimana WebBrain menjaga tagihan LLM cloud tetap terkendali?" di atas).

Apakah WebBrain mengirim seluruh DOM ke model AI?

Tidak. Secara default, WebBrain tidak mengirim HTML mentah atau salinan mentah DOM. Ia memulai dengan URL dan judul halaman, panduan situs yang sesuai, serta tangkapan layar viewport opsional saat fitur visi diaktifkan.

Ketika suatu tugas membutuhkan konten halaman, WebBrain membacanya sesuai kebutuhan sebagai pohon aksesibilitas semantik yang diringkas atau teks yang diekstrak. Pembacaan difilter berdasarkan visibilitas bila sesuai, dibatasi jumlah karakternya, dan dibagi menjadi beberapa halaman. Akses ke sumber halaman mentah hanya tersedia dalam mode Dev.

Mengapa WebBrain 33.0.0 dan versi lebih baru berlisensi GPL?

WebBrain 33.0.0 dan versi lebih baru didistribusikan di bawah GPL-3.0-or-later karena ekstensi browser memaketkan dan mengintegrasikan runtime WebAssembly Xapian/libzim berlisensi GPL untuk pencarian teks penuh arsip ZIM Wikipedia.

Paket ekstensi menyertakan pemberitahuan GPL yang berlaku, dan sumber lengkap runtime yang dipaketkan dipublikasikan bersama setiap rilis. Rilis sebelum 33.0.0 tetap berlisensi MIT, dan subproyek yang diterbitkan independen serta komponen pihak ketiga mempertahankan lisensi masing-masing. Lihat catatan keputusan lisensi untuk detailnya.
