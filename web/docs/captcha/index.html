CAPTCHA solvers and fallback

Enable the services you want WebBrain to use, choose their order, and see which challenges each service supports.

API coverage checked September 29, 2026 · Chrome and Firefox

Set up a provider

  1. Open Settings → CAPTCHA.
  2. Enter a provider API key. Typing checks its enabled box; you can turn the box off while keeping the key.
  3. Save the setting. Test checks the account balance without enabling or saving the provider.
  4. Enable additional services if you want fallback. Each has its own checkbox.

The provider’s collapsed Advanced section contains its weight. A higher weight means it is tried earlier. Equal weights retain the default order.

Providers and coverage

All seven services have API integrations. Common widgets can use automatic detection; other methods need the challenge-specific inputs shown in their API documentation. A service being listed does not guarantee that a particular website accepts its answer.

CAPTCHA tools are available in Act and Dev with Mid or Full tiers. Ask does not expose them. Compact requests manual completion and can report a partial result when verification blocks the task.

Which providers handle hCaptcha?

NopeCHA and NoneCap are the integrated hCaptcha providers. The other five services are not advertised as hCaptcha solvers in WebBrain. Old examples, sandbox pages, and unpublished drafts are not treated as evidence of a current production API.

Enterprise hCaptcha may need fresh rqdata, a matching proxy, or the solver’s browser identity. A returned token still needs to be accepted by the website. No paid live acceptance benchmark was performed for this integration.

How fallback works

WebBrain tries enabled, compatible providers in weight order. An error or timeout moves to the next provider within the same solve request. A disabled provider is skipped even if its key is saved. A provider is submitted at most once in that request.

More than one service may charge

A timed-out job can still finish at the first service while the next one starts. Fallback can therefore cost more than one solve. WebBrain does not start another provider cycle because the page later rejects an answer.

NopeCHA and NoneCap balances are shown as credits. Provider prices, plans and availability can change; check the provider’s account page.

What happens on the page?

Automatic detection handles supported reCAPTCHA, hCaptcha and standalone Turnstile widgets. The agent can inspect the wider native catalog, supply observed inputs, and receive tokens, cookies, text, coordinates or structured answers. It can bind those answers to a selected page field, callback, cookie or image/grid target.

Some sites need additional integration for sliders, drag paths, rotation controls or proprietary submissions. Recognition clicks use synthetic events, which some sites reject. Missing inputs or unsuccessful page verification require manual completion; an API response alone is not proof that the challenge cleared.

WebBrain does not silently change your proxy or User-Agent. In particular, NopeCHA Turnstile requires a proxy matching the browser’s submission IP. Cookie-based Cloudflare methods have their own HTML, proxy and browser requirements.

Account keys and data

Keys are stored in extension settings and added to API requests internally. Each attempted provider receives the challenge inputs needed by that method, which may include the page URL, site key, metadata, image/audio bytes and explicitly supplied proxy/cookie data. Testing a balance also contacts that provider.

Cookie answers are applied only through explicit bindings to the current page and its browser cookie store. The extension requests the cookies permission for this. It does not automatically send your entire cookie jar or execute code returned by a solver.

Managed WebBrain Cloud sessions retain their separate CapSolver broker. Personal keys, weights and native method calls do not expand that managed service.
