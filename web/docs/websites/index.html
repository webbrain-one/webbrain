Docs / WebBrain for websites
One script tag

Give every visitor an assistant that reads and works on your pages.

WebBrain for websites puts a launcher on your site. Visitors ask about the page they are on, and, if you allow it, WebBrain fills in forms and clicks buttons for them. It is free, and you manage it at sites.webbrain.one.

How it works

  1. Your page loads the widget. The script tag loads embed.js from sites.webbrain.one. It adds the launcher and the chat panel to the page, inside its own shadow root so your styles and its styles don't mix.
  2. The visitor asks. The widget reads the page the way the WebBrain browser extension does: as an accessibility tree of headings, text, links, fields and buttons. Visitors install nothing.
  3. The server asks the model. The widget sends the question and what it read to sites.webbrain.one, which adds your site's settings and instructions and asks the AI model what to do next.
  4. The widget does it, on the page. The model either answers or asks for a tool: read more of the page, scroll, do exact math, or, in Ask and act, type and click. The widget runs the tool in the visitor's browser and sends the result back. A question takes a few of these steps; at most 5 in Ask and 8 in Act.

The widget is built from the extension's own code, so it reads pages and acts on them the same way. Its source is in the WebBrain repository under GPL-3.0, and every copy of embed.js links to the exact commit it was built from.

About five minutes

Add it to your site

  1. Sign in at sites.webbrain.one. Enter your email and open the sign-in link we send you. The link works once and expires in 15 minutes. There is no password.
  2. Add your site. Give it a name and its address, for example example.com. The address matters: the assistant answers only on that domain (see Limits).
  3. Copy the script from the Install tab and paste it before </body> on every page where you want WebBrain, or into your CMS's custom code setting.
  4. Publish. The launcher appears in the corner you chose. Later changes in the dashboard reach your site without touching the script.
<!-- WebBrain for websites -->
<script src="https://sites.webbrain.one/embed.js"
        data-site-id="site_…"
        defer></script>

Your site ID is in the dashboard under Settings. It never changes. Deleting a site there stops its script at once.

Try it before it goes live

Open the playground to see the assistant with your site's settings, or paste the script into a page on localhost, which every site accepts for testing.

Ask only, or Ask and act

On the Behavior tab you choose what WebBrain may do on your site. The server enforces it, whatever the page or the visitor asks for, and the widget runs only the tools of the mode it is in.

Ask onlyReads the page, answers questions, summarizes, extracts data and does exact math. Never clicks or types.
Ask and actCan also type into fields, tick boxes, choose options, click buttons, press keys and follow links for the visitor, with a glow around the page and a Stop button.
ModeTools the model may use
Askget_accessibility_tree, read_page, get_interactive_elements, get_window_info, extract_data, get_selection, scroll, wait_for_stable, calculate, done
Act addsclick_ax, click, type_ax, type_text, set_field, set_checked, press_keys, navigate, find_text, wait_for_element, scratchpad_write

Act works as the visitor, in their browser, on the page they have open: whatever they could click, it can click. Choose Ask only unless filling forms or walking through steps for visitors is the point.

Behavior settings

SettingWhat it does
GreetingThe first thing visitors see when they open the assistant. Up to 160 characters.
Instructions for this siteAdded to every conversation on your site; visitors don't see them. Use them for what the page itself doesn't say: tone, what to recommend, what to avoid, where to send people. For example: “When visitors ask about pricing, point out that annual billing saves 20%. For refunds, link to /support.”
Highlight to askWhen a visitor selects text, a small pill offers to explain it.
Instructions guide the model; they don't lock anything

Write instructions for the help you want, not as a security boundary. What the assistant can do is set by the mode and the tools above.

Starter questions

On the Starter questions tab, add one-click questions that show when visitors open the assistant. Each has a label (what the button says), a prompt (what is actually asked) and a mode. Act questions are turned off while the site is set to Ask only.

Good starter questions are specific to the page: “Summarize this plan comparison”, “Which plan fits a team of 5?”, “Fill in the demo request for me”.

Buttons and the JavaScript API

Any element on a page that loads the script can start a question. Add the attribute to a button or link:

<!-- Asks right away -->
<button data-webbrain-ask="Summarize this page in 3 points">Summarize this page</button>

<!-- Puts the request in the composer; the visitor sends it -->
<button data-webbrain-act="Fill in the contact form for me">Fill it in for me</button>

data-webbrain-act only fills in the composer, because any markup on a page, including comments and posts your users wrote, can carry the attribute. The visitor decides to send it. Clicks made by WebBrain itself never start a run.

From your own code, window.WebBrain is ready once the script has loaded:

WebBrain.open();      // open the panel (also: close(), toggle())
WebBrain.ask('Summarize this page in 3 points');
WebBrain.act('Fill in the contact form for me');   // sites set to Ask and act
WebBrain.clear();     // start a new conversation
WebBrain.reloadConfig();   // pick up dashboard changes without a reload

Limits

WebBrain for websites is free, and the model it runs on is ours, so the chat is guarded:

GuardWhat it means for your site
Your domain onlyThe assistant answers only on the address you gave the site, its www. form and its subdomains, and on localhost for testing. Elsewhere visitors see “This assistant only answers on its own website.” If you move domains, update the address under Settings.
Per visitorA visitor who asks a lot in a short time is asked to wait a few minutes. There is a daily cap per visitor too.
Per site and overallEach site, and the service as a whole, has a daily limit. When one is reached, visitors are told to try again tomorrow.
Conversation lengthVery long conversations are refused with a prompt to start a new chat.

Normal use stays far below these limits. If your site needs more, tell us on Discord.

Privacy and safety

  • What leaves the visitor's browser: their question, the conversation so far, and the parts of the page the assistant read. They go to sites.webbrain.one and on to the AI model provider for that turn.
  • What we keep: counts per site (conversations, Ask and Act runs, tool calls) and the day's usage. Not the conversations.
  • Passwords stay out. Values of password, hidden and other credential fields are never put in what the assistant reads.
  • Pages are untrusted. Page text is passed to the model marked as untrusted content, so text on a page can't pose as instructions. As with any AI agent, this reduces the risk; it doesn't remove it.
  • Visitors stay in control. Every Act run shows a glow around the page and a Stop button.
Tell your visitors

If your privacy policy lists the services your site uses, add that page content and questions asked in the assistant are sent to WebBrain and its AI model provider to answer them.

Troubleshooting

What you seeWhat to check
No launcherThe script is on the page, before </body>, with the right data-site-id. If your site sends a Content Security Policy, allow https://sites.webbrain.one in script-src, connect-src and img-src.
“This assistant only answers on its own website.”The page's domain doesn't match the site's address under Settings, or the page is opened from a file.
“The assistant can't answer right now.”The AI model didn't answer. Try again in a moment; if it keeps happening, tell us.
“Too many questions in a short time.”The per-visitor limit; it clears within minutes.
“…reached today's limit.”A daily limit; it resets at midnight UTC.
Dashboard changes don't showReload the page, or call WebBrain.reloadConfig().
Act does nothingThe site is set to Ask only, or the request was made with data-webbrain-act, which waits for the visitor to send it.
