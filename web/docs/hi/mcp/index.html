अपने कोडिंग एजेंट को उस ब्राउज़र का उपयोग करने दें जिसमें आप पहले से साइन इन हैं।

WebBrain MCP, Codex, Claude Code, Cursor, OpenClaw, OpenCode और अन्य stdio MCP क्लाइंट्स को आपके असली Chromium प्रोफ़ाइल से जोड़ता है। एक बार की सेटअप पूरी करने के बाद, बस ब्राउज़र टास्क को स्वाभाविक भाषा में बताएँ। आपका कोडिंग एजेंट उपयुक्त WebBrain टूल चुनकर उन्हें कॉल करता है; WebBrain लक्ष्य को ब्राउज़र के अंदर निष्पादित करता है, साइडबार जैसे ही मोड, सोर्स-अनुमति और दृश्यमान स्टॉप कंट्रोल का उपयोग करते हुए।

आपको MCP फ़ंक्शन कॉल खुद टाइप करने की ज़रूरत नहीं

बस कहें "WebBrain का उपयोग करके मेरे ब्राउज़र में खुले डैशबोर्ड का सारांश बताओ" या "WebBrain के Act मोड से इस फ़ॉर्म को अपडेट करो"। आपका MCP क्लाइंट उस अनुरोध को टूल कॉल में बदल देगा और उसी बातचीत में परिणाम लौटाएगा। इस गाइड में आगे फ़ंक्शन के रूप में दिखाए गए उदाहरण मुख्यतः डीबगिंग या क्लाइंट डेवलपर्स के संदर्भ के लिए हैं।

केवल Chromium

ब्रिज को एक्सटेंशन के ऑफ़स्क्रीन डॉक्यूमेंट की ज़रूरत होती है, इसलिए Chrome, Edge, Brave, Opera या Vivaldi उपयोग करें। Firefox एक्सटेंशन अपनी जगह पूरी तरह उपयोगी रहता है, पर इस MCP सर्वर से नहीं जुड़ सकता।

पूरा रास्ता

क्या कहाँ शुरू होता है

आपका MCP क्लाइंट npm पैकेज को stdio के ज़रिए एक लोकल चाइल्ड प्रोसेस के रूप में चलाता है। यह प्रोसेस केवल 127.0.0.1:17374 पर सुनता है। एक्सटेंशन उसी की ओर डायल करता है, और फिर चुने गए ब्राउज़र टैब में WebBrain के एजेंट लूप से हर टास्क निष्पादित करता है।

→
@webbrain/mcp-serverstdio · 127.0.0.1:17374

आपके ब्राउज़र में WebBrainसाइन इन किए टैब · अनुमति गेट

सर्वर दूसरा ब्राउज़र नहीं है और न ही Cookie कॉपी करता है। यह MCP क्लाइंट और एक्सटेंशन के बीच एक लोकल हैंडऑफ पॉइंट है। ब्राउज़र प्रोफ़ाइल—और इसलिए प्रमाणित सेशन—कभी नहीं हिलती।

कनेक्ट करने से पहले

आवश्यकताक्या जाँचें
Chromium ब्राउज़रवर्तमान WebBrain एक्सटेंशन इंस्टॉल किए हुए Chrome, Edge, Brave, Opera या Vivaldi।
Node.jsNode 20 या उससे नया। npx पैकेज डाउनलोड करके चलाता है।
MCP क्लाइंटCodex, Claude Code, Cursor, OpenClaw या OpenCode जैसे लोकल stdio सर्वर का समर्थन करने वाला क्लाइंट।
एक खाली लोकल पोर्ट17374 किसी अन्य WebBrain MCP प्रोसेस से पहले से घिरा नहीं होना चाहिए।
सक्रिय WebBrain प्रदातासौंपे गए टास्क को निष्पादित करने के लिए एक्सटेंशन को फिर भी सेटअप किए WebBrain Compass, लोकल या API-समर्थित मॉडल चाहिए।
चरण 1 · केवल एक बार

अपने MCP क्लाइंट में सर्वर रजिस्टर करें

नीचे दी गई क्लाइंट-विशिष्ट सेटअप में से कोई एक चुनेँ, केवल एक बार। ये इंस्टॉलेशन कमांड हैं, ब्राउज़र टास्क माँगने का तरीका नहीं। रजिस्ट्रेशन के बाद क्लाइंट आपके लिए सर्वर शुरू कर देगा और आप सामान्य बातचीत जारी रखें; उसी पोर्ट पर मैनुअल कॉपी एक साथ न चलाएँ।

Codex ऐप, CLI या IDE एक्सटेंशन

codex mcp add webbrain -- npx -y @webbrain/mcp-server

Codex MCP सर्वर को ~/.codex/config.toml में सहेजता है; एक ही Codex होस्ट पर ऐप, CLI और IDE एक्सटेंशन यही सेटअप साझा करते हैं। लंबे ब्राउज़र टास्क के लिए यह फ़ाइल खोलें और टूल को Codex के डिफ़ॉल्ट प्रति-कॉल बजट से ज़्यादा समय दें:

[mcp_servers.webbrain]
command = "npx"
args = ["-y", "@webbrain/mcp-server"]
tool_timeout_sec = 360

फ़ाइल बदलने के बाद ऐप या IDE एक्सटेंशन दोबारा चालू करें। CLI में, codex mcp list चलाकर एंट्री की पुष्टि करें, और Codex सेशन में /mcp से जुड़े सर्वर की जाँच करें। साझा होस्ट सेटअप और सभी समर्थित विकल्पों के लिए आधिकारिक Codex MCP गाइड देखें।

Claude Code

claude mcp add --transport stdio webbrain -- npx -y @webbrain/mcp-server

स्पष्ट ट्रांसपोर्ट मौजूदा Claude Code MCP सेटअप से मेल खाता है। जोड़ने के बाद claude mcp list चलाकर सर्वर की स्थिति जाँचें।

Cursor

Cursor की MCP सेटिंग्स में लोकल stdio सर्वर जोड़ें, या यह सामग्री Cursor के MCP JSON फ़ाइल में डालें। फ़ॉर्मैट Cursor लोकल MCP सर्वर फ़ॉर्मैट का पालन करता है:

{
  "mcpServers": {
    "webbrain": {
      "command": "npx",
      "args": ["-y", "@webbrain/mcp-server"]
    }
  }
}

OpenCode

यह एंट्री ~/.config/opencode/opencode.json में जोड़ें, OpenCode के लोकल MCP सर्वर फ़ॉर्मैट का उपयोग करते हुए:

{
  "mcp": {
    "webbrain": {
      "type": "local",
      "command": ["npx", "-y", "@webbrain/mcp-server"]
    }
  }
}

OpenClaw

OpenClaw में WebBrain को आउटबाउंड MCP सर्वर के रूप में रजिस्टर करें। इस इंटीग्रेशन के लिए openclaw mcp serve उपयोग न करें: वह कमांड OpenClaw को स्वयं सर्वर बना देता है, जो उलटी दिशा है।

openclaw mcp add webbrain \
  --command npx \
  --arg -y \
  --arg @webbrain/mcp-server \
  --timeout 360

mcp add सहेजने से पहले stdio सर्वर को जाँचता है। सहेजी गई परिभाषा देखने के लिए openclaw mcp status --verbose चलाएँ। सामान्य coding और messaging टूल प्रोफ़ाइल में सेट किए MCP सर्वर शामिल होते हैं; minimal प्रोफ़ाइल, स्पष्ट bundle-mcp डीनाई या सैंडबॉक्स टूल पॉलिसी उन्हें छिपा सकती हैं। मौजूदा रजिस्ट्री और पॉलिसी विवरण के लिए OpenClaw MCP गाइड देखें।

मैन्युअल रूप से चलाएँ

लिस्टनर का निदान करने के लिए मैनुअल शुरुआत उपयोगी है, पर आम तौर पर MCP उपयोग में ज़रूरी नहीं:

npx -y @webbrain/mcp-server

उस टर्मिनल को खुला रखें। उसे बंद करने से ब्रिज लिस्टनर बंद हो जाता है। सोर्स चेकआउट से, mcp-server/ के अंदर npm install, npm run build, फिर npm start चलाएँ।

चरण 2

WebBrain को लोकल लिस्टनर की ओर मोड़ें

  1. अपने MCP क्लाइंट को चालू या रीस्टार्ट करें।एक्सटेंशन के जुड़ने से पहले उसका WebBrain सर्वर चल रहा होना चाहिए।
  2. WebBrain सेटिंग्स खोलें।सेटिंग्स → Bridge पर जाएँ।
  3. सटीक URL सेट करें।ws://127.0.0.1:17374/extension दर्ज करें।
  4. पेयरिंग की चिपकाएँ।टर्मिनल में npx -y @webbrain/mcp-server pairing-key चलाएँ (या ~/.webbrain/bridge-key खोलें), और कुंजी को पेयरिंग की फ़ील्ड में चिपकाएँ। सर्वर केवल उसी ब्राउज़र पर भरोसा करता है जो यह कुंजी रखने का सबूत दे। यदि फ़ील्ड नहीं दिखती, पहले WebBrain अपडेट करें।
  5. क्लाउड ब्रिज चालू करें।स्थिति "कनेक्ट हो रहा है" से "कनेक्ट हो गया" होनी चाहिए। यह नाम ऐतिहासिक कारणों से है: यह गंतव्य लोकल है।
  6. एंड-टू-एंड कनेक्शन जाँचें।MCP क्लाइंट से webbrain_connection कॉल करवाएँ। "Connected" इस बात का प्रमाण है कि क्लाइंट, लोकल सर्वर, WebSocket लिस्टनर और एक्सटेंशन हैंडशेक—सब तैयार हैं।
एक समय में केवल एक ब्रिज गंतव्य

एक्सटेंशन एक आउटबाउंड ब्रिज सॉकेट रखता है: WebBrain Cloud 17373 पर, यह MCP सर्वर 17374 पर, या LM Studio प्लगइन 17375 पर। URL बदलने से गंतव्य बदल जाता है; वे एक साथ नहीं चलते।

चरण 3 · बस पूछें

ब्राउज़र टास्क को स्वाभाविक भाषा में बताएँ

Codex, Claude Code, Cursor, OpenClaw या OpenCode में, वैसा ही लिखें जैसे किसी साथी को टास्क सौंपते। WebBrain का नाम लेने से आपका इरादा बिल्कुल स्पष्ट हो जाता है; पेज, अपेक्षित परिणाम, दायरा, और यह कि बदलाव की अनुमति है या नहीं—सब शामिल करें।

पेज बदले बिना पढ़ाई

WebBrain का उपयोग करके मेरे ब्राउज़र में खुले Stripe डैशबोर्ड को पढ़ो। पिछले सात दिनों की असफल पेमेंट्स की सूची दो—ग्राहक, राशि, मुद्रा, तारीख और असफलता का कारण शामिल करते हुए। कुछ भी मत बदलो।

पूर्वानुमेय JSON लौटाएँ

WebBrain का उपयोग करके मेरे ब्राउज़र में खुले डैशबोर्ड से सभी बकाया इनवॉइस निकालो। ग्राहक, राशि, मुद्रा, देय तिथि और इनवॉइस URL वाला JSON लौटाओ। कुछ भी मत बदलो।

पेज से इंटरैक्ट करें

WebBrain के Act मोड से मेरे ब्राउज़र में दिख रही कस्टमर रिकॉर्ड खोलो, और कंपनी का नाम Acme Europe में अपडेट करो। किसी भी अंतिम सबमिट या पुष्टि से पहले रुक जाओ।

कोडिंग एजेंट आम पढ़ाई या इंटरैक्शन के लिए webbrain_run चुनता है, और संरचित डेटा माँगे जाने पर webbrain_extract चुनता है। वह पैरामीटर देता है, रन की मॉनिटरिंग करता है, और WebBrain का परिणाम बातचीत में वापस प्रस्तुत करता है। Ask मोड पढ़ और एक्सट्रैक्ट सकता है; क्लिक, टाइप, नेविगेट या सबमिट नहीं कर सकता। Act मोड इंटरैक्ट कर सकता है, WebBrain की सामान्य ब्राउज़र-साइड अनुमतियों के अधीन रहते हुए।

अंदरूनी विवरण—आपको ये टाइप करने की ज़रूरत नहीं

ऊपर वाले पहले प्रॉम्प्ट के लिए क्लाइंट कुछ इस तरह का कॉल करेगा। यह रूप MCP क्लाइंट बनाने या डीबग करते समय काम आता है; आम उपयोगकर्ता इसे छोड़ सकते हैं।

webbrain_run(
  task: "read the open Stripe dashboard and list failed payments from the last 7 days with customer, amount, currency, date, and failure reason",
  mode: "ask"
)

जिन टास्क्स में इंटरैक्शन ज़रूरी है, साफ़ कहें "WebBrain का Act मोड उपयोग करें" और ब्राउज़र दृश्यमान रखें। WebBrain अपने सामान्य सोर्स-वार क्षमता अनुमोदन प्रॉम्प्ट लागू करेगा।

छह टूल, एक भरोसे की सीमा

वे टूल जो आपका MCP क्लाइंट आपके लिए इस्तेमाल करता है

आप आम तौर पर परिणाम चुनते हैं, टूल नहीं। आपका MCP क्लाइंट ये विवरण पढ़ता है, उपयुक्त टूल चुनता है, आपके अनुरोध के अनुसार उसके इनपुट भरता है, और आगे की कॉल्स संभालता है। यह रेफरेंस आपको यह व्यवहार समझने या डीबग करने के लिए है।

टूलकिस काम के लिएज़रूरी इनपुट
webbrain_runकोई भी ब्राउज़र लक्ष्य, केवल-पढ़ने वाला या इंटरैक्टिव।task, mode, वैकल्पिक tab_id, wait, timeout_seconds, और केवल Act वाला allow_api_mutations।
webbrain_extractप्रमाणित पेज डेटा से पूर्वानुमेय JSON निकालना। हमेशा Ask मोड।task, output_schema, वैकल्पिक tab_id, wait और timeout_seconds।
webbrain_statusएक बैकग्राउंड रन को पोल करना या सभी ज्ञात रन्स की सूची देना।वैकल्पिक run_id। छोड़ देने पर रन्स की सूची मिलती है।
webbrain_respondउपयोगकर्ता का जवाब रुके हुए रन तक पहुँचाना।run_id, clarify_id, answer, वैकल्पिक timeout_seconds।
webbrain_abortगलत या अब ज़रूरी न रहे रन को रोकना।run_id। यह पहले हो चुके ऑपरेशन वापस नहीं करता।
webbrain_connectionएक्सटेंशन हैंडशेक जाँचना और टूटे कनेक्शन पर लक्षित समाधान पाना।कोई इनपुट नहीं।
MCP क्लिक या टाइप टूल क्यों नहीं है

WebBrain की अनुमति जाँचें एक्सटेंशन के एजेंट लूप में होती हैं। निचले स्तर के प्राइमेटिव्स को सीधे MCP से सामने लाना उस सीमा को पार कर जाएगा। अगर आपको डिटर्मिनिस्टिक लो-लेवल ब्राउज़र ऑटोमेशन (जैसे Playwright) चाहिए, तो अन्य MCP सर्वर देखें। WebBrain ऑपरेशनों को एक्सटेंशन के अनुमति मॉडल के अंदर रखकर आपके साइन इन किए सेशन की रक्षा करता है।

संरचित JSON माँगें

आम उपयोग में, बताएँ क्या निकालना है और चाहिए वाले फ़ील्डों के नाम लें: "WebBrain से खुले डैशबोर्ड से सभी बकाया इनवॉइस निकालो और ग्राहक, राशि, मुद्रा, देय तिथि और इनवॉइस URL वाला JSON लौटाओ।" सक्षम MCP क्लाइंट इन फ़ील्डों को ज़रूरी schema में बदलकर आपके लिए webbrain_extract कॉल कर सकता है।

नीचे दिया गया फ़ंक्शन-रूप उदाहरण क्लाइंट डेवलपर्स और डीबगिंग के लिए बराबर टूल कॉल दिखाता है। task में चयन तर्क बताएँ; सिर्फ़ आउटपुट का रूप output_schema में बताएँ।

webbrain_extract(
  task: "extract every overdue invoice visible in this account; preserve the displayed currency and use ISO dates where the page provides a full date",
  output_schema: {
    type: "object",
    properties: {
      invoices: {
        type: "array",
        items: {
          type: "object",
          properties: {
            customer: { type: "string" },
            amount: { type: "number" },
            currency: { type: "string" },
            due_date: { type: "string" },
            invoice_url: { type: "string" }
          },
          required: ["customer", "amount", "currency", "due_date"]
        }
      }
    },
    required: ["invoices"]
  }
)
  • स्पष्ट properties और required फ़ील्ड वाले ऑब्जेक्ट रूट का उपयोग करें।
  • जितना कम डेटा चाहिए उतना ही माँगें। Schema उस डेटा तक पहुँच नहीं देता जो ब्राउज़र सेशन को दिखता ही नहीं।
  • यह टूल केवल-पढ़ने वाला है, पर पेज का टेक्स्ट और परिणाम फिर भी WebBrain के सेट LLM प्रदाता तक जाते हैं।
  • अगर परिणाम रन के स्थायी स्नैपशॉट के लिए बहुत बड़ा है, तो स्थिति रिपोर्ट कर सकती है कि सहेजा गया परिणाम कट गया। अनुरोध छोटा करें और दोबारा चलाएँ।

रन लाइफसाइकल समझें

ज़्यादातर MCP क्लाइंट यह लाइफसाइकल आपके लिए संभालते हैं: वे परिणाम का इंतज़ार करते हैं, जब मानव इनपुट चाहिए तब WebBrain का स्पष्टीकरण सवाल दिखाते हैं, और आपके जवाब से आगे बढ़ते हैं। नीचे दिए स्पष्ट कॉल क्लाइंट डेवलपर्स, समस्या निवारण, या जानबूझकर क्लाइंट से लंबा टास्क बैकग्राउंड में शुरू करवाने के लिए उपयोगी हैं।

फ़ोरग्राउंड कॉल डिफ़ॉल्ट रूप से इंतज़ार करते हैं। लंबे काम के लिए क्लाइंट wait: false सेट करके webbrain_status से पोल कर सकता है।

webbrain_run(task: "compare the invoices across all visible pages", mode: "ask", wait: false)

# लौटे ID को बार-बार चेक करें
webbrain_status(run_id: "mcp_…")

WebBrain रन का टाइमआउट नियंत्रण MCP क्लाइंट को लौटा देता है, पर जानबूझकर ब्राउज़र टास्क को रोकता नहीं है। लौटे run_id को पोल करें। इससे बचाव होता है कि टाइमआउट किसी ऐसे टास्क को चुपचाप न मार दे जो शायद पहले ही महत्वपूर्ण ऑपरेशन कर चुका हो।

जब WebBrain सवाल पूछे

रुका हुआ स्नैपशॉट इंसानी भाषा का सवाल और clarify_id दोनों रखता है। वह सवाल उपयोगकर्ता को दिखाएँ। उनका जवाब शब्दशः भेजें; अनुमान न लगाएँ।

webbrain_respond(
  run_id: "mcp_…",
  clarify_id: "clarify_…",
  answer: "Use the Acme EU account."
)

सबसे छोटी अनुमति चुनें

विकल्पक्या की अनुमतिकब उपयोग करें
mode: "ask"पढ़ना, सारांश, तुलना और एक्सट्रैक्ट। कोई पेज इंटरैक्शन नहीं।आपको सिर्फ़ जानकारी चाहिए। यह डिफ़ॉल्ट विकल्प है।
mode: "act"WebBrain के अनुमति गेट से नेविगेशन, क्लिक, टाइपिंग, डाउनलोड और फ़ॉर्म इंटरैक्शन।परिणाम के लिए दृश्यमान ब्राउज़र ऑपरेशन ज़रूरी हैं।
allow_api_mutations: trueAct रन को UI रास्ता अनुपयुक्त होने पर बदलाव करने वाले HTTP रिक्वेस्ट की अनुमति देता है।दुर्लभ, स्पष्ट अपवाद। Ask मोड में अस्वीकार होता है, और डिफ़ॉल्ट में बंद रहना चाहिए।

MCP क्लाइंट का अनुमोदन और WebBrain का अनुमोदन अलग-अलग स्तर हैं। आपका क्लाइंट webbrain_run कॉल करने से पहले पूछ सकता है; WebBrain किसी सोर्स पर महत्वपूर्ण ऑपरेशन से पहले पूछ सकता है। एक अनुमोदन दूसरे की जगह नहीं लेता।

सुरक्षा सीमाएँ जो आपको बनाए रखनी चाहिए

  • लिस्टनर को लोकल रखें।यह 127.0.0.1 से बँधा है। पोर्ट 17374 फ़ॉरवर्ड न करें, कंटेनर ब्रिज से पब्लिश न करें, या प्रॉक्सी के ज़रिए नेटवर्क पर न ले जाएँ।
  • पेयरिंग की को सुरक्षित रखें।लोकल लूपबैक अपने आप में प्रमाणीकरण नहीं है, इसलिए सर्वर सॉकेट पर तभी भरोसा करता है जब वह पेयरिंग की से कुंजीपटल वाले HMAC से एक बार की चुनौती का जवाब दे; कुंजी स्वयं कभी सॉकेट से नहीं गुज़रती। ~/.webbrain/bridge-key पढ़ने वाला कोई भी व्यक्ति पेयर कर सकता है, इसलिए कुंजी चैट में न चिपकाएँ। एक्सटेंशन सर्वर की पहचान जाँचता नहीं, इसलिए लोकल कोड और MCP पैकेजों को फिर भी भरोसेमंद सॉफ़्टवेयर मानें।
  • पहले Ask उपयोग करें।केवल-पढ़ने वाला काम जाँचने में आसान है और उसका असर-दायरा छोटा होता है।
  • Act मोड में ब्राउज़र दृश्यमान रखें।आप साइडबार में रन रोक सकते हैं, और अप्रत्याशित नेविगेशन या टाइपिंग को रोकने का कारण मानना चाहिए।
  • प्रदाता सीमा याद रखें।MCP ब्रिज लोकल रहता है, पर पेज की सामग्री WebBrain में सेट मॉडल प्रदाता तक जाती है। जब सामग्री डिवाइस पर ही रहनी हो, लोकल मॉडल उपयोग करें।
  • टाइमआउट को रॉलबैक न समझें।अबॉर्ट आगे के स्टेप्स रोकता है; भेजी गई ईमेल, सबमिट किए फ़ॉर्म, खरीद या अन्य पूर्ण ऑपरेशन उसे वापस नहीं कर सकते।

पूरा डिज़ाइन देखने के लिए सुरक्षा मॉडल, गोपनीयता और डेटा प्रवाह, और मोड, सुरक्षा और गोपनीयता गाइड देखें।

लक्षण के अनुसार समस्या निवारण

लक्षणआमतौर पर इसका मतलबउपाय
कनेक्शन त्रुटि: WebSocket त्रुटिसेट किए URL पर कोई प्रोसेस नहीं सुन रहा।MCP क्लाइंट चालू या रीस्टार्ट करें, पोर्ट 17374 की पुष्टि करें, और सर्वर प्रोसेस चलता रखें।
webbrain_connection असंयुक्त रिपोर्ट करता हैलोकल सर्वर मौजूद है, पर एक्सटेंशन ने हैंडशेक पूरा नहीं किया।Chromium ब्राउज़र उपयोग करें, क्लाउड ब्रिज चालू करें, और सटीक /extension URL सेट करें।
EADDRINUSE या सर्वर तुरंत बंद हो जाएदूसरा MCP क्लाइंट या मैनुअल सर्वर पोर्ट 17374 पहले ही थामे हुए है।दूसरा प्रोसेस रोकें। एक समय में केवल एक WebBrain MCP सर्वर डिफ़ॉल्ट पोर्ट घेर सकता है।
MCP टूल नहीं दिखतेक्लाइंट ने सेटअप दोबारा लोड नहीं किया या npm प्रोसेस शुरू नहीं हो सका।क्लाइंट रीस्टार्ट करें, उसकी MCP सर्वर सूची/लॉग देखें, और Node 20+ तथा npm पहुँच की पुष्टि करें।
टूल running लौटाता हैसर्वर या क्लाइंट का इंतज़ार बजट खत्म हो गया; ब्राउज़र रन को जानबूझकर ज़िंदा रखा गया।लौटे ID से webbrain_status पोल करें, या आगे के लंबे टास्क wait: false से शुरू करें।
रन needs_user_input दिखाता हैआगे बढ़ने के लिए WebBrain को मानव निर्णय चाहिए।सटीक सवाल पहुँचाएँ, फिर मिलते-जुलते IDs से webbrain_respond कॉल करें।
Firefox कभी नहीं जुड़ताFirefox में ऑफ़स्क्रीन-डॉक्यूमेंट ब्रिज रनटाइम नहीं है।MCP के लिए Chrome, Edge, Brave, Opera या Vivaldi उपयोग करें। Firefox सीधी साइडबार उपयोग के लिए समर्थित रहता है।
WebBrain Cloud या LM Studio डिस्कनेक्ट हो गएMCP URL ने एक्सटेंशन के एकमात्र ब्रिज गंतव्य की जगह ले ली।काम पूरा होने पर सेटिंग्स को पोर्ट 17373 (Cloud) या 17375 (LM Studio) पर वापस मोड़ें।

संबंधित इंटीग्रेशन

LM Studio उपयोग कर रहे हैं?

LM Studio अलग WebBrain Web Tools प्लगइन उपयोग करता है, इस MCP पैकेज को नहीं। उसके fetch_url और research_url टूल ब्राउज़र एक्सटेंशन के बिना सार्वजनिक पेज पढ़ सकते हैं; उसके ब्राउज़र टूल पोर्ट 17375 से लक्ष्य आपके साइन इन किए Chromium सेशन को सौंप सकते हैं।

एक ब्रिज गंतव्य चुनें

सिर्फ़ पब्लिश किए प्लगइन के उपयोग के लिए LM Studio के अंदर @webbrain/mcp-server रजिस्टर न करें। LM Studio प्लगइन गाइड देखें, और जब यह इंटीग्रेशन चाहिए तो एक्सटेंशन के क्लाउड ब्रिज URL को MCP पोर्ट 17374 से प्लगइन पोर्ट 17375 पर बदलें।

ये सर्वर जानबूझकर क्या नहीं करता

  • यह हेडलेस ब्राउज़र नहीं चलाता और न ही बिल्कुल नया ब्राउज़र प्रोफ़ाइल बनाता है।
  • यह Firefox बिल्ड से काम नहीं करता।
  • यह Cookie, क्रेडेंशियल या सेशन स्टोरेज एक्सपोर्ट नहीं करता।
  • यह WebBrain के लगभग पचास क्लिक, टाइपिंग, फ़्रेम, स्क्रीनशॉट, नेटवर्क और DOM प्राइमेटिव्स को सीधे MCP क्लाइंट को नहीं दिखाता।
  • यह ब्रिज को दूर से सुरक्षित रूप से उजागर नहीं करता।
  • यह WebBrain के अंदर मॉडल सेट करने की ज़रूरत खत्म नहीं करता।

अगर आपको अलग-थलग प्रोफ़ाइल में डिटर्मिनिस्टिक लो-लेवल ब्राउज़र ऑटोमेशन चाहिए, तो Playwright-शैली का MCP सर्वर ज़्यादा उपयुक्त हो सकता है। जब तय करने वाली ज़रूरत आपका पहले से साइन इन ब्राउज़र सेशन और WebBrain का ब्राउज़र-अंदर सुरक्षा मॉडल हो, तब WebBrain MCP उपयोग करें।
