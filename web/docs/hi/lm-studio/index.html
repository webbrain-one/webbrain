LM Studio मॉडल को वेब तक पहुंचने के दो तरीके दें।

WebBrain Web Tools किसी भी tool-capable LM Studio चैट में पब्लिक URL पढ़ने की सुविधा जोड़ता है। WebBrain एक्सटेंशन जोड़ने पर, यही प्लगइन आपके साइन-इन किए हुए Chromium प्रोफ़ाइल में भी लक्ष्य सौंप सकता है।

यह प्लगइन है, MCP सेटअप नहीं

LM Studio Hub से webbrain/web-tools इंस्टॉल करें। इस रास्ते के लिए @webbrain/mcp-server रजिस्टर न करें और MCP पोर्ट 17374 का उपयोग न करें; LM Studio प्लगइन का ब्राउज़र डीलिगेशन पोर्ट 17375 इस्तेमाल करता है।

एक प्लगइन, दो रास्ते

मॉडल तक पहुंच सकता है क्या

LM Studio चैट मॉडलआपके प्रॉम्प्ट से टूल चुनता है
→
webbrain/web-toolsलोकल Node प्लगइन · छह टूल
→
पब्लिक URL या साइन-इन ब्राउज़रएनामस HTTP · वैकल्पिक एक्सटेंशन ब्रिज
रास्ताकिसके लिए बेहतरयह क्या नहीं कर सकता
fetch_url / research_urlपब्लिक लेख, दस्तावेज़, API, JSON, टेक्स्ट और स्टैटिक HTML।ब्राउज़र कुकीज़, JavaScript रेंडरिंग, क्लिक, टाइपिंग या ऑथेंटिकेटेड सेशन नहीं।
browser_taskसाइन-इन डैशबोर्ड, वेबमेल, क्लाइंट-रेंडर्ड ऐप्स और दिखने वाली ब्राउज़र इंटरैक्शन वाले कार्य।Chromium पर WebBrain और प्लगइन ब्रिज कनेक्शन चाहिए।

इंस्टॉल करने से पहले

आवश्यकताक्या जांचें
LM Studioमौजूदा डेस्कटॉप ऐप खोलें। इसका बंडल्ड रनटाइम इंस्टॉल किए प्लगइन्स चला सकता है; सामान्य उपयोग के लिए अलग से Node.js इंस्टॉल करना ज़रूरी नहीं।
tool-capable मॉडलऐसे मॉडल और चैट कॉन्फ़िगरेशन चुनें जो टूल कॉल कर सकें। बिना टूल वाले प्लेन-टेक्स्ट मॉडल प्लगइन को नहीं बुलाएंगे।
नेटवर्क एक्सेसदोनों HTTP टूल लोकल प्लगइन प्रोसेस से आपके मांगे हुए URL से जुड़ते हैं।
वैकल्पिक ब्राउज़र कनेक्शनbrowser_task के लिए, Chrome, Edge, Brave, Opera या Vivaldi में WebBrain इंस्टॉल करें और पोर्ट 17375 खाली रखें।
सक्रिय WebBrain प्रोवाइडरब्राउज़र कार्य WebBrain एक्सटेंशन में कॉन्फ़िगर प्रोवाइडर से ही चलते हैं।
Hub से शुरू करें

WebBrain Web Tools इंस्टॉल और सक्षम करें

  1. LM Studio खुला रखें।webbrain/web-tools Hub लिस्टिंग खोलें और Run in LM Studio चुनें। आप उसी मशीन पर नीचे दिया गया डीप लिंक भी खोल सकते हैं।
  2. चैट में प्लगइन सक्षम करें।चैट इनपुट के बगल में इंटीग्रेशन या टूल कंट्रोल खोलें और webbrain/web-tools चालू करें।
  3. tool-capable मॉडल चुनें।प्लगइन उस चैट को अपने टूल देता है; मॉडल आपके अनुरोध से तय करता है कि कब उन्हें बुलाना है।
  4. पहले पब्लिक वेब रास्ता आज़माएं।पूछें: "https://news.ycombinator.com पढ़ें और मौजूदा सुर्खियों के मुख्य विषयों का सारांश दें।" मॉडल को research_url इस्तेमाल करना चाहिए।
lmstudio://plugin?owner=webbrain&name=web-tools

CLI इंस्टॉलेशन

lms clone Hub आर्टिफैक्ट को मौजूदा डायरेक्टरी में कॉपी करता है; वह उस कॉपी को अपने आप इंस्टॉल नहीं करता। क्लोन की गई डायरेक्टरी में जाएं और lms dev का इंस्टॉल रूप चलाएं:

lms clone webbrain/web-tools
cd web-tools
lms dev --install

CLI व्यवहार के लिए LM Studio का lms clone रेफरेंस और lms dev --install रेफरेंस देखें।

छह टूल, दो ट्रस्ट सरफेस

प्लगइन मॉडल को क्या देता है

टूलकिसके लिए इस्तेमाल करेंब्राउज़र एक्सटेंशन चाहिए?
fetch_urlजाने-पहचाने HTTP(S) URL को फेच करें। JSON, HTML, प्लेन टेक्स्ट, अनुरोध हेडर और बॉडी संभालता है, और बाइनरी रिस्पॉन्स को इनलाइन करने के बजाय सारांशित करता है।नहीं
research_urlपढ़ने योग्य लेख या दस्तावेज़ टेक्स्ट निकालता है, आम नेविगेशन तत्व हटाते हुए।नहीं
browser_taskनेचुरल-लैंग्वेज Ask या Act लक्ष्य को साइन-इन ब्राउज़र में WebBrain को सौंपें।हां
browser_statusएक्सटेंशन कनेक्शन जांचें, या runId से मौजूदा रन को पोल करें।हां
browser_respondneeds_user_input पर रुके रन में उपयोगकर्ता का जवाब भेजें।हां
browser_abortचल रहे रन को रोकें। पहले हो चुकी क्रियाएं वापस नहीं होंगी।हां
लंबे पेज सिर्फ़ काटे नहीं जाते, उन्हें दबाया जाता है

जब रिज़ल्ट रिटर्न बजट से ज़्यादा हो, तो HTTP टूल शुरुआत, चुनी हुई उच्च-संकेत वाली बीच की क़िस्में और अंत रखते हैं। कॉम्पैक्ट रिज़ल्ट compacted: true बताता है और कॉम्पैक्शन मेटाडेटा शामिल करता है। जब छोड़ी गई सामग्री मायने रखती हो, तो सँकरा पेज मांगें या maxChars बढ़ाएं।

बिना ब्राउज़र पब्लिक HTTP टूल इस्तेमाल करें

जाना-पहचाना लेख पढ़ें

research_url से https://example.com/article पढ़ें और लेखक का मुख्य तर्क, समर्थन में सबूत और बताई गई सीमाएं दें।

API रिस्पॉन्स जांचें

fetch_url से https://api.example.com/status पढ़ें। HTTP स्टेटस और सेवा की सेहत बताते फ़ील्ड लौटाएं।

research_url आमतौर पर लेख की सामग्री के लिए बेहतर विकल्प है। जब रिस्पॉन्स का प्रकार, JSON संरचना, हेडर, मेथड या बॉडी मायने रखता हो, तो fetch_url इस्तेमाल करें।

URL फेच ब्राउज़र टैब नहीं है

ये अनुरोध एनामस हैं और पेज का JavaScript नहीं चलाते। अगर रिज़ल्ट spaSuspected: true बताए, या पेज लॉगिन मांगे, तो HTTP रास्ता दोहराना बंद करें और एक्सटेंशन जोड़ने के बाद browser_task इस्तेमाल करें।

वैकल्पिक साइन-इन रास्ता

अपने इस्तेमाल वाले ब्राउज़र से जोड़ें

  1. Chromium ब्राउज़र में WebBrain इंस्टॉल करें।ब्रिज Chrome, Edge, Brave, Opera और Vivaldi में काम करता है। Firefox यह कनेक्शन नहीं संभाल सकता।
  2. LM Studio में webbrain/web-tools सक्षम करें।प्लगइन इनिशियलाइज़ होते ही अपना लोकल लूपबैक लिस्टनर खोल लेता है।
  3. WebBrain सेटिंग्स खोलें।Settings → Bridge पर जाएं।
  4. प्लगइन URL और पेयरिंग की सेट करें।ws://127.0.0.1:17375/extension दर्ज करें, ~/.webbrain/bridge-key (प्लगइन शुरू होते ही बनता है, MCP सर्वर भी यही की इस्तेमाल करता है) की की Pairing key फ़ील्ड में पेस्ट करें, फिर क्लाउड ब्रिज चालू करें।
  5. पूरी पाथ की जांच करें।LM Studio मॉडल से browser_status कॉल करने को कहें। कनेक्टेड रिज़ल्ट साबित करता है कि प्लगइन लिस्टनर और एक्सटेंशन हैंडशेक दोनों तैयार हैं।
एक समय में एक ही ब्रिज गंतव्य

एक्सटेंशन का केवल एक आउटबाउंड ब्रिज सॉकेट है। पोर्ट 17375 इसे इस प्लगइन से जोड़ता है, पोर्ट 17374 MCP सर्वर से और पोर्ट 17373 WebBrain Cloud से। URL बदलने से गंतव्य बदलता है, वे आपस में नहीं जुड़ते।

दो मॉडल शामिल हो सकते हैं

LM Studio चैट मॉडल तय करता है कि browser_task कॉल करना है और रिज़ल्ट पाता है। WebBrain एक्सटेंशन WebBrain में कॉन्फ़िगर सक्रिय प्रोवाइडर से सौंपा गया ब्राउज़र रन चलाता है। अगर पेज की सामग्री डिवाइस पर ही रहनी हो, तो उस WebBrain प्रोवाइडर को भी लोकल मॉडल इस्तेमाल करने पर सेट करें।

पेज बदले बिना पढ़ें

Ask मोड में browser_task से मेरे ब्राउज़र में पहले से खुला अकाउंट डैशबोर्ड पढ़ें और हाल के पांच अलर्ट सूचीबद्ध करें। कुछ भी न बदलें।

अनुमति गेट के साथ इंटरैक्ट करें

Act मोड में browser_task से मेरे ब्राउज़र में दिख रहे ड्राफ्ट को खोलें और कंपनी का नाम Acme Europe अपडेट करें। किसी अंतिम सबमिट या कन्फ़र्म से पहले रुकें।

चल रहे ब्राउज़र रन को चलने दें

browser_task रिज़ल्ट का इंतज़ार करता है, पर उसका टाइमआउट एक्सटेंशन में पहले से चल रहे काम को रद्द नहीं करता। लौटा हुआ runId संभालें और स्थिति के अनुसार रिकवरी टूल इस्तेमाल करें।

runningbrowser_status से पोल करें
needs_user_inputपूछें, फिर browser_respond इस्तेमाल करें
completedरिज़ल्ट तैयार है
failedएरर और सबूत देखें
abortedरुक गया; पहले की क्रियाएं बरकरार
  • टाइमआउट के बाद दोहरा browser_task न चलाएं; मौजूदा रन को पोल करें।
  • WebBrain के स्पष्टीकरण वाले सवालों का जवाब कभी गढ़ें नहीं। उपयोगकर्ता से पूछें और उनका जवाब शब्दशः आगे भेजें।
  • browser_abort आगे के कदम रोकता है। यह सबमिट किए फॉर्म, भेजे संदेश या पूरी हुई अन्य क्रियाओं को वापस नहीं कर सकता।

दोनों ट्रस्ट सरफेस को साफ़ रखें

  • पब्लिक HTTP लोकल प्लगइन प्रोसेस में चलता है।fetch_url मेथड, हेडर और बॉडी भेज सकता है, इसलिए बदलाव का अनुरोध तभी करें जब आप बदलाव चाहते हों।
  • प्राइवेट नेटवर्क टारगेट डिफ़ॉल्ट रूप से ब्लॉक होते हैं।लूपबैक, RFC1918, लिंक-लोकल, क्लाउड मेटाडेटा और आम इनट्रानेट होस्टनेम अस्वीकार होते हैं। localhost या LAN तक पहुंचने के लिए, सिर्फ़ ज़रूरत वाली चैट में, LM Studio के प्लगइन सेटिंग्स में Allow private network access चालू करें। मॉडल खुद इसे चालू नहीं कर सकता, और चालू होने पर भी क्लाउड मेटाडेटा एंडपॉइंट ब्लॉक रहेंगे।
  • रिडायरेक्ट दोबारा जांचे जाते हैं।प्लगइन हर गंतव्य सत्यापित करता है और डोमेन-पार रिडायरेक्ट पर क्रेडेंशियल जैसे हेडर हटा देता है।
  • ब्राउज़र लिस्टनर लूपबैक पर ही रहता है।पोर्ट 17375 को कभी फॉरवर्ड या प्रॉक्सी न करें। एक्सटेंशन हैंडशेक क्लाइंट को पहचानता है पर शेयर्ड-सीक्रेट ऑथेंटिकेशन नहीं है; लोकल सॉफ्टवेयर को भरोसेमंद मानें।
  • Ask मोड डिफ़ॉल्ट है।Act तभी इस्तेमाल करें जब मांगे नतीजे के लिए दिखने वाली ब्राउज़र इंटरैक्शन ज़रूरी हो, और ब्राउज़र ऐसी जगह रखें जहां आप अनचाहा व्यवहार रोक सकें।
  • LM Studio मॉडल टूल रिज़ल्ट देखता है।ब्राउज़र रन WebBrain में कॉन्फ़िगर सक्रिय प्रोवाइडर से कार्य संदर्भ भी भेजता है। दोनों मॉडलों की सीमाएं सोच-समझकर चुनें।

इम्प्लीमेंेशन-लेवल विवरणों के लिए (इसमें यह भी कि हर कनेक्शन जांची गई पते पर कैसे फिक्स होता है), प्लगइन के सुरक्षा नोट्स पढ़ें।

लक्षण के हिसाब से समस्या-निदान

लक्षणआमतौर पर इसका मतलबउपाय
टूल नहीं दिखतेइस चैट में प्लगइन सक्षम नहीं है, या चुना मॉडल टूल कॉल नहीं कर सकता।चैट इनपुट के बगल में webbrain/web-tools चालू करें और tool-capable मॉडल चुनें।
browser_status डिस्कनेक्टेड बताता हैप्लगइन मौजूद है, पर WebBrain एक्सटेंशन अभी जुड़ा नहीं।Chromium इस्तेमाल करें, क्लाउड ब्रिज चालू करें, और ठीक ws://127.0.0.1:17375/extension दर्ज करें।
लिस्टनर नहीं चलता या एड्रेस टक्कर बताता हैदूसरा प्लगइन इंस्टेंस या प्रोसेस पहले से पोर्ट 17375 पकड़े हुए है।डुप्लिकेट इंस्टेंस बंद करें, फिर प्लगइन रीलोड करें। पहले lsof -nP -iTCP:17375 -sTCP:LISTEN से जांचें।
पब्लिक पेज खाली हैपेज JavaScript से रेंडर होता है या सामग्री लॉगिन के पीछे छिपी है।अगर spaSuspected true है, एक्सटेंशन जोड़ें और browser_task इस्तेमाल करें।
कार्य टाइमआउट हो गया पर ब्राउज़र अभी भी काम कर रहा हैइंतज़ार का बजट खत्म हुआ, पर WebBrain रन रद्द नहीं हुआ।लौटे हुए runId से browser_status कॉल करें, या रोकने के लिए browser_abort इस्तेमाल करें।
Firefox कभी नहीं जुड़ताFirefox में ऑफस्क्रीन-डॉक्युमेंट ब्रिज रनटाइम नहीं है।ब्राउज़र टूल के लिए Chromium ब्राउज़र इस्तेमाल करें। दोनों पब्लिक HTTP टूल बिना एक्सटेंशन के चलते रहते हैं।
MCP या WebBrain Cloud डिस्कनेक्ट हो गयाLM Studio URL ने एक्सटेंशन के एकमात्र ब्रिज गंतव्य को बदल दिया।काम पूरा होने पर सेटिंग्स पोर्ट 17374 (MCP) या 17373 (WebBrain Cloud) पर वापस कर दें।
