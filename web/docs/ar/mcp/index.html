جلسة حقيقية وتحكم على مستوى المهام

دع وكيل البرمجة لديك يستخدم المتصفح الذي سجّلت الدخول إليه بالفعل.

يربط WebBrain MCP عملاء stdio MCP مثل Codex وClaude Code وCursor وOpenClaw وOpenCode وغيرهم بملفك الحقيقي في Chromium. بعد إعداد لمرة واحدة، صِف مهمة المتصفح بلغة طبيعية فقط. يختار وكيل البرمجة لديك أدوات WebBrain المناسبة ويستدعيها؛ وينفّذ WebBrain الهدف داخل المتصفح مستخدمًا الأوضاع نفسها وأذونات الأصول وعناصر التوقف المرئية الموجودة في الشريط الجانبي.

لا تحتاج إلى إدخال استدعاءات دوال MCP يدويًا

قُل «استخدم WebBrain لتلخيص لوحة المعلومات المفتوحة في متصفحي» أو «استخدم وضع Act في WebBrain لتحديث هذا النموذج». يحوّل عميل MCP لديك هذا الطلب إلى استدعاءات أدوات ويعيد النتيجة في المحادثة نفسها. الأمثلة المعروضة لاحقًا بصيغة الدوال مخصصة أساسًا لتصحيح الأخطاء أو لمطوري العملاء.

Chromium فقط

يتطلب الجسر مستند خارج الشاشة في الامتداد، لذا استخدم Chrome أو Edge أو Brave أو Opera أو Vivaldi. يمكن استخدام امتداد Firefox بشكل مستقل، لكنه لا يستطيع الاتصال بخادم MCP هذا.

المسار الكامل

ما الذي يبدأ أين

يشغّل عميل MCP لديك حزمة npm كعملية فرعية محلية عبر stdio. تستمع هذه العملية فقط على 127.0.0.1:17374. يتصل بها الامتداد ثم ينفّذ كل مهمة عبر حلقة الوكيل في WebBrain ضمن تبويب المتصفح المحدد.

الخطوة 1 · مرة واحدة فقط

سجّل الخادم لدى عميل MCP لديك

استخدم إحدى تهيئة العملاء المحددة أدناه، مرة واحدة فقط. هذه أوامر تثبيت، وليست الطريقة التي تطلب بها مهام المتصفح. بعد التسجيل يشغّل العميل الخادم نيابةً عنك وتواصل المحادثة كالمعتاد؛ لا تشغّل نسخة يدوية موازية على المنفذ نفسه.

تطبيق Codex أو CLI أو امتداد IDE

codex mcp add webbrain -- npx -y @webbrain/mcp-server

يخزّن Codex خوادم MCP في ~/.codex/config.toml؛ ويتشارك التطبيق وCLI وامتداد IDE على المضيف نفسه هذه التهيئة. للمهام الطويلة في المتصفح، افتح الملف ومنحِ الأداة وقتًا يتجاوز ميزانية Codex الافتراضية لكل استدعاء:

[mcp_servers.webbrain]
command = "npx"
args = ["-y", "@webbrain/mcp-server"]
tool_timeout_sec = 360

أعد تشغيل التطبيق أو امتداد IDE بعد تعديل الملف. في CLI، شغّل codex mcp list للتأكد من الإدخال واستخدم /mcp داخل جلسة Codex لفحص الخادم المتصل. راجع دليل Codex MCP الرسمي لمعرفة تهيئة المضيف المشترك وجميع الخيارات المدعومة.

Claude Code

claude mcp add --transport stdio webbrain -- npx -y @webbrain/mcp-server

تتطابق وسيلة النقل الصريحة مع تهيئة MCP الحالية في Claude Code. بعد الإضافة، شغّل claude mcp list للتحقق من صحة الخادم.

Cursor

أضف خادم stdio محليًا في إعدادات MCP في Cursor، أو ضع هذا المحتوى في ملف JSON الخاص بـ MCP الذي يستخدمه Cursor. يتبع التنسيق تنسيق خوادم MCP المحلية في Cursor:

{
  "mcpServers": {
    "webbrain": {
      "command": "npx",
      "args": ["-y", "@webbrain/mcp-server"]
    }
  }
}

OpenCode

أضف هذا الإدخال إلى ملف ~/.config/opencode/opencode.json باستخدام تنسيق خوادم MCP المحلية في OpenCode:

{
  "mcp": {
    "webbrain": {
      "type": "local",
      "command": ["npx", "-y", "@webbrain/mcp-server"]
    }
  }
}

OpenClaw

سجّل WebBrain في OpenClaw كخادم MCP صادر. لا تستخدم openclaw mcp serve لهذا التكامل: فهذا الأمر يجعل OpenClaw نفسه يعمل كخادم، أي باتجاه معاكس.

openclaw mcp add webbrain \
  --command npx \
  --arg -y \
  --arg @webbrain/mcp-server \
  --timeout 360

يستكشف mcp add خادم stdio قبل حفظه. شغّل openclaw mcp status --verbose لفحص التعريف المحفوظ. تتضمن ملفات الأدوات العادية coding وmessaging خوادم MCP المُهيَّأة؛ وقد يخفيها ملف minimal أو رفض صريح لـ bundle-mcp أو سياسة أدوات في بيئة معزولة. راجع دليل MCP في OpenClaw لمعرفة تفاصيل السجل والسياسات الحالية.

التشغيل اليدوي

التشغيل اليدوي مفيد لتشخيص المستمع، لكنه غير ضروري في الاستخدام العادي لـ MCP:

npx -y @webbrain/mcp-server

اترك تلك الطرفية مفتوحة. إغلاقها يوقف مستمع الجسر. من نسخة الشيفرة المصدرية، شغّل npm install ثم npm run build ثم npm start داخل mcp-server/.

الخطوة 2

وجّه WebBrain إلى المستمع المحلي

  1. شغّل عميل MCP لديك أو أعد تشغيله. يجب أن يعمل خادم WebBrain الخاص به قبل أن يتمكن الامتداد من الاتصال.
  2. افتح إعدادات WebBrain. انتقل إلى الإعدادات ← Bridge.
  3. حدّد الرابط بدقة. أدخل ws://127.0.0.1:17374/extension.
  4. الصق مفتاح الاقتران. شغّل npx -y @webbrain/mcp-server pairing-key في طرفية (أو افتح ~/.webbrain/bridge-key) والصق المفتاح في حقل مفتاح الاقتران. لا يثق الخادم إلا بمتصفح يثبت أنه يحمل هذا المفتاح. إذا غاب الحقل، فحدّث WebBrain أولًا.
  5. فعّل الجسر السحابي. يجب أن تتغير الحالة من «جارٍ الاتصال» إلى «متصل». التسمية لأسباب تاريخية: هذا الهدف محلي.
  6. تحقق من الاتصال من طرف إلى طرف. اطلب من عميل MCP استدعاء webbrain_connection. كلمة «Connected» تثبت أن العميل والخادم المحلي ومستمع WebSocket ومصافحة الامتداد جاهزة.
وجهة جسر واحدة في كل مرة

يحتفظ الامتداد بمقبس جسر صادر واحد: WebBrain Cloud على 17373، أو خادم MCP هذا على 17374، أو إضافة LM Studio على 17375. تغيير الرابط يبدّل الوجهة ولا يجمع بينها في قناة واحدة.

الخطوة 3 · اسأل مباشرة

صِف مهمة المتصفح بلغة طبيعية

اكتب الطلب في Codex أو Claude Code أو Cursor أو OpenClaw أو OpenCode كما لو كنت تكلّف زميلًا بمهمة. ذكر WebBrain يجعل قصتك واضحة لا لبس فيها؛ ضمّن الصفحة والنتيجة المتوقعة والنطاق وما إذا كانت التغييرات مسموحة.

قراءة دون تغيير الصفحة

استخدم WebBrain لقراءة لوحة معلومات Stripe المفتوحة بالفعل في متصفحي. ادرج المدفوعات الفاشلة خلال الأيام السبعة الماضية مع العميل والمبلغ والعملة والتاريخ وسبب الفشل. لا تغيّر أي شيء.

إرجاع JSON قابل للتنبؤ

استخدم WebBrain لاستخراج جميع الفواتير المتأخرة من لوحة المعلومات المفتوحة في متصفحي. أعد JSON يتضمن العميل والمبلغ والعملة وتاريخ الاستحقاق ورابط الفاتورة. لا تغيّر أي شيء.

التفاعل مع الصفحة

استخدم وضع Act في WebBrain لفتح سجل العميل المعروض بالفعل في متصفحي وحدّث اسم الشركة إلى Acme Europe. توقف قبل أي إرسال أو تأكيد نهائي.

يختار وكيل البرمجة webbrain_run للقراءة أو التفاعل العامين، ويختار webbrain_extract عند طلب بيانات مهيكلة. وهو يزوّد الوسائط ويراقب التشغيل ويعرض نتيجة WebBrain في المحادثة. يستطيع وضع Ask القراءة والاستخراج، لكنه لا يستطيع النقر أو الكتابة أو التنقل أو الإرسال. يستطيع وضع Act التفاعل، وفق أذونات WebBrain المعتادة في المتصفح.

التفاصيل الداخلية — لا تحتاج إلى إدخالها

بالنسبة لأول مطالبة أعلاه، سيجري العميل استدعاءً مشابهًا لهذا. هذا التمثيل مفيد عند بناء عملاء MCP أو تصحيحها، ويمكن للمستخدم العادي تجاهله.

webbrain_run(
  task: "read the open Stripe dashboard and list failed payments from the last 7 days with customer, amount, currency, date, and failure reason",
  mode: "ask"
)

للمهام التي تتطلب تفاعلًا، قل صراحةً «استخدم وضع Act في WebBrain» وأبقِ المتصفح مرئيًا. سيطبّق WebBrain رسائل الموافقة المعتادة لكل قدرة ولكل أصل.

ست أدوات وحدّ ثقة واحد

الأدوات التي يستخدمها عميل MCP نيابةً عنك

تختار عادةً النتيجة لا الأداة. يقرأ عميل MCP هذه الأوصاف، ويختار الأداة المناسبة، ويملأ مدخلاتها وفق طلبك، ويتعامل مع الاستدعاءات اللاحقة. وهذا المرجع يساعدك على فهم هذا السلوك أو تصحيحه.

الأداةالاستخدامالمدخلات المهمة
webbrain_runأي هدف في المتصفح، للقراءة فقط أو تفاعلي.task وmode واختياريًا tab_id وwait وtimeout_seconds، إضافة إلى allow_api_mutations الخاص بوضع Act فقط.
webbrain_extractJSON قابل للتنبؤ مستخرج من بيانات صفحات موثَّقة. يكون دائمًا في وضع Ask.task وoutput_schema واختياريًا tab_id وwait وtimeout_seconds.
webbrain_statusاستطلاع تشغيل جارٍ في الخلفية أو إدراج جميع التشغيلات المعروفة.run_id اختياري. احذفه لإدراج التشغيلات.
webbrain_respondإيصال إجابة المستخدم إلى تشغيل متوقف مؤقتًا.run_id وclarify_id وanswer واختياريًا timeout_seconds.
webbrain_abortإيقاف تشغيل خاطئ أو لم يعد مطلوبًا.run_id. لا يتراجع عن الإجراءات المنفَّذة بالفعل.
webbrain_connectionفحص مصافحة الامتداد والحصول على إصلاح موجَّه عند انقطاع الاتصال.لا مدخلات.
لماذا لا توجد أداة نقر أو كتابة في MCP

تقع فحوص الأذونات في WebBrain داخل حلقة الوكيل في الامتداد. ولو عُرضت البدائيات منخفضة المستوى مباشرة عبر MCP لتجاوزت تلك الحدود. إذا احتجت إلى أتمتة متصفح حتمية منخفضة المستوى (مثل Playwright) ففكر في خوادم MCP أخرى. يحمي WebBrain جلستك المسجَّل الدخول إليها بإبقاء الإجراءات داخل نموذج أذونات الامتداد.

اطلب JSON مهيكلًا

في الاستخدام العادي، قل ما الذي تريد استخراجه وسمِّ الحقول المطلوبة: «استخرج جميع الفواتير المتأخرة من لوحة المعلومات المفتوحة باستخدام WebBrain، وأعد JSON يتضمن العميل والمبلغ والعملة وتاريخ الاستحقاق ورابط الفاتورة». ويستطيع عميل MCP قادر ترجمة هذه الحقول إلى المخطط المطلوب واستدعاء webbrain_extract نيابةً عنك.

يوضح المثال بصيغة الدالة أدناه استدعاء الأداة المكافئ لمطوري العملاء ولأغراض التصحيح. صِف منطق الاختيار في task، واكتب شكل المخرجات في output_schema فقط.

webbrain_extract(
  task: "extract every overdue invoice visible in this account; preserve the displayed currency and use ISO dates where the page provides a full date",
  output_schema: {
    type: "object",
    properties: {
      invoices: {
        type: "array",
        items: {
          type: "object",
          properties: {
            customer: { type: "string" },
            amount: { type: "number" },
            currency: { type: "string" },
            due_date: { type: "string" },
            invoice_url: { type: "string" }
          },
          required: ["customer", "amount", "currency", "due_date"]
        }
      }
    },
    required: ["invoices"]
  }
)
  • استخدم جذر كائن مع حقلَي properties وrequired صريحين.
  • اطلب أضيق البيانات التي تحتاجها. لا يمنح المخطط صلاحية الوصول إلى بيانات لا تراها جلسة المتصفح.
  • الأداة للقراءة فقط، لكن نص الصفحة والنتيجة يُرسلان مع ذلك إلى مزوّد نماذج اللغة الكبير المهيَّأ في WebBrain.
  • إذا كانت النتيجة أكبر من اللقطة المخزَّنة للتشغيل، فقد يفيد الحالة بأن النتيجة المخزَّنة بُترت. قلّل الطلب وأعد المحاولة.

افهم دورة حياة التشغيل

يدير معظم عملاء MCP هذه الدورة نيابةً عنك: فهم ينتظرون النتيجة، ويعرضون سؤال التوضيح من WebBrain عند الحاجة إلى تدخل بشري، ثم يواصلون بإجابتك. الاستدعاءات الصريحة أدناه مفيدة لمطوري العملاء أو لاستكشاف الأخطاء أو عند الرغبة في تشغيل مهمة طويلة في الخلفية عمدًا.

تنتظر الاستدعاءات في المقدمة بشكل افتراضي. وللأعمال الطويلة يمكن للعميل ضبط wait: false والاستطلاع باستخدام webbrain_status.

runningيستمر العمل في المتصفح
needs_user_inputمرّر السؤال إلى المستخدم
completedالنتيجة جاهزة
failedاطّلع على الخطأ والأدلة
abortedمتوقف؛ والإجراءات السابقة ما زالت سارية
# مرجع على مستوى الأداة
# البدء دون انتظار
webbrain_run(task: "compare the invoices across all visible pages", mode: "ask", wait: false)

# استطلاع المعرّف المُعاد
webbrain_status(run_id: "mcp_…")

يُعيد انتهاء مهلة تشغيل WebBrain التحكم إلى عميل MCP، لكنه لا يُجهض مهمة المتصفح عن قصد. استطلع المعرّف run_id المُعاد. وهذا يمنع أن ينهي انقضاء المهلة مهمةً قد تكون اتخذت إجراءً مهمًا بالفعل.

عندما يطرح WebBrain سؤالًا

تتضمن اللقطة المتوقفة سؤالًا مقروءًا للبشر ومعرف clarify_id. اعرض السؤال على المستخدم. وأرسل إجابته حرفيًا؛ لا تستنتجها.

webbrain_respond(
  run_id: "mcp_…",
  clarify_id: "clarify_…",
  answer: "Use the Acme EU account."
)

اختر أقل صلاحية كافية

الخيارالإجراءات المسموحةمتى يُستخدم
mode: "ask"القراءة والتلخيص والمقارنة والاستخراج. دون تفاعل مع الصفحة.عندما تحتاج إلى المعلومات فقط. وهذا الخيار الافتراضي.
mode: "act"التنقل والنقر والكتابة والتنزيل والتفاعل مع النماذج عبر بوابة أذونات WebBrain.عندما تتطلب النتيجة إجراءات مرئية في المتصفح.
allow_api_mutations: trueيسمح لتشغيل Act باستخدام طلبات HTTP مُعدِّلة عندما لا يكون مسار الواجهة مناسبًا.استثناء صريح نادر. يُرفض في وضع Ask، وينبغي أن يبقى مغلقًا افتراضيًا.

موافقة عميل MCP وموافقة WebBrain طبقتان مستقلتان. قد يسأل عميلك قبل استدعاء webbrain_run، وقد يسأل WebBrain قبل إجراء مهم على أصل معين. ولا تُغني موافقة عن الأخرى.

حدود الأمان التي يجب الحفاظ عليها

  • أبقِ المستمع محليًا. إنه مرتبط بـ 127.0.0.1. لا تُحوّل المنفذ 17374 ولا تنشره عبر جسر حاويات ولا ترحّله إلى الشبكة.
  • احفظ مفتاح الاقتران بعناية. حلقة الاسترجاع وحدها ليست مصادقة؛ فلا يثق الخادم بمقبس إلا بعد أن يجيب تحديًا لمرة واحدة بـ HMAC مفتاحُه هو مفتاح الاقتران، ولا يمر المفتاح نفسه عبر المقبس أبدًا. ويستطيع أي شخص يقرأ ~/.webbrain/bridge-key أن يقترن، لذا لا تلصق المفتاح في محادثة. ولا يوثّق الامتداد هوية الخادم، لذا ما زال ينبغي اعتبار الشيفرة المحلية وحزم MCP برمجيات موثوقة.
  • استخدم وضع Ask أولًا. فالعمل للقراءة فقط أسهل للتحقق ونطاق تأثيره أصغر.
  • أبقِ المتصفح مرئيًا في وضع Act. يمكنك إيقاف التشغيل من الشريط الجانبي، وأي تنقل أو كتابة غير متوقعين يُعدّان سببًا للإيقاف.
  • تذكّر حدّ المزوّد. يبقى جسر MCP محليًا، لكن محتوى الصفحة يُرسل إلى مزوّد النموذج المهيَّأ في WebBrain. استخدم نموذجًا محليًا عندما يجب أن يبقى المحتوى على الجهاز.
  • لا تخطئ فتظن أن انتهاء المهلة تراجع عن الإجراءات. الإيقاف يوقف الخطوات اللاحقة؛ ولا يستطيع التراجع عن بريد أُرسل أو نموذج أُرسل أو عملية شراء أو أي إجراء مكتمل آخر.

للتصميم الكامل، طالع نموذج الأمان والخصوصية وتدفق البيانات ودليل الأوضاع والأمان والخصوصية.

تكامل ذو صلة

أتستخدم LM Studio؟

يستخدم LM Studio إضافة WebBrain Web Tools المنفصلة، لا حزمة MCP هذه. وتستطيع أداتا fetch_url وresearch_url فيها قراءة الصفحات العامة دون امتداد المتصفح؛ وتستطيع أدوات المتصفح فيها تفويض هدف إلى جلسة Chromium المسجَّل الدخول إليها عبر المنفذ 17375.

اختر وجهة جسر واحدة

لا تسجّل @webbrain/mcp-server داخل LM Studio لمجرد استخدام الإضافة المنشورة. راجع دليل إضافة LM Studio، ثم بدّل رابط الجسر السحابي في الامتداد من منفذ MCP 17374 إلى منفذ الإضافة 17375 عند الحاجة إلى ذلك التكامل.

ما لا يفعله هذا الخادم عن قصد

  • لا يشغّل متصفح بلا واجهة ولا ينشئ ملف تعريف متصفح جديدًا.
  • لا يعمل عبر إصدار Firefox.
  • لا يصدّر ملفات تعريف الارتباط أو بيانات الاعتماد أو تخزين الجلسات.
  • لا يعرّي نحو خمسين بدائية نقر وكتابة وإطار والتقاط شبكة وDOM في WebBrain مباشرة لعميل MCP.
  • لا يجعل الجسر آمنًا للتعريض البعيد.
  • لا يلغي الحاجة إلى نموذج مهيَّأ داخل WebBrain.

إذا احتجت إلى أتمتة متصفح حتمية منخفضة المستوى في ملف تعريف معزول، فقد يناسبك خادم MCP بأسلوب Playwright أكثر. استخدم WebBrain MCP عندما يكون الشرط الحاسم هو جلسة متصفحك المسجَّل الدخول إليها القائمة إضافةً إلى نموذج الأمان داخل المتصفح لدى WebBrain.
