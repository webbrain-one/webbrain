Docs / Mga provider at modelo
Ang modelong nasa likod ng panel

Piliin ang setup na tumutugma sa inyong pasensya, pangangailangan sa privacy, at budget.

Kasama sa WebBrain ang 114 provider card na saklaw ang mga hosted cloud service, direktang cloud API, model router, at lokal na OpenAI-compatible server. Kailangan lang ninyo ng isang aktibong provider.

Mabilis na pagpili

Pinakakaunting hakbang

WebBrain Compass

Built-in, aktibo by default, at may araw-araw na libreng allowance; walang model server o API key.

Privacy at offline capability

Lokal na modelo

Gumamit ng llama.cpp, Ollama, ODS, LM Studio, Jan, vLLM, SGLang, o LocalAI.

Direkta sa vendor

Cloud API

Ilagay ang inyong sariling key para sa OpenAI, Anthropic, Gemini, Mistral, DeepSeek, xAI, Groq, at iba pang suportadong provider.

Malawak na katalogo ng modelo

Model router

Lumipat sa maraming modelo gamit ang isang account; angkop sa madalas mag-eksperimento.

114 built-in provider card

Idinagdag ng seksyong LLM ng Mga Setting ang 79 direktang API at router, kabilang ang Azure AI Foundry, Vertex AI, Vertex Anthropic, Cerebras, Cohere, DeepInfra, Perplexity, Vercel AI Gateway, Venice, at maraming rehiyonal na coding plan. Maaaring maghanap ayon sa pangalan ng provider o modelo.

Karamihan sa mga card ay gumagamit ng API key at OpenAI-compatible endpoint. Ang mga Vertex card ay gumagamit ng Google Cloud project, rehiyon, at authorization key; ang global na rehiyon ay gumagamit ng global endpoint ng Google, at sinusuportahan din ng Vertex Anthropic ang mga multi-region host na us at eu. Tinatanggap ng Cloudflare ang opsyonal na AI Gateway ID; para sa mga @cf/ modelo, kusang ginagamit ang default gateway kapag walang nilagay. Ang mga provider na sumusuporta sa streaming ay nagpapakita ng tugon sa real time sa interactive na Ask, at kusang nagre-retry nang isang beses nang walang streaming kapag naantala ang koneksyon. Kapag ibinaon ng serbisyo ang token usage, direkta itong naitatala; kung hindi, nagtatala ang WebBrain ng maingat na pagtatantya upang hindi maikot ang streaming sa mga cost limit.

Mga hakbang sa pag-setup

  1. Buksan ang Mga Setting → Mga modelo → LLM. Pumili ng Higit pa… sa menu ng modelo ng side panel, o piliin ang LLM sa ilalim ng Mga modelo sa sidebar ng Mga Setting. Inililista nito ang mga chat provider.
  2. Hanapin ang provider. Gamitin ang “Lokal”, “Cloud”, “Router”, o ang search box.
  3. I-expand ang card at punan ang mga halaga. Kailangan ng mga lokal na server ng address at pangalan ng modelo; kailangan din ng mga cloud provider ng API key.
  4. I-save. Isinusulat sa browser ang mga kasalukuyang field.
  5. Subukan ang koneksyon. Ayusin muna ang mga error sa address, key, modelo, o server.
  6. Gawing aktibo. Lumipat lamang kapag tagumpay ang pagsubok. Ang pag-save ay hindi nangangahulugang aktibo na.

Gumana sa terminal ay hindi garantadong ma-access ng extension

Ang rejected na koneksyon ay karaniwang nangangahulugang hindi pa nakabukas ang server o mali ang port; ang mga CORS/Origin error ay nangangailangan ng pag-payo sa browser extension origin. Karaniwan sa Ollama: OLLAMA_ORIGINS="chrome-extension://*,moz-extension://*" ollama serve.

Mga prompt tier

CompactPinakamaikling prompt at pinakamaliit na tool surface, para sa maliliit na lokal na modelo na mga 8k context.
MidKasama ang mga karaniwang browser task, iframe, download, scheduled task, at form validation. Inirerekomendang simula para sa lokal.
FullNagdadagdag ng mga advanced fallback tool tulad ng hover, drag and drop, frame, at Shadow DOM.

Fixed sa Full ang mga cloud provider; default na Mid ang mga lokal na provider; hindi magagamit ng Compact provider ang Dev mode.

Kapag nabigo ang pagsubok ng koneksyon

  1. Connection refused: Buksan ang lokal na server at kumpirmahin ang port.
  2. CORS/Origin: Payagan ang WebBrain extension origin sa server.
  3. Unauthorized: Kumpirmahin na ang key at Base URL ay galing sa iisang provider.
  4. Model not found: Kopyahin ang eksaktong model ID, o gamitin ang Load models.
  5. Timeout: Itaas ang LLM request timeout sa “Mga Setting → Budget” para sa malalaking CPU lokal na modelo.
  6. Nabigo pagkatapos ng ilang yugto: Kumpirmahin ang totoong context window; ibaba ang prompt tier o palakihin ang context ng modelo.

Opsyonal na assistive model

Hawak ng aktibong provider ang pangunahing usapan, pagpaplano, at mga huling tugon. Sa ibang entry sa ilalim ng Mga modelo sa Mga Setting mapapa-configure nang hiwalay ang Bisyon model, Pagsasalita (speech-to-text) endpoint, Generative media, Decision model, at SafeSocial. Hindi apektado ang mga ito ng provider filter o paglipat.

Default na Auto ang Vision at Decision model: sa Chrome, ginagamit ang Compass VLD v6 2B kapag tapos na i-download (Compass VLD Tiny v5 kung ito lang ang na-download; kung wala ang pareho at Ternary Bonsai 2 2B Vision o D1 lang ang na-download, ang una ang nagbabasa ng screenshot at ang ikalawa ang humahawak ng desisyon; kapag aktibo ang WebBrain Cloud, ang managed decision model ng Compass ang humahawak ng desisyon), at walang ginagamit bago ang download. Ang decision model ay sumasagot lamang ng mga oo/hindi at multiple-choice na tanong tulad ng “Tapos na ba ang task na ito?”; piliin ang On upang ang OpenRouter, TypeSafe, lokal na server, D1 o ang in-browser model ang sumagot ng lahat ng desisyon, o ang Off upang huwag gumamit. Nanatili ang mga umiiral na permiso at completion check. Tingnan ang Vision, speech at decision model para sa setup at pagbabahagi ng datos.
