Independiyenteng local na daan ng compatibility

Gumamit ng account, hindi API key, ngunit huwag ipagpalang mawala ang hangganan ng tiwala.

Maaaring i-expose ng EasyCLIProxyAPI ang mga sinusuportahang account ng provider bilang isang local na OpenAI-compatible endpoint. Magagamit ito ng WebBrain, ngunit hindi nito binubuo, sine-audit, ipinamamahagi, o inuurungan ang proxy app.

Hindi binuo, hino-host, sine-audit, o ginagarantiya ng WebBrain

Pinapangasiwaan ng EasyCLIProxyAPI ang mga sign-in ng provider, mga lokal na credential, ang hiwalay na na-install na core ng CLIProxyAPI, at ang mga sarili nitong update. Suriin ang source code at kasalukuyang release, mag-download lamang mula sa upstream repository, at beripikahin ang mga release file kung nagbibigay ang upstream ng digest. Hindi masusuri ng WebBrain kung ano ang gagawin ng mga future na upstream build.

Ang paggamit ng local na proxy ay hindi nangangahulugang local din ang inference. Ang konteksto ng pahina at mga prompt ay patuloy na napapadala sa account ng provider na pinipili ng proxy. Maaaring magbago ang mga patakaran ng provider; ang isang OAuth flow na gumagana ay hindi nangangahulugang pinapayagan ito ng provider para sa lahat ng third-party client.

  • OpenAI: Magkahiwalay na produkto ang subscription ng ChatGPT at ang billing ng API. Tingnan ang pagkakaiba ng subscription at API at ang kasalukuyang Terms of Use.
  • Anthropic: pinipigilan ng mga tuntunin ng konsomer nito ang awtomatiko o di-tao na access maliban sa API key o iba pang malinaw na pinapayagang interface. Tingnan ang kasalukuyang Consumer Terms.
  • Google: ayon sa mga tuntunin ng Gemini CLI, hindi maaaring gamitin ang OAuth authentication nito sa mga third-party tool o serbisyo. Tingnan ang kasalukuyang mga tuntunin ng Gemini CLI.
  • Kimi at xAI: ang pagkakaroon ng OAuth sa upstream ay teknikong kakayahan lamang, hindi pahintulot o garantiya ng compatibility. Suriin ang mga tuntunin na naaangkop sa iyong produkto, plan, rehiyon, at account bago mag-sign in.

Inilalarawan ng gabay na ito ang isang compatibility setup, hindi payong legal. Ang mga desisyon sa account, data, at pagsunod ay nananatiling sa inyong responsibilidad.

Mga kasalukuyang iniaalok ng upstream app

Kasalukuyang naglilista ang EasyCLIProxyAPI ng limang browser-based na paraan ng pag-sign in. Galing sa upstream app ang mga pangalang ito at hindi opisyal na integration ng WebBrain; maaaring huminto ang mga ito sa paggana o mag-expose ng ibang modelo nang walang paalala.

Nanatili ang unang koneksyon sa inyong computer, hindi ang ikalawa. Iniimbak ng EasyCLIProxyAPI ang upstream OAuth material sa labas ng WebBrain; ang WebBrain ay nag-iimbak lamang ng local na proxy client key na inilagay ninyo sa Settings.

Setup

Ikonekta ang local endpoint

  1. Suriin at i-install ang upstream. I-download ang EasyCLIProxyAPI mula sa GitHub release page. Sa Version Management, i-install ang katugma na core ng CLIProxyAPI.
  2. Limitahan ang proxy sa loopback address. Panatilihing 127.0.0.1 ang listening address, isara ang LAN access, at huwag kailanman i-forward ang port 8317. Palitan ang maiikli o default na client key ng malakas na random na value; depende sa bersyon, maaaring nasa Advanced Settings o API Access ang mga kaugnay na kontrol.
  3. Pagpaganapin lamang ang account na talagang gagamitin. Buksan ang OAuth, piliin ang Codex, Claude, Antigravity, Kimi, o xAI, at tapusin ang pag-sign in sa provider page. Maghinto kaagad kung nagpapakita ang provider ng mga tuntunin o permiso na hindi ninyo tinatanggap.
  4. I-start ang core at kopyahin ang OpenAI-compatible URL. Sa Home, i-start ang runtime at kopyahin ang OpenAI endpoint. Ang karaniwang default ay http://127.0.0.1:8317/v1; gamitin ang halagang ipinapakita ng tumatakbong bersyon.
  5. Buksan ang Mga Setting → Mga modelo → LLM sa WebBrain. Piliin ang Higit pa… sa menu ng modelo sa side panel, pagkatapos ay hanapin ang Local OpenAI-compatible proxy sa listahan. I-paste ang server URL at ang proxy client key, hindi ang OAuth token ng provider.
  6. I-load at piliin ang modelo. I-click ang Load Models at pumili ng modelong iniaalay ng proxy. Awtomatikong pupunan ng WebBrain ang Context window mula sa listahan ng modelo ng proxy, sa llama.cpp server sa likod nito, o sa pangalan ng kilalang hosted model (hanggang 128k); kung walang mabatid, gagamit ng 64k. Hindi nito papalitan ang halagang manually ninyong isinulat maliban kung mas maliit na window ang iniuulat ng server, kaya manu-manong ibaba ang halaga kung ang proxy ay humaharap sa maliliit na local na modelong hindi nag-uulat ng window. I-enable ang vision lamang kung talagang tumatanggap ng mga imahe ang modelong iyon.
  7. I-save, subukan, pagkatapos i-enable. Patakbuhin ang Test Connection at kumpirmahin ang berdeng tagumpay bago itong gawing chat provider. Unang subukan ang Ask mode sa mga di-sensitibong nilalaman.
Huwag gumamit ng 0.0.0.0, LAN IP, tunnel, o pampublikong reverse proxy

Ang local na client key ay hindi ligtas na authentication system para sa pampublikong internet. Anumang proseso na nakakuha ng key ay maaaring magpadala ng mga request sa pamamagitan ng naka-sign-in na account ng provider.

Mga sinasadyang hindi ginagawa ng WebBrain

  • Hindi nito binubundle, sinisimulan, inu-update, o bineberipika ang EasyCLIProxyAPI o CLIProxyAPI.
  • Hindi nito tinatanggap o pinapangasiwaan ang mga OAuth refresh token ng upstream.
  • Hindi nito ipinangako na kasama sa consumer subscription ang API-like o awtomatikong access.
  • Hindi nito nilalagpasan ang mga quota ng provider, mga paghihigpit sa rehiyon, pagsusuri ng account, o mga tuntunin.
  • Hindi nito nagagawang private o on-device ang inference na naka-host sa malayo.
