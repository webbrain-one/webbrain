Tunay na session, kontrol sa antas ng task

Hayaan ang iyong coding agent na gumamit ng browser na naka-sign in ka na.

Iniikonekta ng WebBrain MCP ang Codex, Claude Code, Cursor, OpenClaw, OpenCode, at iba pang stdio MCP client sa iyong tunay na Chromium profile. Pagkatapos ng isang beses na setup, ilarawan mo lang ang browser task sa natural na wika. Pipiliin at tatawagin ng iyong coding agent ang naaangkop na WebBrain tool; isinasagawa ng WebBrain ang target sa loob ng browser gamit ang parehong mga mode, permiso ng pinagmulan, at nakikitang kontrol ng paghinto tulad ng sa sidebar.

Hindi mo kailangang i-type ang mga MCP function call nang manu-mano

Sabihin "gamitin ang WebBrain para buodin ang dashboard na bukas sa aking browser" o "i-update ang form na ito gamit ang Act mode ng WebBrain". Isasalin ng iyong MCP client ang hiling na ito sa isang tool call at ibabalik ang resulta sa parehong usapan. Ang mga halimbawang anyo-function sa ibaba ng gabay na ito ay pangunahin para sa debugging o mga developer ng client.

Chromium lang

Kailangan ng bridge ng offscreen document ng extension, kaya gumamit ng Chrome, Edge, Brave, Opera, o Vivaldi. Nais pa ring magamit nang mag-isa ang Firefox extension, ngunit hindi ito makakakonekta sa MCP server na ito.

Buong landas

Ano ang nagsisimula saan

Isinisimula ng iyong MCP client ang npm package bilang lokal na child process sa pamamagitan ng stdio. Ang process na ito ay nakikinig lamang sa 127.0.0.1:17374. Tinatawagan ito ng extension, pagkatapos isinasagawa ang bawat task sa pamamagitan ng agent loop ng WebBrain sa napiling tab ng browser.

Codex, Claude Code, Cursor, OpenClaw, OpenCodeMCP client · may-ari ng child process
→
@webbrain/mcp-serverstdio · 127.0.0.1:17374
→
WebBrain sa browser moMga naka-sign in na tab · permission gate

Hindi ang server ay ikalawang browser at hindi kinokopya ang mga cookie. Ito ay lokal na handoff point sa pagitan ng MCP client at ng extension. Hindi gumagalaw ang browser profile — kaya't ang naka-authenticate na session.

Hakbang 1 · isang beses lang

Irehistro ang server sa iyong MCP client

Gamitin ang isa sa mga sumusunad na client-specific na configuration, isang beses lang. Mga ito ay command ng pag-install, hindi ang paraan ng paghiling ng browser task. Pagkatapos ng pagrehistro, sisimulan ng client ang server para sa iyo at patuloy kang magchachat; huwag patakbuhin nang sabay ang manual na kopya sa parehong port.

Codex app, CLI, o IDE extension

codex mcp add webbrain -- npx -y @webbrain/mcp-server

Iniimbak ng Codex ang mga MCP server sa ~/.codex/config.toml; ibinahagi ng app, CLI, at IDE extension sa parehong Codex host ang configuration na iyon. Para sa matitagal na browser task, buksan ang file at bigyan ang tool ng mas maraming oras kaysa sa default na budget ng Codex kada tawag:

[mcp_servers.webbrain]
command = "npx"
args = ["-y", "@webbrain/mcp-server"]
tool_timeout_sec = 360

I-restart ang app o IDE extension pagkatapos baguhin ang file. Sa CLI, patakbuhin ang codex mcp list upang kumpirmahin ang entry at gamitin ang /mcp sa isang Codex session upang suriin ang nakakonektang server. Tingnan ang opisyal na Codex MCP guide para sa shared host configuration at lahat ng sinusuportahang opsyon.

Claude Code

claude mcp add --transport stdio webbrain -- npx -y @webbrain/mcp-server

Tutugma ang malinaw na transport sa kasalukuyang Claude Code MCP configuration. Pagkatapos idagdag, patakbuhin ang claude mcp list upang suriin ang kalusugan ng server.

Cursor

Magdagdag ng lokal na stdio server sa mga setting ng MCP ng Cursor, o ilagay ang nilalamang ito sa MCP JSON file na ginagamit ng Cursor. Sinusundan ng format ang Cursor local MCP server format:

{
  "mcpServers": {
    "webbrain": {
      "command": "npx",
      "args": ["-y", "@webbrain/mcp-server"]
    }
  }
}

OpenCode

Idagdag ang entry na ito sa ~/.config/opencode/opencode.json, gamitin ang local MCP server format ng OpenCode:

{
  "mcp": {
    "webbrain": {
      "type": "local",
      "command": ["npx", "-y", "@webbrain/mcp-server"]
    }
  }
}

OpenClaw

Irehistro ang WebBrain sa OpenClaw bilang outbound na MCP server. Huwag gamitin ang openclaw mcp serve para sa integrasyong ito: ginagawa ng utos na iyon ang OpenClaw mismo na server, kabaligtaran ng direksyon.

openclaw mcp add webbrain \
  --command npx \
  --arg -y \
  --arg @webbrain/mcp-server \
  --timeout 360

Susuriin ng mcp add ang stdio server bago ito i-save. Patakbuhin ang openclaw mcp status --verbose upang suriin ang naka-save na depinisyon. Kasama ng mga karaniwang coding at messaging tool profile ang mga naka-configure na MCP server; maaaring itago ang mga ito ng minimal profile, malinaw na pagtanggi ng bundle-mcp, o sandbox tool policy. Tingnan ang OpenClaw MCP guide para sa kasalukuyang registry at detalye ng policy.

Patakbuhin nang manual

Kapaki-pakinabang ang manual na paglunsad para i-diagnose ang listener, ngunit hindi kinakailangan sa normal na paggamit ng MCP:

npx -y @webbrain/mcp-server

Panatilihing bukas ang terminal na iyon. Kung isasara ito, isasara rin ang bridge listener. Mula sa source checkout, patakbuhin ang npm install, npm run build, at pagkatapos ang npm start sa loob ng mcp-server/.

Hakbang 2

Ituwid ang WebBrain sa lokal na listener

  1. Isimulan o i-restart ang iyong MCP client. Dapat na gumagana ang server ng WebBrain bago makapagkonekta ang extension.
  2. Buksan ang mga Setting ng WebBrain. Pumunta sa Mga Setting → Bridge.
  3. Itakda ang eksaktong URL. I-type ang ws://127.0.0.1:17374/extension.
  4. I-paste ang pairing key. Patakbuhin sa terminal ang npx -y @webbrain/mcp-server pairing-key (o buksan ang ~/.webbrain/bridge-key) at i-paste ang key sa field ng Pairing key. Pinagkakatiwalaan lang ng server ang browser na mapatutunayang hawak nito ang key na iyon. Kung wala ang field, i-update muna ang WebBrain.
  5. Paganahin ang cloud bridge. Dapat magbago ang status mula "Kumokonekta" tungo sa "Nakakonekta". Dahil sa kasaysayan ang pangalan: lokal ang target na ito.
  6. I-verify ang end-to-end na koneksyon. Hilingin ang MCP client na tumawag ng webbrain_connection. Pinatutunayan ng "Connected" na handa na ang client, lokal na server, WebSocket listener, at handshake ng extension.
Isang bridge target lamang sa isang pagkakataon

May hawak na iisang outbound bridge socket ang extension: WebBrain Cloud sa 17373, ang MCP server na ito sa 17374, o ang LM Studio plugin sa 17375. Ang pagbabago ng URL ay lumilipat ng target, hindi nagmo-multiplex.

Hakbang 3 · magtanong lang

Ilarawan ang browser task sa natural na wika

Sa Codex, Claude Code, Cursor, OpenClaw, o OpenCode, isulat ang hiling na parang ito ay ibibigay mo sa katrabaho. Ginagawang walang kalituhan ng pagbanggit sa WebBrain ang intensyon mo; isama ang page, inaasahang resulta, saklaw, at kung pinapayagan ang mga pagbabago.

Pagbabasa nang hindi binabago ang page

Gamitin ang WebBrain para basahin ang Stripe dashboard na bukas na sa aking browser. Ilista ang mga nabigong pagbabayad sa nakalipas na pitong araw kasama ang customer, halaga, currency, petsa, at dahilan ng kabiguan. Huwag baguhin ang kahit ano.

Pagbabalik ng predictable na JSON

Kunin ng WebBrain ang lahat ng overdue na invoice mula sa dashboard na bukas na sa aking browser. Magbalik ng JSON na may customer, halaga, currency, due date, at invoice URL. Huwag baguhin ang kahit ano.

Pakikipag-ugnayan sa page

Gamitin ang Act mode ng WebBrain para buksan ang record ng customer na nakikita na sa aking browser at i-update ang pangalan ng kompanya sa Acme Europe. Huminto bago ang kahit anong final na pagsusumite o pagkumpirma.

Pipiliin ng coding agent ang webbrain_run para sa pangkalahatang pagbabasa o pakikipag-ugnayan, at ang webbrain_extract kapag humiling ng structured na data. Ibinibigay nito ang mga argumento, binabantayan ang run, at inilalapat ang resulta ng WebBrain pabalik sa usapan. Maaaring magbasa at mag-extract ang Ask mode; hindi maaaring mag-click, mag-type, mag-navigate, o magsumite. Maaaring makipag-ugnayan ang Act mode, sa ilalim ng normal na permiso sa browser ng WebBrain.

Mga detalye sa ibaba — hindi mo kailangang i-type ang mga ito

Para sa unang prompt sa itaas, gagawa ang client ng call na katulad ng mga sumusunod. Kapaki-pakinabang ang representasyong ito kapag bumubuo o nagde-debug ng MCP client; maaaring balewalain ito ng mga karaniwang user.

webbrain_run(
  task: "read the open Stripe dashboard and list failed payments from the last 7 days with customer, amount, currency, date, and failure reason",
  mode: "ask"
)

Para sa mga task na nangangailangan ng pakikipag-ugnayan, sabihin nang malinaw na "gamitin ang Act mode ng WebBrain" at panatilihing nakikita ang browser. Ilalapat ng WebBrain ang normal nitong mga prompt ng aprubal ng kakayahan kada pinagmulan.

Anim na tool, isang hangganan ng tiwala

Mga tool na ginagamit ng iyong MCP client para sa iyo

Kadalasan, pinipili mo ang resulta, hindi ang tool. Binabasa ng iyong MCP client ang mga paglalarawang ito, pinipili ang naaangkop na tool, pinupuno ang mga input nito ayon sa hiling mo, at hinahawakan ang mga susunod na tawag. Nandito ang reference na ito para maunawaan o i-debug mo ang gawing iyon.

ToolGamitMahahalagang input
webbrain_runAnumang target sa browser, read-only o interactive.task, mode, opsyonal na tab_id, wait, timeout_seconds, at Act-only na allow_api_mutations.
webbrain_extractNag-e-extract ng predictable na JSON mula sa naka-authenticate na data ng page. Palaging Ask mode.task, output_schema, opsyonal na tab_id, wait, at timeout_seconds.
webbrain_statusNagpo-poll ng isang background run o naglilista ng lahat ng kilalang run.Opsyonal na run_id. Iwasan upang ilista ang mga run.
webbrain_respondIpinapasa ang sagot ng user pabalik sa naka-pause na run.run_id, clarify_id, answer, opsyonal na timeout_seconds.
webbrain_abortInihinto ang run na mali o hindi na kailangan.run_id. Hindi nina-cancel ang mga aksyong nagawa na.
webbrain_connectionSinusuri ang handshake ng extension at nakakakuha ng tuwirang pag-aayos kapag na-disconnect.Walang input.
Bakit walang MCP click o type tool

Nasa agent loop ng extension ang mga pagsusuri ng permiso ng WebBrain. Ang direktang pagkalantad sa mga mababang primitibo sa MCP ay lalaktaw sa hangganan na iyon. Kung kailangan mo ng deterministic na mababang antas ng browser automation (tulad ng Playwright), isaalang-alang ang ibang MCP server. Pinoprotektahan ng WebBrain ang iyong naka-sign in na session sa pamamagitan ng pagpapanatili ng mga aksyon sa loob ng permission model ng extension.

Humiling ng structured na JSON

Sa normal na paggamit, sabihin kung ano ang kukunin at pangalanan ang mga gustong field: "gamitin ang WebBrain para kunin ang lahat ng overdue na invoice mula sa bukas na dashboard at magbalik ng JSON na may customer, halaga, currency, due date, at invoice URL." Maaaring isalin ng mahusay na MCP client ang mga field na iyon sa kinakailangang schema at tatawagin ang webbrain_extract para sa iyo.

Ipinapakita ng halimbawang anyo-function sa ibaba ang katumbas na tool call para sa mga developer ng client at debugging. Ilarawan ang lohika ng pagpili sa task; ilarawan lamang ang hugis ng output sa output_schema.

webbrain_extract(
  task: "extract every overdue invoice visible in this account; preserve the displayed currency and use ISO dates where the page provides a full date",
  output_schema: {
    type: "object",
    properties: {
      invoices: {
        type: "array",
        items: {
          type: "object",
          properties: {
            customer: { type: "string" },
            amount: { type: "number" },
            currency: { type: "string" },
            due_date: { type: "string" },
            invoice_url: { type: "string" }
          },
          required: ["customer", "amount", "currency", "due_date"]
        }
      }
    },
    required: ["invoices"]
  }
)
  • Gumamit ng object root na may malinaw na mga field na properties at required.
  • Humiling ng pinakamakitid na data na kailangan mo. Hindi nagbibigay ang schema ng access sa data na hindi nakikita ng browser session.
  • Read-only ang tool, ngunit ipinapadala pa rin ang text ng page at resulta sa LLM provider na naka-configure sa WebBrain.
  • Kung masyadong malaki ang resulta para sa persistent snapshot ng run, maaaring iulat ng status na na-truncate ang naka-imbak na resulta. Litiin ang hiling at ulitin.

Unawain ang lifecycle ng run

Hinahawakan ng karamihan sa mga MCP client ang lifecycle na ito para sa iyo: hinihintay nila ang resulta, ipinapakita ang tanong ng WebBrain para sa paglilinaw kapag kailangan ng input ng tao, at nagpapatuloy sa sagot mo. Kapaki-pakinabang ang mga malinaw na tawag sa ibaba para sa mga developer ng client, pag-troubleshoot, o sinasadyang pagsisimula ng mahabang task sa background ng client.

Default na naghihintay ang mga foreground call. Para sa matitagal na trabaho, maaaring itakda ng client ang wait: false at mag-poll gamit ang webbrain_status.

runningPatuloy ang trabaho sa browser
needs_user_inputIpasa ang tanong sa user
completedHanda na ang resulta
failedTingnan ang error at ebidensya
abortedNahinto; nananatili ang mga naunang aksyon
# Reference sa antas ng tool
# Simulan nang hindi naghihintay
webbrain_run(task: "compare the invoices across all visible pages", mode: "ask", wait: false)

# I-poll ang naibalik na ID
webbrain_status(run_id: "mcp_…")

Ibinabalik ng timeout ng run ng WebBrain ang kontrol sa MCP client ngunit sinasadyang hindi inihihinto ang browser task. I-poll ang naibalik na run_id. Pinipigilan nito na pumatay nang tahimik ng timeout ang task matapos itong maaaring gumawa na ng mga makabuluhang aksyon.

Kapag nagtanong ang WebBrain

Nilalaman ng naka-pause na snapshot ng isang tanong na nababasa ng tao at ng clarify_id. Ipakita ang tanong sa user. Ipadala ang sagot nila nang salita-sa-salita; huwag maghaka.

webbrain_respond(
  run_id: "mcp_…",
  clarify_id: "clarify_…",
  answer: "Use the Acme EU account."
)

Pumili ng pinakamaliit na awtoridad

PagpiliMga pinapayagang aksyonKailan gamitin
mode: "ask"Pagbabasa, pagbubuod, paghahambing, at pag-extract. Walang pakikipag-ugnayan sa page.Kailangan mo lang ng impormasyon. Ito ang default na pagpili.
mode: "act"Pag-navigate, pag-click, pag-type, pag-download, at pakikipag-ugnayan sa form sa pamamagitan ng permission gate ng WebBrain.Nangangailangan ang resulta ng nakikitang aksyon sa browser.

Magkakahiwalay na layer ang aprubal ng MCP client at ng WebBrain. Maaaring magtanong ang client mo bago tumawag ng webbrain_run; maaaring magtanong ang WebBrain bago ang makabuluhang aksyon sa isang pinagmulan. Hindi pumapalit ang isa sa kabilang aprubal.

Mga hangganan ng seguridad na dapat mong panatilihin

  • Panatilihing lokal ang listener. Nakatali ito sa 127.0.0.1. Huwag i-forward ang port 17374, i-publish sa container bridge, o i-proxy sa network.
  • Itago nang maayos ang pairing key. Hindi sapat ang loopback bilang authentication, kaya pinagkakatiwalaan ng server ang socket lamang kapag sinagot nito ang isang bagong challenge gamit ang HMAC na naka-key sa pairing key; hindi kailanang ipinapadala ang mismong key sa socket. Sinumang makakabasa ng ~/.webbrain/bridge-key ay makapag-pair, kaya huwag i-paste ang key sa chat. Hindi beripika ng extension ang pagkakakilanlan ng server, kaya pa rin ituring ang lokal na code at MCP package na mapagkakatiwalaang software.
  • Gamitin muna ang Ask. Mas madaling beripika ang read-only na trabaho at mas maliit ang blast radius nito.
  • Panatilihing nakikita ang browser para sa Act. Maaari mong ihinto ang run sa side panel; ang hindi inaasahang navigation o pag-type ay dapat ituring na dahilan ng paghinto.
  • Tandaan ang hangganan ng provider. Nanatiling lokal ang MCP bridge, ngunit ipinapadala ang nilalaman ng page sa model provider na naka-configure sa WebBrain. Gumamit ng lokal na model kapag dapat na manatili sa device ang nilalaman.
  • Huwag ituring ang timeout bilang rollback. Inihinto ng pag-abort ang mga susunod na hakbang; hindi nito mababalik ang naipadalang email, naisumiteang form, pagbili, o ibang nakumpletong aksyon.

Para sa buong disenyo, tingnan ang security model, privacy at daloy ng data, at ang gabay sa mga mode, kaligtasan, at privacy.

Kaugnay na integrasyon

Gumamit ng LM Studio?

Ginagamit ng LM Studio ang hiwalay na WebBrain Web Tools plugin, hindi ang MCP package na ito. Maaaring basahin ng mga tool nitong fetch_url at research_url ang mga pampublikong page nang hindi nangangailangan ng browser extension; maaaring ipagkatiwala ng mga browser tool nitong ang target sa iyong naka-sign in na Chromium session sa pamamagitan ng port 17375.

LM Studio plugin guide, at pagkatapos ay lumipat ng cloud bridge URL ng extension mula MCP port 17374 tungo sa plugin port 17375 kapag kailangan mo ng integrasyong iyon.

Mga sinasadyang hindi ginagawa ng server na ito

  • Hindi ito naglulunsad ng headless browser o gumagawa ng bagong browser profile.
  • Hindi ito gumagana sa pamamagitan ng Firefox build.
  • Hindi ito nag-e-export ng mga cookie, kredensyal, o session storage.
  • Hindi nito direktang ilalantad sa MCP client ang humigit-kumulang limang pu ng click, type, frame, screenshot, network, at DOM primitives ng WebBrain.
  • Hindi nito pinagagawang ligtas na ilantad ang bridge sa remote.
  • Hindi nito aalisin ang pangangailangan ng naka-configure na model sa loob ng WebBrain.

Kung kailangan mo ng deterministic na mababang antas ng browser automation sa isang isolated na profile, baka mas angkop ang isang Playwright-style na MCP server. Gamitin ang WebBrain MCP kapag ang natitiyak na pangangailangan ay ang iyong umiiral na naka-sign in na browser session kasama ang safety model sa browser ng WebBrain.
