Lokal na modelo, live na web

Bigyan ang model ng LM Studio ng dalawang paraan upang maabot ang web.

Idinagdag ng WebBrain Web Tools ang pagbabasa ng mga pampublikong URL sa kahit anong chat ng LM Studio na sumusuporta sa mga tool. Kapag nakakabit ang WebBrain extension, maaari ring i-delegate ng parehong plugin ang isang goal sa Chromium profile na naka-sign in ka na.

Ito ay plugin, hindi ang setup ng MCP

I-install ang webbrain/web-tools mula sa LM Studio Hub. Huwag i-register ang @webbrain/mcp-server o gumamit ng MCP port na 17374 para sa landas na ito; ang delegation ng browser mula sa LM Studio plugin ay gumagamit ng port 17375.

Magsimula sa Hub

I-install at i-enable ang WebBrain Web Tools

  1. Panatilihing bukas ang LM Studio. Buksan ang listahan sa Hub ng webbrain/web-tools at piliin ang Run in LM Studio. Maaari mo ring buksan ang deep link sa ibaba sa parehong makina.
  2. I-enable ang plugin sa chat. Buksan ang kontrol ng integrations o tools tabi ng chat input at i-on ang webbrain/web-tools.
  3. Pumili ng modelong sumusuporta sa tool. Iniaalok ng plugin ang mga tool nito sa chat na iyon; ang modelo ang nagdedesisyon kung kailan ang mga ito tatawagin batay sa iyong kahilingan.
  4. Subukan muna ang landas ng pampublikong web. Itanong: "Basahin ang https://news.ycombinator.com at buod ang mga pangunahing tema sa mga kasalukuyang headline." Dapat gamitin ng modelo ang research_url.
lmstudio://plugin?owner=webbrain&name=web-tools

Pag-install ng CLI

Kinokopya ng lms clone ang artifact ng Hub sa kasalukuyang directory; hindi nito awtomatikong ini-install ang kopya na iyon. Pumasok sa na-clone na directory at patakbuhin ang install form ng lms dev:

lms clone webbrain/web-tools
cd web-tools
lms dev --install

Tingnan ang reference ng lms clone at reference ng lms dev --install ng LM Studio para sa pag-uugali ng CLI.

Anim na tool, dalawang trust surface

Mga kakayahan na binibigay ng plugin sa modelo

ToolGamitin para saKailangan ng browser extension?
fetch_urlKumukuha ng kilalang HTTP(S) URL. Hinahawakan ang JSON, HTML, plain text, request headers at bodies, at binubuod ang mga binary response sa halip na i-inline.Hindi
research_urlKinukuha ang mababasang teksto ng artikulo o dokumentasyon habang binabatid ang mga karaniwang elemento ng nabigasyon.Hindi
browser_taskIni-delegate ang natural-language na Ask o Act goal sa WebBrain sa naka-sign in na browser.Oo
browser_statusSinusuri ang koneksyon ng extension, o nagpo-poll ng umiiral na run sa pamamagitan ng runId.Oo

browser_abortHinihintang ang tumatakbong run. Hindi mababawi ang mga natapos nang aksyon.Oo
Ang mahahabang pahina ay naii-compress, hindi lang basta napuputol

Kapag lumampas ang resulta sa return budget, pinapanatili ng mga HTTP tool ang simula, mga piniling high-signal na gitnang talata, at ang dulo. Ang na-compress na resulta ay nag-uulat ng compacted: true at naglalaman ng metadata ng compression. Humiling ng mas makitid na pahina o taasan ang maxChars kapag mahalaga ang lumaktawang nilalaman.

Gumamit ng mga pampublikong HTTP tool nang walang browser

Magbasa ng kilalang artikulo

Gamitin ang research_url upang basahin ang https://example.com/article at ibigay ang pangunahing argumento ng may-akda, mga suportadong ebidensya, at mga ipinahayag na limitasyon.

Suriin ang isang API response

Gamitin ang fetch_url upang basahin ang https://api.example.com/status. Ibalik ang HTTP status at ang mga field na nagpapakita ng kalusugan ng serbisyo.

Karaniwang mas angkop ang research_url para sa prose. Gamitin ang fetch_url kapag mahalaga ang uri ng response, istruktura ng JSON, headers, method, o body.

Ang pagkuha ng URL ay hindi tab ng browser

Ang mga kahilingang ito ay anonymous at hindi pinapatakbo ang JavaScript ng pahina. Kung ang isang resulta ay nag-uulat ng spaSuspected: true, o nangangailangan ang pahina ng login, huminto sa pag-ulit ng HTTP route at gamitin ang browser_task pagkatapos ikonekta ang extension.

Opsyonal na landas na naka-sign in

Ikonekta ang browser na ginagamit mo na

  1. I-install ang WebBrain sa isang Chromium browser. Gumagana ang bridge sa Chrome, Edge, Brave, Opera, at Vivaldi. Hindi kayang tahanan ng Firefox ang koneksyong ito.
  2. I-enable ang webbrain/web-tools sa LM Studio. Binubuksan ng plugin ang lokal na loopback listener nito kapag na-initialize.
  3. Buksan ang mga Setting ng WebBrain. Pumunta sa Settings → Bridge.
  4. Itakda ang URL ng plugin at ang pairing key. Ilagay ang ws://127.0.0.1:17375/extension, i-paste ang key mula sa ~/.webbrain/bridge-key (nilikha kapag nagsimula ang plugin; pinagsasama sa MCP server) sa field ng Pairing key, pagkatapos ay i-enable ang cloud bridge.
  5. Beripikahin ang buong landas. Hilingin sa model ng LM Studio na tumawag ng browser_status. Ang resulta na connected ay patunay na handa na ang listener ng plugin at ang handshake ng extension.
Isang destinasyon ng bridge lamang sa isang pagkakataon

May isang labas na bridge socket lamang ang extension. Iniekonekta ng port 17375 ito sa plugin na ito, ng port 17374 sa MCP server, at ng port 17373 sa WebBrain Cloud. Ang pagbabago ng URL ay lumilipat ng destinasyon; hindi pinagsasama ang mga ito.

Maaaring may dalawang modelo na sangkot

Dinudugtong ng chat model ng LM Studio na tumawag ng browser_task at tinatanggap ang resulta. Isinasagawa ng WebBrain extension ang na-delegate na browser run gamit ang aktibong provider na na-configure sa loob ng WebBrain. Kung dapat manatili sa device ang nilalaman ng pahina, i-configure ang WebBrain provider na iyon upang gumamit din ng lokal na modelo.

Pagbabasa nang hindi binabago ang pahina

Gamitin ang browser_task sa Ask mode upang basahin ang account dashboard na nakabukas na sa browser ko at ilista ang limang pinakabagong alert. Huwag baguhin ang kahit ano.

Interaction sa pamamagitan ng mga permission gate

Gamitin ang browser_task sa Act mode upang buksan ang draft na nakikita na sa browser ko at i-update ang pangalan ng kompanya sa Acme Europe. Huminto bago ang kahit anong final na pagsumite o pagkumpirma.

Hayaan na magpatuloy ang tumatakbong browser run

Naghihintay ang browser_task ng resulta, ngunit hindi kinakansela ng timeout nito ang trabaho na tumatakbo na sa extension. Panatilihin ang ibinigay na runId at gamitin ang recovery tool na tumutugma sa status.

runningMag-poll gamit ang browser_status
needs_user_inputMagtanong, pagkatapos gamitin ang browser_respond
completedHanda na ang resulta
failedTingnan ang error at ebidensya
abortedHumininto; nanatiling may bisa ang mga naunang aksyon
  • Huwag magsimula ng inulit na browser_task pagkatapos ng timeout; i-poll ang umiiral na run.
  • Huwag kailanang gumawa ng sagot sa mga tanong ng WebBrain para sa linaw. Itanong sa user at ipasa ang kanilang sagot nang salita-sa-salita.
  • Hinihintang ang browser_abort ang mga susunod na hakbang. Hindi nito mababawi ang naipadala nang form, naipadala nang mensahe, o ibang natapos nang aksyon.

Panatilihing malinaw ang dalawang trust surface

  • Tumatakbo ang pampublikong HTTP sa lokal na proseso ng plugin. Maaaring magpadala ang fetch_url ng method, headers, at body, kaya humiling lamang ng mutation kapag sinasadya mo ito.
  • Default na harang ang mga pribadong network target. Tinanggihan ang loopback, RFC1918, link-local, cloud metadata, at mga karaniwang intranet hostname. Para maabot ang localhost o LAN, i-on ang Allow private network access sa mga setting ng plugin sa LM Studio, lamang sa usaping nangangailangan nito. Hindi maaaring i-on ng modelo ang setting na ito, at nananatiling harang ang mga cloud metadata endpoint kahit na naka-on.
  • Muling sinusuri ang mga redirect. Vinevalida ng plugin ang bawat destinasyon at tinatanggal ang mga credential-like na header kapag tumawid ang redirect sa ibang origin.
  • Nanatiling naka-loopback ang listener ng browser. Huwag kailanang i-forward o i-proxy ang port 17375. Kinikilala ng handshake ng extension ang client ngunit hindi ito shared-secret authentication; ituring ang lokal na software na pinagkakatiwalaan.
  • Ang Ask mode ang default. Gamitin ang Act lamang kapag nangangailangan ang hinahiling na resulta ng nakikitang interaction ng browser, at panatilihin ang browser sa paraang kayang mong ihinto ang hindi inaasahang pag-uugali.
  • Nakikita ng model ng LM Studio ang mga resulta ng tool. Nagpapadala rin ng task context ang browser run sa pamamagitan ng aktibong provider na na-configure sa loob ng WebBrain. Maingat na piliin ang hangganan ng parehong modelo.

Para sa mga detalye sa antas ng implementation (kasama kung paano inii-pin ang bawat koneksyon sa sinusuri nang address), basahin ang mga Tala ng kaligtasan ng plugin.

VariableDefaultKahulugan

Kung binago mo ang port o path para sa plugin na lokal na binubuo, i-update ang URL ng cloud bridge sa mga setting ng WebBrain upang tumugma. Panatilihin ng karamihan sa mga user ang mga default.
