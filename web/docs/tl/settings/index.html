Tigilang hulaan ang ibig sabihin ng mga setting

Alamin kung ano ang dapat baguhin — at kung ano ang hindi kailangang hawakan.

Buksan ang Mga Setting mula sa gear sa side panel o sa mga opsyon ng browser extension. Nasa iisang page ang lahat: inililista ng sidebar ang bawat seksyon, at hinahanap ng search box sa itaas nito ang lahat ng seksyon. Binubuksan ng Higit pa… sa menu ng model sa side panel ang Mga modelo → LLM, at binubuksan ng Pamahalaan ang mga pahintulot ng site sa menu na ⚠ tabi ng mikrofon ang Mga pahintulot at privacy. Karamihan sa mga tao ay General, ang seksyong LLM, at Mga pahintulot at privacy lang ang kailangan; ang ibang seksyon ay para sa mga partikular na problema.

Mga screenshot mula sa English interface ng iisang-page na Mga Setting · pareho ang posisyon ng mga kontrol sa Filipino interface · hindi naglalaman ng tunay na credentials ang mga sintetikong halimbawa

Paghahanap

Hinahanap ng search box sa itaas ng sidebar ang lahat ng seksyon nang sabay-sabay at ipinapakita ang bawat resulta sa ilalim ng pangalan ng seksyon nito. Habang may mga resulta, walang seksyong minamarkahan bilang kasalukuyan. I-click ang pangalan ng seksyon sa itaas ng mga resulta, o pumili ng seksyon sa sidebar, para buksan ito; parehong tinatapos nito ang paghahanap, gayundin ang pag-clear ng search.

Makitid na window at lumang link

Kapag mas makitid sa mga 880 pixel, nagiging strip sa itaas ng page ang sidebar na naiiskrol nang pahalang. Gumagana pa rin ang mga link sa lumang page ng Providers at Permissions, sa bookmark man o sa ibang lugar: binubuksan nila ang katugmang seksyon ng Mga Setting.

Araw-araw na paggamit

General: ang mga switch na kailangan ng karamihan

Kosmetiko o praktikal ang itsura, ang epekto habang gumagana ang agent, at ang download folder. Kasunod nito ang tatlong pinagsamang switch; bawat isa ay nagtatakda ng isang grupo ng magkakaugnay na Advanced setting sa isang hakbang. Napipili ang wika at zoom sa side panel, kaya hindi ito inulit dito.

Gaano kahigpit sinusuri ng WebBrain ang agent habang gumagana ito.

Walang posisyong nagbabago ng mga permission prompt, at umiiral pa rin ang mga pahintulot sa site.

Kalidad ng larawan

Gaano karaming detalye ng imahe ang natatanggap ng model. Nagpapadala ang Matipid ng mas maliliit na screenshot, hanggang dalawa bawat turn. Nagpapadala ang Balanse (default) ng katamtamang laki na screenshot, isa pagkatapos buksan ng agent ang page. Nagpapadala ang Matalas ng buong laki at detalyadong screenshot at kumukuha ng isa pagkatapos ng bawat aksyong nagbabago ng page, na gumagamit ng mas maraming image token.

Mga alerto sa pagkumpleto

Ano ang nangyayari kapag naghihintay ng iyong pagsusuri ang isang plan o natapos ang isang task. Ang Lahat (default) ay nagpapatugtog ng tunog, nagpapaulan ng confetti at pinakikislap ang tab. Pinakikislap lang ng Tahimik ang tab. Walang ginagawa ang Naka-off.

Custom at detalyadong pag-aayos

May link na Ayusin nang detalyado sa Advanced ang bawat switch na nagbubukas ng mga setting na kinakatawan nito. Kapag binago mo ang isa sa mga iyon doon, magpapakita ang switch ng Custom; pumili ng posisyon para i-reset ang mga ito. Kung naka-off ang action guards sa Advanced, magpapakita ang Pagbabantay sa agent ng Custom at sasabihin ito; ibabalik ito ng Masusi, Balanse at Mabilis, habang ang Walang pagbabantay ang sadyang paraan para patakbuhin ito nang naka-off. Walang bagong naiimbak: binabasa at isinusulat ng mga switch ang parehong mga setting ng Advanced, kaya patuloy na gumagana ang mga na-export na configuration at mas lumang profile.

Araw-araw na paggamit

Mga modelo → LLM: piliin ang kasalukuyang model

Inililista ng seksyong LLM, ang una sa ilalim ng Mga modelo, ang mga chat provider. Direkta itong binubuksan ng Higit pa… sa menu ng model sa side panel.

Isang provider lang ang aktibo sa isang pagkakataon. I-filter ang listahan ayon sa Lokal, Cloud o Router; maghanap ayon sa provider, model o field; pagkatapos ay buksan ang isang card para i-edit ito. Ang tamang pagkakasunod ay I-save → Subukan ang Koneksyon → Itakda Bilang Aktibo.

Para sa local server address, context window, prompt tier at troubleshooting, tingnan ang Mga Provider at Modelo.

Kung kinakailangan

Mga modelo → Bisyon, Pagsasalita, Generative, Decision at SafeSocial

Ang ibang entry sa ilalim ng Mga modelo ay mga opsyonal na helper model: Bisyon, Pagsasalita, Generative (imahe at video), Decision at SafeSocial. Hindi nagbabago ang aktibong provider sa pag-configure ng mga ito.

Ang Vision at Decision model ay parehong default na Auto. Sa Chrome na may hardware WebGPU, gagamitin ng Auto ang Compass VLD v6 2B (mga 2.4 GB, tumatakbo sa device mo) kapag na-download na, at wala bago ito (kung na-download mo na ang dating Compass VLD Tiny v5 ngunit hindi ang v6, gagamitin ng Auto ang Tiny v5); habang aktibo ang WebBrain Cloud, ang managed decision model ng Compass ang sasagot ng mga desisyon hanggang matapos ang download. Ang pindutan na Mag-download ng mga lokal na model sa install page, ang WebGPU card sa Mga modelo → LLM, ang Bisyon card at ang Modo Apocalypse ay nagda-download ng parehong model; isang download ang sapat para sa chat, screenshot at desisyon.

Bisyon

Piliin kung sino ang magbabasa ng mga screenshot. Kapag may na-save kang OpenAI-compatible endpoint, lahat ng screenshot ay papunta roon habang ang aktibong provider ay patuloy na nagpaplano at gumagawa ng tool call. Kung walang endpoint, babasahin mismo ng aktibong model ang mga screenshot kung nakakakita ito ng larawan; kung hindi, ang vision model sa browser ang magbabasa (Chrome lang). Panatilihin ang lahat ng default para ang aktibong provider ang bahala sa vision. Nasa Advanced → Visual at mga screenshot ang laki ng imahe at ang limit bawat turn, o sa switch na Kalidad ng larawan sa General; nasa Mga pahintulot at privacy ang pagbura ng sensitibong nilalaman sa screenshot.

May limang opsyon ang vision model sa browser:

  • Auto (default): gagamitin ang Compass VLD kapag na-download na (pinipili ang v6 2B; Tiny v5 kung ito lang ang na-download); gagamitin ang Ternary Bonsai 2 2B Vision kung ito lang ang na-download; naka-off hanggang sa matapos ang download.
  • Compass VLD v6 2B: mga 2.4 GB; ang parehong model ay maaari ring mag-chat at sumagot ng mga tanong tungkol sa desisyon. Kung ang na-download lang ay ang dating Compass VLD Tiny v5 (mga 2.2 GB), iyon ang gagamitin ng opsyong ito.
  • Ternary Bonsai 2 2B Vision: mga 1.45 GB; ang parehong model ay maaari ring mag-chat.
  • WebBrain VL 2 450M: mga 810 MB, para sa vision lamang. Hihingin ng unang download ang pahintulot mo at susuriin ang WebGPU.
  • Naka-off: walang ginagamit na vision model sa browser.

Ang pagbabago ng opsyon ay hindi awtomatikong nagda-download; gamitin ang pindutan na I-download sa card. Hindi naghihintay ng download ang mga task; ang mga screenshot na binabasa sa browser ay hindi lumalabas sa device mo. Walang vision model sa browser ang Firefox.

Pagsasalita

Mag-configure ng Whisper-compatible endpoint para sa mga recording. Kung iiwanang blangko, susubukan ang mga naka-configure na provider sa sunod-sunod: OpenAI, Groq, LM Studio, llama.cpp.

Generative

Kumonek sa fal.ai, OpenRouter, ComfyRouter o local na ComfyUI server para sa image at video generation tool. Walang naka-configure na serbisyo by default.

Decision

Ang decision model ay isang maliit at mabilis na model na sumasagot sa mga tanong na oo/hindi at multiple-choice ng agent, halimbawa “Tapos na ba ang task na ito?”, kaya hindi na kailangang abalahin ang chat model. Hindi ito nagpaplano, nagki-click o nagta-type. May tatlong mode na mapipili:

  • Auto (default): walang kailangang i-set. Sa Chrome, kapag na-download na ang Compass VLD (pinipili ang v6 2B; Tiny v5 kung ito lang ang na-download), ito ang tumitingin kung talagang tapos na ang mga task sa side panel at ang mga scheduled watch at task; kung D1 lang ang na-download, D1 ang tumitingin. Habang ang WebBrain Cloud (Compass) ang chat provider mo, ang decision model ng Compass ang sasagot hanggang sa ma-download ang isa sa mga ito. Sa ibang pagkakataon, walang ginagamit na decision model. Ipinapakita ng card kung alin ang ginagamit.
  • Naka-on: lahat ng desisyon ay gumagamit ng provider na iyong na-configure: OpenRouter, TypeSafe, local na System One server, D1, o ang chat model sa browser sa Chrome. Naka-on lahat ng desisyon by default. Buksan ang Piliin kung aling mga desisyon ang gagamit nito para i-disable ang indibidwal na desisyon (patunayin ang pagkumpleto, patunayin ang scheduled watch, patunayin ang pagkumpleto ng scheduled task, mabilis na klasipikasyon, mabilis na browser action (eksperimental)) at itakda ang mga threshold.
  • Naka-off: hindi kailanman gumagamit ng decision model, kasama ang sa Compass. Tinitingnan pa rin ng chat model kung tapos na ang mga task.

Agad na nagkakabisa ang paglipat ng mode; kailangang i-click ang I-save para sa mga provider field sa mode na “Naka-on”. Ang Subukan ang Koneksyon ay nagpapadala lang ng isang request na may fixed na example data. Ang I-reset ay babalik sa Auto at buburahin ang mga naka-save na decision key. Natatanggap ng mga cloud decision provider ang limitadong data ng task at page at maaaring magkaroon ng bayad; pinapatay ng mahigpit na paghawak ng lihim ang mga decision model. Ang mga configuration na may decision outsourcing na naka-on bago ilunsad ang mga mode na ito ay patuloy na gagana bilang “Naka-on” kasama ang dating mga switch.

SafeSocial

Opsyonal na on-device image classifier para sa Instagram. Naka-off hanggang sa i-on mo; iisang beses lang ida-download ang model at gagana ito sa browser.

Araw-araw na kaligtasan

Mga pahintulot at privacy: saan maaaring kumilos ang WebBrain, at ano ang lumalabas sa browser

Panatilihing naka-on ang Magtanong bago ang mahahalagang aksyon. Kapag pinili mo ang “Palaging payagan” sa side panel, ire-record ng WebBrain ang isang partikular na kakayahan para sa isang partikular na site, at ililista ito ng seksyong ito. Ang bawat permanenteng pahintulot ay tumutugma sa malinaw na kombinasyon ng “site + kakayahan”; hindi awtomatikong pinapayagan ang pag-type, pag-download, pag-upload, pagpapatakbo ng JavaScript o pag-schedule ng task kapag pinayagan ang click.

Nasa side panel din ang parehong switch: binubuksan ito ng pindutan na ⚠ tabi ng mikrofon sa input box, kasama ang link papunta sa seksyong ito. Habang naka-off ang mga prompt, kulay orange ang pindutan na may isang tuldok. Ang pag-off ng mga prompt doon ay hindi pag-apruba ng permission card na naghihintay na; ikaw pa rin ang sasagot sa card na iyon.

Pangkalahatan ang master switch

Kapag in-off ito, pinapayagan ang mga aksyong walang prompt sa bawat site hanggang i-on mo itong muli. Mas malawak ito kaysa pagbibigay ng isang kakayahan sa isang host.

Mga limitasyon

Mga Badyet: gaano kalayo ang isang task

Pinagsasama ng “Mga Badyet” ang mga limitasyon sa paggastos, paghihintay at dami ng gawain: ang mga alawans sa gastos ng cloud, gaano katagal hihintayin ng tanong ang sagot mo, ang limit ng hakbang at ang timeout ng model request. Nasa Advanced ang badyet ng imahe ng mga screenshot, katabi ng ibang mga setting ng vision.

Mga hakbang at timeout

Sa mas mataas na limit ng hakbang, mas malaki ang tsansang matapos o makabangon ang mahahabang workflow, ngunit maaari ring mas maraming token ang magamit. Nililimitahan lang ng timeout ng request ang paghihintay bago magsimulang tumugon ang model; hindi nito pinuputol ang sagot na nagsi-stream na.

Ang walang limit na hakbang ay hindi ibig sabihing mas maaasahan

Inaalis lang ng ∞ ang mekanikal na hinto; hindi nito ginagawang mas bihira ang paulit-ulit na loop ng model. Panatilihin ang may hangganang limit maliban kung babantayan mo nang buo ang mahabang task.

Kung kinakailangan

Memory: pagpasyahan kung anong impormasyon ang mananatili

  • Ang Naka-encrypt na Cloud Sync ay para sa mga miyembro ng WebBrain Compass; ang mga supported na provider key, profile at memory ay ine-encrypt gamit ang sync password bago i-upload. Hindi mababawi ng WebBrain ang password na iyon. Hindi isinisync ang chat history at OAuth sign-in.
  • Ang Profile auto-fill ay isang magagamit-muling bloke ng personal na detalye. Nakaimbak ito sa plaintext sa browser profile na ito, at ipinapadala sa aktibong model provider kapag pinagana.
  • Iniimbak ng Memory ng user ang matatagal na kagustuhan; agad na sine-save ng /memory --add. Opsyonal ang auto-learn at ang pagkatuto mula sa mga natapos na form; naka-gray ang mga ito habang naka-off ang memory ng user, at kailangan din ng pagkatuto mula sa form na naka-on ang auto-learn.
Huwag gawing password manager ang memory

Huwag mag-imbak ng mga password, API key, token, recovery code o iba pang lihim sa profile o memory ng user.

Desisyon sa tiwala

Mga Kasanayan: karagdagang tagubilin at tools

Maaaring magdagdag ang skill ng mga tagubilin sa system prompt; ang skill na may webbrain-tools manifest ay maaari ring mag-expose ng HTTP o download-job tool. Kinokopya ang na-import na teksto ng skill sa local storage ng browser at ipinapadala sa naka-configure mong LLM bilang bahagi ng system prompt.

Una sa seksyong Mga Kasanayan ang mga naka-enable na skill, sunod ang mga built-in na skill na maaari mong i-enable. Ang pag-click ng Magdagdag ng kasanayan ay nagbubukas ng form para mag-import ng skill mula sa URL o mag-paste ng teksto nito; ang I-edit sa naka-enable na skill ay maglo-load ng skill na iyon sa parehong form.

Ang pag-import ay pag-apruba

Mag-import lang ng skill na pinagkakatiwalaan mo. Maaaring ipadala ng mga idineklarang HTTPS tool nito ang mga idineklarang input sa idineklarang endpoint nang walang bagong prompt sa bawat call. Dumadaan pa rin ang mga download tool sa karaniwang permission gate ng Downloads bago mag-save ng file.

Mga integration · kung kinakailangan

CAPTCHA: mga account ng solver

May sariling card ang seksyong CAPTCHA, sa ilalim ng Mga integration, para sa CapSolver, 2Captcha, CapMonster Cloud, SolveCaptcha, Anti-Captcha, NopeCHA at NoneCap. Ang paglagay ng key ay nagmamarka nito bilang enabled; maaari mo rin itong i-uncheck at panatilihin ang key. May epekto kapag na-save; hindi awtomatikong pinapagana ng pag-test ng balance ang serbisyo.

Buksan ang Advanced settings ng bawat serbisyo para baguhin ang weight; ang default ay mula 100 hanggang 94 ayon sa pagkakasunod sa itaas. Maaaring i-enable ang maraming serbisyo nang sabay; ang mga compatible na serbisyo ay susubukan mula sa pinakamataas na weight pababa. Maaaring magdulot ng maraming charge ang fallback pagkatapos ng error o timeout.

Gumagamit ang hCaptcha ng NopeCHA o NoneCap; nangangailangan ang ibang uri ng suporta ng serbisyo at page parameters. Basahin ang buong CAPTCHA guide (English) para sa coverage table, fallback behavior, privacy at mga limitasyon sa paglalapat sa page.

Mga integration · kung kinakailangan

Bridge: hayaang kontrolin ng backend ang browser na ito

Ikinokonekta ng Bridge ang browser na ito sa isang program na nagpapatakbo rito: isang MCP client tulad ng Claude Code o Cursor, LM Studio, o WebBrain Cloud. Naka-off ito hanggang i-on mo ang Hayaang kontrolin ng backend ang browser na ito. Pinupunan ng mga preset button ang lokal na WebSocket address para sa bawat backend; lokal na ws:// address lang ang tinatanggap, at kailangan din ng MCP at LM Studio ang kanilang pairing key. Sa Chrome, hinahayaan ng Eksperimental na WebMCP ang WebBrain na tumuklas at magpatakbo ng mga tool na inilalantad ng mga sinusuportahang page. Sa Firefox, narito rin ang trusted automation card para sa lokal na companion.

Nasa gabay sa MCP at gabay sa LM Studio ang mga hakbang sa pag-setup.

Kung kinakailangan

Offline: Modo Apocalypse

Ipinapakita ng seksyong Offline kung naka-on ang Modo Apocalypse at kung ano ang na-install nito, halimbawa “Naka-on · 2 ang naka-install · 1.96 GiB · Manu-mano na pag-update”. Binubuksan ng Buksan ang Modo Apocalypse ang sarili nitong page sa bagong tab. Nasa page na iyon ang switch, ang mga lokal na model at ang mga Wikipedia archive, dahil nagsisimula ng mga download na pinamamahalaan ng page na iyon ang pag-on sa mode.

Tingnan ang Modo Apocalypse para sa kung ano ang dina-download nito at kung paano ito gumagana nang walang koneksyon.

Mga kontrol sa pagpaplano

  • Ang Subukan ang pagpaplano ang pinakamainam na pangkalahatang pagpili. Sinusubukan ng WebBrain na gumawa ng structured plan bago tumakbo ang mga tool ng Act o Dev; kung nabigo pa rin ang pagpaplano pagkatapos ulitin, nagpapakita ang WebBrain ng babala at nagpapatuloy ang turn na iyon nang walang plan, sa ilalim ng karaniwang mga safeguard. Kapag pinili ng “Auto” ang Act o Dev para sa isang message at tiyak na maikli at tuwirang task ito (halimbawa pagbubukas ng page, paghahanap, pagpuno at pagsumite ng isang form), lalaktawan ng Subukan ang pagpaplano ang buong plan at mabilis na intent check lang ang gagawin. May plan pa rin ang mga task na may maraming goal, maraming item, maraming website, scheduled execution, o mapanganib na hakbang tulad ng pagbabayad at pagbura; at kapag naka-set ang pagsusuri ng plano sa laging magtanong, may plan din sa bawat Act o Dev turn.
  • Kinakansela ng Mahigpit na pagpaplano ang task kapag hindi makagawa ng wastong plan. Gamitin ito kung mas mahalaga ang “walang plan, walang aksyon” kaysa kaginhawahan.
  • Inaalis ng Naka-off ang dagdag na full-plan call pero pinananatili ang mabilis na intent check; kung nabigo pa rin ang check na iyon pagkatapos ulitin, nagpapatuloy ang turn sa parehong paraan. Maaari itong mas mabilis at mas mura, pero nawawala ang plan review checkpoint.

Itinatakda ng Mga paghinto para sa pagsusuri ng plano kung kailan hihinto ang isang wastong plan para sa iyong pag-apruba. Sa default, humihinto lang ito kapag mas mababa ang kumpiyansa ng planner sa Suriin kapag mas mababa sa kumpiyansang ito, na 75% sa default.

Auto-screenshot

Ang Kapag nag-navigate (ang default) ay kumukuha ng isang screenshot pagkatapos buksan ng agent ang page para makita ng vision model kung saan ito napunta. Ang Kapag nagbago ang state ay kumukuha rin pagkatapos ng mga click, pag-type at ibang aksyong nagbabago ng page, na gumagamit ng mas maraming image token; ang Bawat hakbang ay kumukuha pagkatapos ng bawat tool call; ang Naka-off ay kumukuha lamang kapag hiniling.
